# Инвертированный индекс (Inverted Index)

## Что это такое

Инвертированный индекс — это структура данных, которая для каждого **термина**
(слова/токена) хранит список **документов**, в которых этот термин встречается.

Обычный (прямой) индекс выглядит как «документ → его слова», а инвертированный —
наоборот: «слово → документы». Отсюда и название «инвертированный» (обращённый).

## Как устроен

По сути это отображение (словарь):

```
термин → постинг-лист (список идентификаторов документов)
```

Пример. Три документа:

- Документ 1: «красная машина»
- Документ 2: «синяя машина»
- Документ 3: «красная ручка»

Инвертированный индекс:

| Термин  | Документы |
|---------|-----------|
| красная | 1, 3      |
| машина  | 1, 2      |
| синяя   | 2         |
| ручка   | 3         |

## Основные операции и сложность

- **Добавление документа** `addDocument(docId, text)` — O(k), где k — число терминов в тексте.
- **Поиск по термину** `search(term)` — O(1) для доступа к постинг-листу (плюс вывод результата).
- **Пересечение (AND)** `searchAll(terms)` — берём самый короткий постинг-лист и проверяем остальные.
- **Объединение (OR)** `searchAny(terms)` — объединяем постинг-листы.
- **Частота по документам** `documentFrequency(term)` — сколько документов содержат термин.

## Где применяется

- Полнотекстовый поиск (поисковые системы: Elasticsearch, Lucene, Google и др.).
- Поиск по коду и документации.
- Базы данных для поиска по содержимому.
- Рекомендательные системы и тегирование.

## Отличие от прямого индекса

Прямой индекс хранит «документ → слова», что удобно для ответа на вопрос
«какие слова есть в документе X». Инвертированный хранит «слово → документы»,
что делает быстрым ответ «в каких документах есть слово X» — именно это нужно
для поиска.
