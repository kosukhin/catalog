# Trie (префиксное дерево, бор)

## Что это такое

**Trie** (от слова *re-trie-val* — «извлечение», также «бор», «луч»,
«префиксное дерево») — это древовидная структура данных для хранения
множества строк, в которой общие префиксы слов хранятся только один раз.

Ключевое свойство: путь от корня к узлу — это префикс строки, а каждый узел
соответствует конкретному символу (или концу слова).

## Как устроен

Каждый узел хранит:

- `children` — отображение «символ → дочерний узел»;
- `isEndOfWord` — флаг, что в этом узле заканчивается какое-то слово;
- `value` — необязательное значение, привязанное к слову.

Пример для слов `cat`, `car`, `dog`, `dot`:

```
            root
           /    \
          c      d
         / \    / \
        a   a  o   o
       /     \ |   |
      t       r g   t
     (*)     (*)(*) (*)
```

`(*)` — терминальный узел (конец слова). Заметьте, что префикс `ca` общий
для `cat` и `car` и хранится один раз.

## Основные операции и сложность

| Операция | Метод | Сложность |
|----------|-------|-----------|
| Вставка слова | `insert(word)` | O(len(word)) |
| Поиск слова | `search(word)` | O(len(word)) |
| Проверка префикса | `startsWith(prefix)` | O(len(prefix)) |
| Удаление слова | `delete(word)` | O(len(word)) |
| Все слова с префиксом | `wordsWithPrefix(prefix)` | O(len(prefix) + k), k — число найденных слов |

Сложность не зависит от количества слов в дереве — только от длины строки.
Это главное преимущество перед наивным перебором списка строк.

## Где применяется

- **Автодополнение** (autocomplete) в поиске, редакторах, IDE.
- **Проверка орфографии** и подсказки исправлений.
- **IP-маршрутизация** (longest prefix match).
- **Словари** и предиктивный ввод (T9).
- **Поиск по префиксам** в базах данных и поисковых системах.
- Решение задач на префиксы (автодополнение, поиск общего префикса).

## Отличия от других структур

- **От хеш-таблицы**: trie даёт упорядоченный обход и поиск по префиксу,
  тогда как HashMap умеет только точный поиск по ключу.
- **От Radix Tree**: обычный trie тратит один узел на один символ; Radix Tree
  сжимает цепочки одиночных узлов в рёбра-подстроки (см. [`RadixTree.md`](./RadixTree.md)).
- **От массива строк**: поиск за O(len), а не O(n · len).

## Недостатки

- Может занимать много памяти для длинных слов с редкими общими префиксами.
- Для наборов строк с малым числом общих префиксов выигрыш невелик.
