# Настройка качества поисковой выдачи (Typesense)

Пример приложения: коллекция `school_events` (1000 школьных событий), backend на Node.js/Express.

## 1. Поля и схема (индексация)

В `backend/scripts/index-data.js` задаётся схема. От неё зависит, что и как searchable/sortable/facetable:

- `type: "string"` — поле индексируется и участвует в полнотекстовом поиске.
- `index: false` — поле хранится, но не ищется (например, внутренние заметки).
- `optional: true` — поле не обязательно при импорте.
- `facet: true` — можно фильтровать/агрегировать (например, `category`, `age_group`).
- `sort: true` — поле можно использовать в `sort_by` (например, `date`).
- `num_dim` для `float[]` — размерность вектора для семантического поиска.

## 2. Параметры запроса (полнотекстовый поиск)

В `backend/index.js` (`/search`):

- `q` — запрос. `*` возвращает все документы.
- `query_by` — по каким полям искать: `title,description,category,location`. Изменение списка меняет релевантность.
- `query_by_weights` — веса полей, например `title:3,description:1`. Заголовок важнее описания.
- `per_page` / `page` — пагинация.
- `sort_by` — сортировка: `date:asc`, `date:desc`, `_text_match:desc`, `_vector_distance:asc` и комбинации.
- `filter_by` — фильтры: `category:=Кино && age_group:=1-4 класс`.
- `facet_by` — фасеты для UI-фильтров.
- `num_typos` — допустимое число опечаток (0..2).
- `prefix` — поиск по префиксу (`true`/`false`).
- `drop_tokens_threshold` / `typo_tokens_threshold` — как Typesense отбрасывает/исправляет токены.
- `prioritize_exact_match` — точное совпадение выше.
- `search_cutoff` / `max_candidates` — ограничение кандидатов (скорость vs качество).

## 3. Семантический (векторный) поиск

- Поле `embedding: float[64]` в схеме.
- `vector_query: embedding:([..], k:10)` — поиск ближайших соседей.
- Качество зависит от модели эмбеддингов. Сейчас используется простой hashing bag-of-words (`backend/lib/embed.js`) — демонстрационный. Для продакшена: OpenAI/Cohere/локальные модели (sentence-transformers) и одинаковая модель для индекса и запроса.
- Гибридный поиск: можно комбинировать текстовый и векторный (Typesense поддерживает `vector_query` вместе с `q`).

## 4. Настройки коллекции

- `default_sorting_field` — сортировка по умолчанию (например, `date`).
- `token_separators`, `symbols_to_index` — как разбивается текст на токены.
- `synonyms` — синонимы (например, «кино» ↔ «фильм»).
- `stopwords` — стоп-слова.
- `curation` / `overrides` — ручное продвижение/скрытие документов для конкретных запросов.

## 5. Что можно сделать в этом приложении

1. Добавить фильтры: `filter_by=category:=Наука` в `/search`.
2. Веса полей: `query_by_weights=title:3,description:1`.
3. Синонимы для кино/выставка/театр.
4. Гибридный поиск: текст + вектор для «похожих, но по смыслу».
5. `prioritize_exact_match=true` для точных названий.
6. Увеличить `num_typos` для устойчивости к опечаткам.

## 6. Исключение полей из ответа

- `exclude_fields: "embedding"` — не возвращать векторы.
- Удаление `highlight`/`highlights` на стороне backend (как сделано в `index.js`).

## 7. Рекомендации

- Начинайте с базовых полей и `query_by`.
- Добавляйте веса и фильтры по мере понимания запросов пользователей.
- Используйте аналитику запросов (какие запросы не дают результатов) для тюнинга синонимов/стоп-слов.
- Для семантики — реальная модель эмбеддингов, а не hashing.
