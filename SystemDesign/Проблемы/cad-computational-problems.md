# САПР: вычислительно тяжёлые задачи (проблемы и их природа)

> **Область документа.** Здесь описана **только проблема**: что за САПР-система, какие в ней данные и
> масштабы, какие операции обязана выполнять система, **почему каждая из них вычислительно тяжёлая**
> (сложность, обусловленность, комбинаторика, вырожденность, чувствительность к допускам) и что видит
> пользователь, когда задача не укладывается в бюджет.
> **Решения, конкретные структуры данных, алгоритмы и «как надо сделать» здесь намеренно не
> рассматриваются** — это отдельный документ. Классы сложности и характер трудности указаны как
> **описание задачи**, а не как рецепт.

---

## 1. Контекст: что за система

Машиностроительная параметрическая САПР (MCAD) «Контур-CAD». Один пользователь — инженер-конструктор,
работает интерактивно; результат — параметрическая модель, чертежи и данные для производства.

| Параметр | Значение |
|---|---|
| Тип | параметрическая 3D-САПР: эскизы, твёрдотельные тела (B-rep), поверхности NURBS, сборки, чертежи |
| Модули | эскиз · деталь · сборка · чертёж · листовой металл · сварка · трубопроводы · CAM · FEA-подготовка · импорт/экспорт |
| Типовая деталь | 200–10 000 граней B-rep, 5–300 поверхностей, 1–500 скруглений |
| Сложная деталь | 200 000 граней, 50 000 поверхностей, листовой металл 300 гибов |
| Типовая сборка | 200–5 000 компонентов |
| Крупная сборка | 1 200 000 компонентов (инстансы крепежа), 400 ГБ в исходных файлах |
| Эскиз | 50–5 000 геометрических ограничений, до 20 000 элементов |
| Чертёж | 1–200 видов, до 50 000 линий на листе, 40 листов в комплекте |
| Облако точек (3D-скан) | 10^8…10^9 точек, 2–20 ГБ |
| Шаг расчётной сетки FEA | 10^6…10^8 степеней свободы |
| Требование интерактивности | кадр ≤ 16 мс (60 fps), реакция на действие мышью ≤ 50 мс |
| Бюджет операции «перестроить модель» | ≤ 2 с (типовая деталь), ≤ 30 с (сборка 5 000 компонентов) |
| Бюджет «открыть сборку» | ≤ 30 с до первого рабочего кадра, ≤ 3 ГБ ОЗУ на рабочем месте |
| Точность по умолчанию | линейный допуск 10^-3 мм, угловой 10^-5 рад |
| Разрядность/арифметика | двойная точность IEEE-754 (52 бита мантиссы ≈ 15–16 значащих цифр) |

### 1.1. Участники и потребители результата

- **Инженер-конструктор** — интерактивная работа: тянет размеры, строит скругления, собирает изделие.
- **Технолог** — развёртки, траектории обработки, раскрой, порядок гибки.
- **Расчётчик** — сетка, граничные условия, прогоны FEA, оптимизация.
- **Чертёжник** — виды, разрезы, ассоциативность с моделью.
- **PDM/PLM-система** — хранит версии, права, состав изделия, синхронизирует изменения.
- **Смежные САПР** — получение/передача STEP, IGES, JT, DXF, парасолида; у каждой свой допуск.

### 1.2. Из чего состоит работа системы

```
эскиз (2D + ограничения)
   └─► деталь (B-rep: грани, рёбра, вершины; поверхности NURBS)
          ├─► операции: выдавливание, вращение, булевы, скругления, оболочка
          ├─► тесселяция (триангуляция для отображения)
          └─► сборка (сопряжения, степени свободы, кинематика)
                 ├─► коллизии и зазоры
                 ├─► чертёж (проекции, разрезы, скрытые линии)
                 ├─► технологии (развёртка, CAM, раскрой, жгуты)
                 ├─► расчёты (массы, допуски, FEA, топологическая оптимизация)
                 └─► обмен (STEP/IGES/JT/STL) и «лечение» геометрии
```

Два свойства этой схемы задают почти все проблемы ниже:

1. **Результат каждого шага — вход следующего**, а ошибка/допуск накапливается по цепочке
   (эскиз → деталь → сборка → чертёж → CAM). Ошибка 10^-6 мм на первом шаге может стать несовпадением
   граней на последнем.
2. **Всё это должно работать интерактивно** — с бюджетом 16–50 мс на реакцию, при объёмах данных,
   которые в наивной постановке требуют минут и гигабайт памяти.

## 2. Что делает эти задачи вычислительно тяжёлыми (таксономия)

Ниже — классы трудностей, к которым относятся проблемы из §5. Одна и та же операция часто попадает
сразу в несколько классов.

| Класс трудности | В чём суть | Где встречается |
|---|---|---|
| **Комбинаторный взрыв** | число вариантов растёт как k^n; перебор невозможен уже при десятках элементов | раскрой (P-14), порядок гибки (P-12), допуски (P-18) |
| **Квадратичный/суперлинейный рост** | наивная стоимость O(n²) при n = 10^5…10^6 даёт 10^10…10^12 операций | коллизии (P-08), скрытые линии (P-11), булевы (P-01) |
| **Нелинейная система** | результат — решение системы нелинейных уравнений, сходимость не гарантирована | эскиз (P-05), сопряжения (P-06) |
| **Плохая обусловленность** | малое изменение входа → большое изменение результата; итерации не сходятся | пересечение поверхностей (P-02), FEA (P-19) |
| **Геометрическая вырожденность** | касание, касание по ребру, совпадающие грани, нулевая длина — ломают и точность, и топологию | булевы (P-01), скругления (P-03), тесселяция (P-04) |
| **NP-трудность** | точное решение невозможно за разумное время в общем случае | раскрой (P-14), CAM (P-13), гибка (P-12), DFM (P-16) |
| **Обратная задача / локальные минимумы** | нужно восстановить модель по данным; оптимум не единственный | облако точек (P-22), топоптимизация (P-20) |
| **Потеря идентичности** | элемент геометрии «переезжает» между версиями, ссылки рвутся | перестроение (P-07), сравнение версий (P-23) |
| **Чувствительность к допуску** | два «правильных» модуля дают разный результат при ε = 10^-3 и ε = 10^-6 | всё, особенно P-21, P-24 |
| **Итеративность вместо формулы** | ответ только приближённый, а пользователю нужен «точный чертёж» | массы (P-17), тесселяция (P-04) |

## 4. Проблемы подробно

### 4.1. Геометрия и топология

#### P-01. Булевы операции над B-rep (объединение, вычитание, пересечение)

**Постановка.** Даны два или более тел, заданных границами (грани на поверхностях NURBS/плоскостях,
рёбра на кривых, вершины). Требуется тело-результат с корректной топологией: замкнутая граница,
согласованные рёбра, отсутствие висячих и дублирующих элементов.

**Масштаб.** Типовая деталь — тысячи граней; «вычитание» инструмента из заготовки при подготовке
к обработке — 10^4–10^5 граней; в дереве построения — 20 булевых операций подряд.

**Почему тяжело.**

- Нужно найти **все** пересечения каждой грани одного тела с каждой гранью другого: в худшем случае это
  произведение числа граней, а для поверхностей NURBS каждое пересечение — итерационный процесс
  (см. P-02).
- Результат **суперлинеен по числу граней**: несколько почти совпадающих граней порождают десятки новых,
  а вырожденные случаи (касание в точке, касание по ребру, совпадающие грани, грань целиком внутри
  другой) требуют отдельных ветвей логики, и число таких комбинаций растёт быстро.
- Классификация «какая часть грани внутри, какая снаружи» требует **согласованных решений по всей
  поверхности**: локальная ошибка в одной точке ломает замкнутость всего результата.

**Где «взрывается».** Последовательные вычитания: каждая операция увеличивает число граней, и 15-я
операция работает уже с 10^5 граней. Касательные и почти касательные случаи (зазор 10^-7 мм при допуске
10^-3 мм) дают «нестабильный» результат — при повторном перестроении получается другая модель.

**Бюджет и что видит пользователь.** Ожидание ≤ 1 с на операцию в интерактиве. При отказе: «операция
не удалась» без объяснения; тело с дырой (не замкнуто → дальше не считаются масса и сетка); время
перестроения растёт нелинейно (0,3 с на 5-й операции → минуты на 20-й); в худшем случае — зависание
интерфейса без индикатора прогресса.

**Чувствительность.** К порядку операций в дереве, к точности входных данных (импортированные тела
приходят с чужими допусками), к допуску слияния вершин.

#### P-02. Пересечение поверхностей и построение линий пересечения

**Постановка.** Для пары поверхностей (NURBS-степени до 3×3, до 16 контрольных точек на патч) нужно
найти кривую пересечения и её параметризацию, пригодную для дальнейшей работы: замкнуть контур,
найти точки выхода на границы, устранить петли.

**Масштаб.** Одна булева операция — до 10^4 пар поверхностей; сложная деталь — 300 × 300 = 9·10^4 пар,
из которых реально пересекается 5–10%.

**Почему тяжело.**

- Пересечение двух NURBS-поверхностей **не имеет замкнутой формы**: это решение системы двух нелинейных
  уравнений от двух параметров, ищется итерационно, с выбором начальных приближений по всей области
  параметров.
- Задача **плохо обусловлена**: при почти касательных поверхностях якобиан близок к вырожденному,
  итерации «прыгают» между ветвями кривой или не сходятся; малая ошибка входа даёт качественно другой
  результат.
- Кривая пересечения — не одна, а набор ветвей: замкнутые петли, ветви, уходящие за границу патча,
  самопересечения; нужно найти **все** ветви, а их число заранее неизвестно (это часть ответа).
- Результат должен быть согласован между соседними патчами: конец кривой на одном патче обязан совпасть
  с началом на другом с точностью допуска.

**Где «взрывается».** Касание поверхностей по линии (скругление, коническая посадка), поверхности,
построенные по результатам импорта с шумом 10^-5 мм; «дрожащая» кривая, у которой точки гуляют в пределах
допуска и контур не замыкается.

**Бюджет и что видит пользователь.** ≤ 200 мс на пару в интерактиве. При отказе: щель между гранями,
из-за которой тело не считается замкнутым; «пила» на кромке; отказ построения с сообщением
«поверхности не пересекаются», хотя они визуально касаются.

**Чувствительность.** К допуску замыкания, к степени и параметризации поверхностей, к выбору
начального приближения, к порядку обхода патчей.

#### P-03. Скругления, фаски и эквидистантные поверхности

**Постановка.** Построить поверхность скругления заданного радиуса вдоль ребра (или набора рёбер),
обрезать прилегающие грани, обеспечить гладкость перехода и корректную топологию в местах стыка
нескольких скруглений.

**Масштаб.** Деталь — до 500 скруглений, из них 20–30% каскадные (скругление по ребру, образованному
другим скруглением); радиусы от 0,2 мм до 200 мм при габарите детали 500 мм.

**Почему тяжело.**

- Скругление — это **эквидистанта с переменной топологией**: при радиусе больше половины толщины стенки
  поверхность самопересекается, и «правильного» ответа не существует — нужно либо менять радиус, либо
  отказывать.
- **Каскадность**: каждое новое скругление меняет грани, на которых строятся следующие; ошибка
  распространяется по дереву, и порядок построения влияет на результат.
- В местах стыка трёх и более скруглений нужно строить «угловую» поверхность, форма которой не
  определена однозначно — результат зависит от эвристики.
- Требование гладкости (G1/G2) добавляет условия на производные, а они вычисляются численно и усиливают
  ошибки.

**Где «взрывается».** Скругление на скруглении на скруглении; радиус, близкий к радиусу соседнего
скругления; тонкостенная деталь, где все стенки 1 мм, а радиус задан 0,9 мм.

**Бюджет и что видит пользователь.** ≤ 2 с при перестроении. При отказе: «невозможно построить
скругление», причём сообщение не указывает, какое именно из 500 рёбер виновато; самопересекающаяся
поверхность, которая ломает булевы операции (P-01) и массы (P-17); «ползущий» дефект — в модели
появляется тонкая складка, заметная только на чертеже (P-11).

**Чувствительность.** К порядку построений, к радиусу относительно толщины, к допуску стыковки,
к тому, какое ребро считается «первым».

#### P-04. Триангуляция NURBS для отображения (тесселяция, LOD, «водонепроницаемость»)

**Постановка.** Превратить точную граничную модель в треугольную сетку с погрешностью не хуже заданной
(отклонение хорды 0,01–0,1 мм) так, чтобы сетка отображала поверхность без щелей между соседними гранями
и допускала несколько уровней детализации.

**Масштаб.** Сложная деталь — 10^7 треугольников; сборка — до 10^9; кадр рисуется за 16 мс, то есть
в бюджет одного кадра входит выбор уровня детализации и передача геометрии.

**Почему тяжело.**

- Число треугольников зависит от **кривизны и расстояния до камеры**, а не от числа граней: гладкая
  поверхность при близком просмотре требует на порядки больше треугольников, чем при дальнем; при
  движении камеры оценка меняется каждый кадр.
- Соседние грани тесселируются независимо, но их края обязаны **совпасть вершина-в-вершину**, иначе
  появляются щели. Согласование краёв двух граней с разной плотностью — отдельная задача, чувствительная
  к допуску.
- Сетка должна быть согласована с точностью: если отклонение хорды выбрано 0,1 мм, а допуск модели
  0,001 мм, то «визуально гладкая» модель не годится для расчёта, и наоборот.
- Для отображения нужны нормали и касательные: численное дифференцирование NURBS на грубой сетке даёт
  «полосы» и артефакты освещения.

**Где «взрывается».** Мелкие скругления (радиус 0,2 мм) на большой детали (500 мм): при равномерном шаге
по параметру число треугольников растёт квадратично по требуемой точности. Переход камеры через границу
уровня детализации даёт «хлопок» геометрии.

**Бюджет и что видит пользователь.** 16 мс на кадр. При отказе: «гранёные» цилиндры и «мыло» вместо
поверхностей; провалы fps при вращении сборки; светлые щели по кромкам; подгрузка частей модели
«пятнами» через несколько секунд после начала вращения.

**Чувствительность.** К выбранному допуску, к расстоянию до камеры, к соотношению «мелкий элемент на
крупной детали», к тому, кэшируется ли сетка между кадрами.

#### P-05. Решатель геометрических ограничений эскиза

**Постановка.** Дан набор геометрических элементов (точки, отрезки, дуги, сплайны) и ограничений
(совпадение, параллельность, перпендикулярность, касание, равенство, размеры, симметрия). Нужно найти
координаты, удовлетворяющие всем ограничениям, и при перетаскивании мышью обновлять их интерактивно.

**Масштаб.** 50–5 000 ограничений, до 20 000 элементов; при перетаскивании — десятки решений в секунду
(один «драг» = 60–120 пересчётов, бюджет ≤ 100 мс на кадр).

**Почему тяжело.**

- Это **система нелинейных уравнений** (трансцендентных: углы, касания, расстояния до кривых), у которой
  нет гарантии существования и единственности решения; число решений может быть конечным множеством.
- Нужно определить **степени свободы** (недоопределённость, переопределённость, противоречивость) — сама
  эта диагностика требует анализа структуры связей, а не только счёта.
- Итерационные методы сходятся **не всегда** и чувствительны к начальному приближению: эскиз «прыгает»
  в другое решение, элементы «переворачиваются», касание переходит на другую сторону.
- При перетаскивании мыши решение нужно получать **за кадр**, то есть решать почти ту же систему заново
  с малым бюджетом времени, сохраняя «непрерывность» картинки.
- Смесь крупных и мелких масштабов (деталь 1000 мм и фаска 0,5 мм) делает систему плохо обусловленной.

**Где «взрывается».** Эскиз с сеткой отверстий и размерными цепочками: 300 ограничений, из которых 12
образуют почти замкнутый контур — решение существует, но итерации «гуляют»; добавление одного размера
делает систему переопределённой, и весь эскиз перестаёт решаться, хотя «лишний» размер — на другом конце.

**Бюджет и что видит пользователь.** При отказе: эскиз «залипает» при перетаскивании (растяжение вместо
движения), элементы скачком меняют положение, «конфликт ограничений» без указания виновника,
невозможность закрыть эскиз («осталась 1 степень свободы» — и непонятно, какая).

**Чувствительность.** К начальному приближению, к порядку применения ограничений, к масштабу единиц,
к наличию почти совпадающих элементов.

#### P-06. Сопряжения сборки и кинематика механизма

**Постановка.** В сборке из тысяч компонентов заданы сопряжения (совпадение, концентричность, касание,
угол, зубчатая передача). Нужно расположить компоненты так, чтобы все сопряжения выполнялись, определить
оставшиеся степени свободы и позволить «прокрутить» механизм.

**Масштаб.** 5 000 компонентов, 5 000–20 000 сопряжений; крупная сборка — 10^6 компонентов, но с
преобладанием крепежа (инстансы, почти без сопряжений).

**Почему тяжело.**

- Та же нелинейная система, что и P-05, но **в 3D и с блочной структурой**: большинство компонентов
  связаны локально, однако есть длинные цепочки и замкнутые контуры (рамы, тяги, рычажные механизмы),
  из-за которых локальные решения не складываются в глобальное.
- **Циклы** в графе сопряжений делают задачу переопределённой по построению: часть связей избыточна,
  и нужно понять, какие именно, иначе «не сходится» вся сборка.
- Кинематика требует **многократного** решения (десятки-сотни положений), при этом промежуточные
  положения могут быть нереализуемы (мёртвые точки), а движение должно оставаться визуально плавным.
- Компонент может быть недоопределён (болтается) — это допустимо при проектировании, но ломает решатель,
  который ожидает определённости.

**Где «взрывается».** Сборка «разваливается» после изменения одной детали: 200 сопряжений помечены
конфликтующими, хотя физически конфликт в одном. Механизм из 12 звеньев при прокрутке скачком переходит
в другую ветвь решения — сборка «выворачивается наизнанку».

**Бюджет и что видит пользователь.** ≤ 30 с на полный пересчёт сборки; кинематика — плавно. При отказе:
компоненты «прыгают» при открытии; прокрутка механизма идёт рывками; «конфликт сопряжений» указывает не
на виновника; часть сборки остаётся неопределённой, и коллизии (P-08) дают ложные срабатывания.

**Чувствительность.** К порядку применения сопряжений, к начальному положению компонентов, к допускам,
к тому, какие связи объявлены «жёсткими», а какие «мягкими».

#### P-07. Перестроение параметрической модели и адресация геометрии

**Постановка.** Модель — это дерево операций (эскиз → выдавливание → булево → скругление → …) плюс
ссылки операций на конкретные элементы геометрии («скруглить *это* ребро»). При изменении параметра нужно
перестроить всё, что от него зависит, и сохранить работоспособность всех ссылок.

**Масштаб.** 2 000 операций в дереве, 10 000 ссылок на грани и рёбра; типовая правка параметра —
1–3 операции, но затрагивает десятки зависимых.

**Почему тяжело.**

- Зависимости образуют **граф**, в котором есть ветвления и циклы (взаимные ссылки эскизов, ссылки на
  геометрию «выше» и «ниже» дерева). Порядок пересчёта должен быть выбран так, чтобы каждый узел считался
  после своих зависимостей, а циклические группы требуют отдельного режима.
- Пересчёт **лавинообразен**: правка наверху дерева меняет число граней внизу, и все ссылки ниже
  становятся неоднозначными.
- **Идентичность геометрии** нестабильна: после правки нумерация граней и рёбер меняется, и «то самое»
  ребро получает другой идентификатор. Ссылка либо теряется, либо (хуже) молча указывает на другое ребро,
  и модель «тихо» становится неверной.
- Частичный пересчёт требует понять, что именно устарело, — а «устарело» зависит от результата
  предыдущих шагов, который ещё не посчитан.

**Где «взрывается».** Изменение одного размера в первом эскизе модели на 2 000 операций: перестраивать
приходится 40% дерева, время растёт с 0,4 с до 90 с. Правка, добавляющая фаску, сдвигает нумерацию
рёбер — и 30 скруглений ниже по дереву оказываются «на других рёбрах».

**Бюджет и что видит пользователь.** ≤ 2 с на правку параметра. При отказе: «ссылка потеряна» на
операции, которая не менялась; модель «перестроилась» с другими скруглениями (не ошибка, а тихое
изменение формы); полный пересчёт вместо частичного — интерфейс замирает на минуты; откатить изменение
нельзя, так как состояние ссылок уже потеряно.

**Чувствительность.** К порядку правок, к тому, какие операции «жёстко» привязаны к топологии,
к наличию циклических зависимостей, к истории правок в PDM.

### 4.2. Сборка, большие модели и интерактив

#### P-08. Обнаружение коллизий и пересечений в крупной сборке

**Постановка.** Проверить, не пересекаются ли компоненты сборки и нет ли нарушения зазоров — в статике
и при движении механизма; для движущихся частей — проверить «заметаемый объём» за время хода.

**Масштаб.** 1,2·10^6 компонентов → попарно 7·10^11 пар; каждая пара — проверка тысяч треугольников;
динамическая проверка — 100 шагов по времени, то есть умножение на 100.

**Почему тяжело.**

- **Квадратичный рост по числу компонентов**: при 10^3 компонентах — 5·10^5 пар, при 10^6 — 10^12. Разница
  между «секунды» и «невозможно» — три порядка по числу компонентов.
- Реальная геометрия — треугольные сетки по 10^3–10^5 треугольников на деталь; точная проверка пересечения
  двух таких сеток нетривиальна сама по себе (вырожденные касания, копланарные треугольники).
- «Зазор» — это не пересечение, а расстояние: нужно вычислять минимум между поверхностями, а не только
  факт контакта.
- При движении важна **непрерывность**: два компонента, не пересекающиеся в начале и в конце шага, могут
  пересечься в середине; шаг по времени влияет на то, будет ли столкновение обнаружено.
- Крепёж (десятки тысяч одинаковых болтов) даёт огромное число пар, каждая из которых «почти касается»
  по определению — любая погрешность допуска превращает их в ложные срабатывания.

**Где «взрывается».** Сборка 1,2·10^6 компонентов: полная проверка «все против всех» — часы; динамическая
проверка механизма — сутки. Ложные срабатывания на крепеже: отчёт на 40 000 «коллизий», из которых
реальных 3.

**Бюджет и что видит пользователь.** ≤ 60 с на статическую проверку сборки, «секунды» — на движущийся
узел. При отказе: проверка не запускается вовсе («слишком большая сборка»); столкновение пропущено и
обнаруживается только в железе; тысячи ложных коллизий в отчёте, который никто не читает; интерфейс
замирает на время проверки.

**Чувствительность.** К величине зазора/допуска, к шагу по времени, к плотности сетки, к тому, входят ли
в проверку крепёж и покупные изделия.

#### P-09. Открытие, навигация и память крупной сборки

**Постановка.** Пользователь открывает сборку на 1,2·10^6 компонентов и должен получить рабочий кадр за
30 с, вращать её с 60 fps и видеть актуальную структуру (состав изделия, свойства, коллизии).

**Масштаб.** 400 ГБ исходных файлов, 1,2·10^6 компонентов, до 10^9 треугольников; рабочая станция —
32 ГБ ОЗУ, видеопамять 8–16 ГБ.

**Почему тяжело.**

- **Объём не помещается в память** ни целиком, ни в виде треугольников: разница между «данные на диске»
  и «данные для кадра» — два-три порядка; держать всё в ОЗУ невозможно, а подгружать по требованию —
  значит платить задержкой на каждом движении камеры.
- **Структура изделия** (иерархия подсборок) не совпадает с пространственным расположением: то, что рядом
  в дереве, может быть далеко в пространстве, и наоборот.
- Компоненты **повторяются** (10^6 позиций — это порядка 5 000 уникальных деталей), но каждая позиция
  имеет своё положение; нужно одновременно «уникальное» представление геометрии и «множественное» —
  позиции.
- Навигация требует **отсечения невидимого**: в типичном кадре видно 1–5% компонентов, но чтобы это
  понять, нужно обработать все.
- Инженеру нужны **точные данные по требованию**: разрез, измерение, свойства, — то есть переход от
  «упрощённого представления для кадра» к «точной геометрии» в момент клика.

**Где «взрывается».** Открытие сборки: 30 с превращаются в 20 минут, если грузить все точные тела;
вращение — 4 fps, если отображать без уровней детализации; переход в режим «разрез» на всей сборке —
пересчёт миллионов треугольников и «зависание»; ООП-модель с 10^7 объектов в памяти — GC-паузы и
невозможность уложиться в лимит.

**Бюджет и что видит пользователь.** 30 с до рабочего кадра, 16 мс на кадр, ≤ 3 ГБ ОЗУ. При отказе:
«недостаточно памяти» на машине с 32 ГБ; сборка открывается минутами; при вращении видны только контуры,
а геометрия «дорисовывается» рывками; разрез или измерение блокируют интерфейс на десятки секунд.

**Чувствительность.** К числу уровней детализации, к политике кэширования на диск, к тому, какие
компоненты считаются «упрощаемыми», к скорости диска и сети (файлы часто лежат в PDM).

#### P-10. Выбор под курсором (picking), привязки и измерение в реальном времени

**Постановка.** Пользователь наводит мышь и хочет мгновенно: подсветить грань/ребро/вершину, «зацепиться»
за характерную точку (центр, касание, пересечение), измерить расстояние, показать всплывающую подсказку.

**Масштаб.** 10^7 треугольников в кадре; движение курсора — 60–120 событий в секунду; точность — не хуже
пикселя экрана, с учётом перспективы.

**Почему тяжело.**

- Нужно попасть **точно в элемент топологии**, а не в треугольник: треугольников у одной грани тысячи,
  и «какая это грань» определяется по принадлежности, обратной задачей.
- Точность в экранных координатах **обратно пропорциональна глубине**: вдали пиксель соответствует
  сантиметрам модели, и привязка становится неоднозначной (два ребра в одном пикселе).
- Привязки конкурируют между собой: одновременно под курсором несколько «магнитов» (конец ребра, центр
  грани, пересечение осей), и выбор зависит от расстояния **в экранном пространстве**, а не в модельном.
- При измерении нужна точная геометрия, а не то представление, что нарисовано (уровень детализации может
  быть грубым) — то есть клик по «упрощённой» модели должен давать точный ответ.
- Всё это — в бюджет 16 мс на кадр, вместе с отрисовкой.

**Где «взрывается».** Мелкий крепёж в глубине сборки: привязка «цепляется» не за тот болт из 40 000
одинаковых; на границе уровня детализации точка привязки «съезжает» на 0,3 мм, и размер на чертеже
получается неверным.

**Бюджет и что видит пользователь.** ≤ 16 мс на ответ. При отказе: подсветка «мигает» между двумя
элементами; привязка «прыгает» при малейшем движении мыши; измерение показывает расстояние до другого
элемента; лаг курсора 100–200 мс при вращении.

**Чувствительность.** К глубине сцены, к соотношению «мелкий объект / крупная сцена», к уровню
детализации, к допуску привязки в пикселях.

### 4.3. Чертёж

#### P-11. Виды, разрезы и удаление невидимых линий (ассоциативный чертёж)

**Постановка.** По 3D-модели построить проекции: видимые линии, невидимые (штриховые), линии перехода,
силуэты, разрезы и сечения — так, чтобы чертёж оставался **ассоциативным**: изменилась модель — чертёж
перестроился.

**Масштаб.** Сложная деталь — 200 000 граней; лист — до 50 000 линий; комплект — 40 листов по 5–20 видов;
перестроение после правки модели должно идти в фоне, не блокируя работу.

**Почему тяжело.**

- **Удаление невидимых линий** требует сравнения каждого ребра с каждой гранью, попадающей в его проекцию:
  в худшем случае квадратично по числу элементов, а для сборок — по числу компонентов в проекции.
- Нужны **силуэтные** линии гладких поверхностей — их нет в модели как рёбер, они появляются только
  в зависимости от направления взгляда; для NURBS это поиск кривой, где нормаль перпендикулярна взгляду
  (см. P-02 по природе задачи).
- **Разрезы** добавляют ещё один слой: нужно пересечь тело плоскостью, построить контур сечения, залить
  штриховкой по правилам, и всё это согласовать с проекциями.
- **Вырожденность в проекции**: ребро, проецирующееся в точку; две грани, проецирующиеся в одну полосу;
  касание — всё это даёт линии «нулевой длины», наложения и «мусор» на чертеже.
- Ассоциативность означает, что после каждой правки модели нужно понять, **что именно** изменилось, и
  обновить только это, — иначе перестроение чертежа занимает минуты.

**Где «взрывается».** Вид на сборку из 5 000 компонентов: линии всех компонентов проецируются друг на
друга, число пар растёт квадратично. Разрез сложной литой детали: тысячи пересечений плоскостью,
штриховка на 10^4 контуров. Комплект из 40 листов перестраивается 20 минут после правки одного размера.

**Бюджет и что видит пользователь.** ≤ 5 с на вид. При отказе: «мусор» из коротких линий и «волос» на
чертеже; невидимые линии, которых не должно быть; штриховка «вылезает» за контур; чертёж перестаёт
соответствовать модели («ассоциативность потеряна»), и его правят руками.

**Чувствительность.** К направлению взгляда и допуску проекции, к тому, какие элементы считаются
«линиями перехода», к порядку построения видов и разрезов.

#### P-12. Развёртка листового металла и порядок гибов

**Постановка.** По согнутой детали из листа построить плоскую заготовку (развёртку) с учётом радиусов
гибки и вычетов, а для производства — определить **порядок гибов**, при котором деталь физически можно
согнуть на прессе без столкновения с инструментом.

**Масштаб.** До 300 гибов в детали, толщины 0,5–6 мм, радиусы 0,2–20 мм; на раскрой уходит заготовка
размером до 3000 × 1500 мм.

**Почему тяжело.**

- Развёртка требует **точной модели деформации**: нейтральный слой, коэффициент удлинения, вычеты зависят
  от материала, толщины, радиуса и направления прокатки; ошибка в 0,2 мм на гибе умножается на число
  гибов и даёт невязку заготовки в сантиметры.
- **Порядок гибов — комбинаторная задача**: из k гибов возможны k! последовательностей, и почти все они
  физически невозможны (деталь упирается в инструмент, уже согнутые полки мешают). Точная постановка
  NP-трудна, число вариантов растёт факториально: 10 гибов — 3,6·10^6, 15 гибов — 1,3·10^12.
- Каждый вариант порядка требует проверки **коллизий с инструментом** на каждом шаге (по сути P-08, но
  для движущихся полок и пуансона).
- Деталь с гибами в разных плоскостях и с «обратными» гибами (гиб в другую сторону) имеет участки, где
  развёртка самопересекается, и однозначного ответа не существует.

**Где «взрывается».** Коробка с 12 гибами и 20 отверстиями: перебор порядков невозможен, а «жадный»
порядок даёт деталь, которую нельзя согнуть на реальном прессе. Развёртка на 300 гибов — плоская деталь,
которая «не влезает» на лист, потому что углы разошлись.

**Бюджет и что видит пользователь.** ≤ 10 с на развёртку. При отказе: развёртка не сходится с готовой
деталью (заготовка короче на 3 мм — деталь не собирается); предложенный порядок гибов нереализуем,
и это выясняется в цеху; отверстия «уезжают» относительно гибов.

**Чувствительность.** К материалу и его коэффициенту удлинения, к радиусу относительно толщины,
к направлению прокатки, к набору инструмента на конкретном прессе.

#### P-13. Генерация траекторий обработки (CAM) и контроль зарезов

**Постановка.** Для заданной операции (2.5D-фрезеровка карманов и контуров, 3D-обработка поверхностей,
сверление) построить траекторию инструмента: без зарезов, без столкновений с оснасткой, с требуемой
шероховатостью, минимумом холостых ходов и приемлемым временем обработки.

**Масштаб.** Карман 500 × 400 мм с 200 островами; 3D-поверхность из 10^5 треугольников; траектория —
10^6 мм пути, до 10^6 точек; расчёт — минуты, а на сложных матрицах — часы.

**Почему тяжело.**

- Задача **NP-трудна** в точной постановке (оптимальное покрытие области с ограничениями); на практике
  ищется «достаточно хорошее» решение, и его качество зависит от эвристики, а не от мощности машины.
- Проверка на **зарез** (снятие лишнего материала) требует сопоставления объёма, снимаемого инструментом,
  с целевой геометрией на всём пути — то есть булевы операции (P-01) в объёме траектории.
- **Объём данных**: 10^6 точек траектории с векторами осей, плюс промежуточные расчёты; ОЗУ и время
  растут линейно-суперлинейно.
- **Столкновения** с оснасткой и станочными узлами — та же задача непрерывной коллизии, но для
  инструмента, оправки и шпинделя на каждом шаге.
- Шероховатость и «перебеги» связывают геометрию траектории с физикой резания: гладкая траектория может
  дать плохую поверхность, а «оптимальная» по длине — зарезы.

**Где «взрывается».** Карман с 200 островами: число «поднятий» и порядок обхода островов — комбинаторны,
расчёт растягивается на часы, а «быстрый» алгоритм оставляет недофрезерованные зоны. Матрица сложной формы:
проверка на зарез по 10^5 треугольникам на каждую из 10^6 точек.

**Бюджет и что видит пользователь.** ≤ 5 мин на операцию. При отказе: зарез на детали (брак стоимостью
в матрицу); «нережущий» инструмент, который не проходит в карман; траектория из 2 млн коротких
перемещений — станок «трясётся» и обработка идёт втрое дольше; расчёт, оставленный на ночь, не
завершился.

**Чувствительность.** К шагу траектории и допуску, к стратегии (зигзаг, спираль, адаптивная), к модели
инструмента, к тому, учитываются ли реальные узлы станка.

#### P-14. Раскрой и вложение деталей на листе (nesting)

**Постановка.** Разместить набор плоских деталей (контуры произвольной формы, с отверстиями и
технологическими перемычками) на листах стандартного размера так, чтобы уложиться в минимальное число
листов и максимально использовать материал, соблюдая зазоры, направление волокон и запретные зоны.

**Масштаб.** 1 000 деталей (от 5 до 2500 мм), 20–200 листов, до 60% деталей — с криволинейным контуром;
требуемая экономия материала — 3–5%, иначе раскрой не имеет смысла.

**Почему тяжело.**

- Это **NP-трудная упаковка** (вариант задачи об укладке с произвольными формами): точный оптимум
  недостижим уже для десятков деталей; разница в 1–2% использования материала имеет денежное значение.
- Формы нельзя описать прямоугольниками: нужна работа с **произвольными контурами**, а значит — со
  смещением контура и проверкой его пересечения (см. P-01/P-03).
- Ограничений много и они разнородны: зазор между деталями, отступ от кромки, направление прокатки,
  «не класть на дефект листа», приоритет срочных заказов, общие детали для нескольких заказов.
- Задача **зависит от партии**: при добавлении одной детали весь раскрой перекраивается, а
  «инкрементальные» решения дают перерасход.
- Для лазерной резки добавляется **порядок обхода**: чтобы лист не «повело», детали режут в определённой
  последовательности, а внутренние контуры — раньше внешних (ещё одна комбинаторная задача).

**Где «взрывается».** 1 000 деталей с криволинейными контурами: «точное» решение невозможно, а жадная
укладка даёт на 8–12% больше листов; «оптимизация за ночь» не успевает перебрать и малой части вариантов.

**Бюджет и что видит пользователь.** ≤ 10 мин на партию. При отказе: перерасход металла на 5–10%
(в масштабе цеха — тонны); деталь не влезает в лист, и это видно только в цеху; раскрой, который нельзя
резать в предложенном порядке (лист «ведёт», детали смещаются).

**Чувствительность.** К числу и форме деталей, к набору размеров листов, к зазору, к приоритетам заказов,
к времени, отведённому на расчёт.

#### P-15. Трассировка трубопроводов, кабелей и жгутов

**Постановка.** Проложить трассу (трубу, кабель, жгут) между заданными точками внутри сборки: обойти
оборудование с нужными зазорами, выдержать минимальные радиусы изгиба, по возможности идти вдоль
существующих трасс и не пересекать запрещённые зоны.

**Масштаб.** 2 000 сегментов трасс, 500 препятствий, до 10^5 треугольников препятствий; ограничения —
радиусы гиба 15–300 мм, зазоры 5–50 мм.

**Почему тяжело.**

- Это **поиск пути в трёхмерном непрерывном пространстве с зазорами**: пространство бесконечно, а
  ограничение «не ближе 20 мм к оборудованию» — это расширение препятствий (эквидистанта, P-03), которое
  само вычисляется нетривиально.
- Нужно одновременно оптимизировать **длину, число изгибов и технологичность**: короткий путь с 30
  изгибами хуже длинного с 4; каждый изгиб имеет минимальный радиус, и трасса должна быть физически
  гнущейся.
- Задача близка к задаче о **дереве Штейнера** (соединить несколько точек общей трассой), которая
  NP-трудна; «правильная» трасса часто идёт через общий канал, который ещё надо найти.
- Препятствия **меняются** по ходу проектирования: трассу проложили, рядом поставили новый узел — трасса
  стала недействительной.
- Проверка «свободен ли отрезок» — это пересечение с геометрией из 10^5 треугольников, повторяемое
  миллионы раз при поиске.

**Где «взрывается».** Жгут на 40 проводов в тесном отсеке: поиск пути «сквозь» оборудование; трасса,
проходящая через зону, где потом появился новый компонент; расчёт, который не находит решения и просто
отказывает.

**Бюджет и что видит пользователь.** ≤ 60 с на трассу. При отказе: трасса «протыкает» оборудование;
невозможно выдержать радиус гиба (трасса изламывается); ручная прокладка «на глаз», которая не сходится
в производстве; отсутствие сообщения, почему решения нет.

**Чувствительность.** К величине зазора, к минимальному радиусу, к плотности препятствий, к тому,
разрешено ли идти вдоль существующих каналов.

#### P-16. Технологичность конструкции и распознавание конструктивных элементов

**Постановка.** Автоматически проверять модель на технологичность (минимальная толщина стенки, глубина
кармана относительно диаметра фрезы, доступность инструмента, минимальный радиус, «глухие» зоны) и
распознавать в геометрии конструктивные элементы: карман, бобышка, отверстие, паз, фаска, ребро.

**Масштаб.** Деталь — 200 000 граней; проверка — десятки правил; распознавание — по всем граням и их
комбинациям.

**Почему тяжело.**

- **Распознавание элементов по граничному представлению неоднозначно**: один и тот же набор граней можно
  интерпретировать как карман, как паз и как их комбинацию; «правильная» интерпретация зависит от
  контекста и технологии. В общем виде задача не имеет единственного решения, а её точные постановки
  NP-трудны.
- Правила технологичности опираются на **комбинации** граней (стенка + дно + радиусы), а не на отдельные
  грани: число комбинаций растёт быстро, и проверка «все карманы» превращается в перебор.
- Доступность инструмента — это фактически задача трассировки (P-15) для каждого кармана.
- Модель может быть «грязной» (после импорта, P-21): грани разбиты произвольно, и элемент «разорван»
  на части, которых в замысле конструктора не было.
- Результат нужен в виде **понятного замечания** с указанием места, а не флага «есть проблемы».

**Где «взрывается».** Литой корпус из 150 000 граней: распознавание карманов даёт 400 срабатываний,
из которых 300 — артефакты разбиения; проверка доступности инструмента для каждого кармана — это сотни
запусков поиска пути.

**Бюджет и что видит пользователь.** ≤ 30 с. При отказе: ложные замечания, из-за которых технологи
перестают пользоваться проверкой; пропущенный «недоступный» карман, который выясняется при наладке;
замечание без указания места, которое невозможно найти в модели.

**Чувствительность.** К разбиению геометрии на грани, к набору правил и порогов, к наличию
импортированной геометрии, к выбранной технологии (фрезеровка / литьё / аддитив).

### 4.5. Расчёты: массы, допуски, сетка, оптимизация

#### P-17. Массово-инерционные характеристики (объём, масса, центр масс, моменты инерции)

**Постановка.** Вычислить объём, массу с учётом плотностей материалов, центр масс, моменты инерции — для
детали и для сборки, с учётом полостей и разнородных материалов.

**Масштаб.** Деталь — 10^5 граней, до 300 поверхностей NURBS; сборка — 5 000 компонентов; результат нужен
за секунду, потому что конструктор смотрит на массу при каждой правке.

**Почему тяжело.**

- Аналитической формулы для произвольного B-rep **нет**: объём и моменты — интегралы по объёму, которые
  сводятся к поверхностным интегралам и считаются численно (квадратуры по поверхностям NURBS); результат
  приближённый, и его точность надо контролировать.
- Точность зависит от **разбиения**: мелкие особенности (фаска 0,2 мм на детали 500 мм) требуют плотных
  квадратур локально; равномерное разбиение даёт либо недопустимую ошибку, либо неприемлемую стоимость.
- Деталь может оказаться **незамкнутой** после неудачной операции (P-01) — тогда интеграл вообще не имеет
  смысла, но это не всегда очевидно.
- Для сборки добавляется **иерархия**: момент инерции зависит от положения компонента (теорема
  Гюйгенса–Штейнера), а положения меняются при каждой правке сопряжений (P-06).
- Отдельная проблема — **расхождение с реальностью**: чертёж, 3D-модель и взвешенная деталь дают три
  разных числа из-за допусков и материала (плотность гуляет на 2–3%).

**Где «взрывается».** Тонкостенный корпус с 200 рёбрами жёсткости и скруглениями: чтобы получить массу
с точностью 0,1%, квадратуры должны быть плотными по всем 300 поверхностям — время растёт в десятки раз.

**Бюджет и что видит пользователь.** ≤ 1 с. При отказе: масса «прыгает» на 2% при правке, не связанной
с массой; центр масс смещается на сантиметры при изменении допуска; расчёт по сборке из 5 000 компонентов
идёт минутами и только «по кнопке», а не онлайн; масса в модели не совпадает с массой в чертеже.

**Чувствительность.** К порядку квадратуры, к допуску на замкнутость, к плотности материала, к тому,
считается ли сборка по точным или упрощённым телам.

#### P-18. Анализ допусков и размерных цепочек

**Постановка.** По размерной цепочке (набору звеньев с допусками) определить, будет ли собираться узел:
какова вероятность и худший случай зазора/натяга, какое звено вносит основной вклад, и что будет, если
производство даст размеры «на границах» полей допусков.

**Масштаб.** 12–30 звеньев в цепочке; 10^4 деталей в изделии; при переборе сочетаний «худший случай» —
2^k вариантов (k = 12 → 4 096, k = 30 → 10^9); статистически — 10^6 прогонов Монте-Карло.

**Почему тяжело.**

- **Комбинаторный взрыв**: полный перебор сочетаний предельных отклонений растёт экспоненциально; при
  k = 30 перебор невозможен, а упрощённые формулы (сумма допусков) дают завышенный или заниженный
  результат в зависимости от корреляций.
- Цепочки **нелинейны**: угловые размеры, положения отверстий, непараллельность плоскостей входят
  тригонометрически, и вклад звена зависит от знака и величины соседних.
- Реальные распределения **не нормальны и не независимы**: обработка на одном станке даёт коррелированные
  отклонения, а смещение настройки сдвигает всё распределение.
- Нужен ответ не «да/нет», а **вклад звеньев** (какое звено ужесточать) — то есть анализ
  чувствительности, дополнительный слой вычислений поверх основного.
- Результат должен учитывать **реальную геометрию**, а не только размеры: контакт по поверхности, а не
  по линии, — это уже задача о зазорах между телами (P-08).

**Где «взрывается».** Цепочка из 30 звеньев по 3 варианта: 10^14 сочетаний — «худший случай» не считается
вообще; Монте-Карло на 10^6 прогонов с пересчётом геометрии на каждом — часы.

**Бюджет и что видит пользователь.** ≤ 10 с. При отказе: узел «не собирается» на производстве при
формально допустимых размерах; расчёт даёт «зазор 0,05 ± 0,2 мм», что не позволяет принять решение;
вклад звеньев не показан, и ужесточают допуск не на том звене (удорожание без эффекта).

**Чувствительность.** К выбранным законам распределений, к корреляциям, к тому, учтены ли угловые
размеры, к точности модели геометрии.

#### P-19. Построение расчётной сетки и решение задачи FEA

**Постановка.** По точной геометрии построить объёмную (тетраэдральную) сетку с заданным качеством
элементов и решить систему уравнений механики; в САПР это нужно «из коробки» на этапе проектирования,
а не в отдельном пакете.

**Масштаб.** 10^6…10^8 степеней свободы; тонкостенные детали с толщиной 1 мм при габарите 500 мм дают
соотношение размеров 500:1; число элементов — 10^6…10^7.

**Почему тяжело.**

- **Геометрия с особенностями**: скругления, фаски, тонкие стенки, острые кромки требуют мелких элементов
  локально; равномерная сетка на такой детали даёт десятки миллионов элементов там, где нужно 200 тысяч.
- **Качество элементов**: тонкие («слюдяные») тетраэдры портят решение; их появление — следствие
  геометрических особенностей и неизбежно при генерации. Оценка качества и «выращивание» элементов —
  итеративный процесс без гарантии успеха.
- **Обусловленность**: число обусловленности системы растёт при измельчении сетки, а тонкие элементы
  ухудшают его ещё сильнее; решение становится чувствительным к округлениям.
- **Размер системы**: 10^7 неизвестных — это десятки гигабайт только под матрицу в плотном виде; время
  решения и память растут нелинейно.
- Модель должна быть **согласована с точной геометрией**: узлы сетки лежат на гранях в пределах допуска,
  иначе граничные условия «съезжают» с реальных поверхностей (см. P-24).

**Где «взрывается».** Корпусная деталь 500 × 300 × 200 мм со стенкой 1,5 мм: чтобы получить 3 элемента по
толщине, нужно 10^7 элементов; сетка строится 40 минут, решение — часы, часть прогонов падает по памяти.

**Бюджет и что видит пользователь.** Часы (в САПР — «оставить на ночь»). При отказе: генерация сетки
не завершается («не удалось построить сетку» на 200 000 гранях); результат не сходится при измельчении
(напряжения «пляшут»); расчёт падает по памяти; инженер упрощает геометрию вручную, теряя точность.

**Чувствительность.** К размеру элемента, к допуску привязки к геометрии, к качеству входной геометрии,
к типу элементов и постановке граничных условий.

#### P-20. Топологическая оптимизация

**Постановка.** Найти распределение материала в заданном объёме, максимизирующее жёсткость при
ограничении по массе (или минимизирующее массу при ограничении по напряжениям), с учётом технологии
изготовления.

**Масштаб.** Расчётная область — 10^5…10^6 элементов; итераций оптимизации — 100…1 000; каждая итерация —
полное решение задачи FEA (P-19).

**Почему тяжело.**

- **Объём счёта**: 500 итераций × решение системы на 10^6 неизвестных — это часы-сутки даже при хорошей
  реализации; задача тривиально упирается в вычислительные ресурсы, а не в «умность» метода.
- Это **обратная задача**: решение не единственно, результат зависит от начального приближения и от
  штрафных параметров; «оптимальная» форма может быть нереализуемой (решетчатая, с внутренними полостями).
- Промежуточные «серые» плотности (между материалом и пустотой) требуют регуляризации, иначе форма
  «рябая» и не технологична.
- Нужны **ограничения производства**: минимальный размер элемента, направление вытяжки, аддитивность /
  литьё, — каждое добавляет вычислений или делает задачу комбинаторной.
- Результат — сетка, а не гладкая геометрия: обратное превращение в B-rep (реконструкция поверхности)
  — самостоятельная тяжёлая задача (см. P-22).

**Где «взрывается».** Кронштейн 300 × 200 × 100 мм с сеткой 2 мм: 3·10^6 элементов, 400 итераций —
несколько суток на 64 ядрах; при сетке 1 мм задача не решается за ночь вовсе.

**Бюджет и что видит пользователь.** Сутки. При отказе: за ночь расчёт не дошёл до результата, и
непонятно, сколько ещё ждать; форма «дырявая» и не изготавливается; при повторном запуске с теми же
данными получается другая форма (расчёт не воспроизводим).

**Чувствительность.** К сетке, к объёмной доле материала, к начальному приближению, к параметрам
регуляризации, к числу потоков (см. §5.2 о детерминизме).

### 4.6. Данные, совместимость и точность

#### P-21. Импорт/экспорт и «лечение» геометрии (STEP, IGES, JT, STL, DXF)

**Постановка.** Принять модель из смежной системы (или отправить свою) так, чтобы она была пригодна для
дальнейшей работы: замкнутые тела, согласованные рёбра, без дубликатов и вырожденных элементов.

**Масштаб.** STEP-файл — до 500 000 сущностей, 2–3 ГБ; импорт сложной сборки — 10^4 компонентов;
типичная доля «битых» файлов во внешнем обмене — 10–30%.

**Почему тяжело.**

- У каждой системы **свой допуск** (10^-3, 10^-5, 10^-6 мм) и своя политика сшивания. Тело, корректное
  в источнике, при переносе получает щели и наложения, которые нужно обнаружить и устранить.
- **Ремонт топологии не имеет гарантированного решения**: нужно найти дыры, отличить «настоящую» дыру
  от допусковой, сшить рёбра, убрать дубликаты граней — при этом любое исправление может изменить форму
  и нарушить замысел.
- Форматы **теряют семантику**: в STEP нет «скругления» — есть грани; после импорта нельзя «уменьшить
  радиус», потому что элемента как сущности больше нет (это же бьёт по P-07 и P-16).
- Объём: 500 000 сущностей надо разобрать, проверить ссылочную целостность и построить свою структуру —
  время и память растут вместе с файлом, а файл приходит по сети из PDM.
- Обратная задача (экспорт) тоже не бесплатна: нужно **перевести** точную геометрию в чужую терминологию,
  не потеряв точность, и уложиться в ограничения формата.

**Где «взрывается».** Импорт сборки из другой САПР: 3 000 компонентов, из них 400 не замкнуты;
автоматическое сшивание либо не сходится, либо «сшивает» грани, которые не должны были соединяться.

**Бюджет и что видит пользователь.** ≤ 5 мин. При отказе: «не тело» вместо твёрдого тела (нельзя
посчитать массу, сетку, выполнить булевы операции); дыры, видимые только в разрезе; потерянные фаски и
отверстия; модель «потяжелела» в 10 раз из-за разбиения граней.

**Чувствительность.** К допуску импорта, к версии формата, к тому, из какой системы пришла геометрия,
к порядку ремонта.

#### P-22. Облако точек: регистрация сканов и реконструкция поверхности

**Постановка.** По данным 3D-сканирования (несколько сканов детали) получить единую модель: совместить
сканы, убрать шум и выбросы, сшить в поверхность, пригодную для сравнения с номиналом или для
проектирования «по образцу».

**Масштаб.** 10^8…10^9 точек на деталь, 10–200 отдельных сканов, шум 0,01–0,1 мм; объём — 2–20 ГБ.

**Почему тяжело.**

- **Регистрация** (совмещение сканов) — оптимизация в пространстве положений: итерационный процесс
  сходится к **локальному** минимуму, зависящему от начального совмещения; при малом перекрытии сканов
  или при симметрии детали совмещение «переворачивается».
- Каждая итерация — перебор 10^8 точек с поиском ближайших соседей; стоимость итерации велика уже сама
  по себе, а итераций нужны сотни.
- **Шум и выбросы**: 1% выбросов достаточно, чтобы средняя ошибка «уехала»; оценки, устойчивые
  к выбросам, дороже обычных.
- **Реконструкция** — обратная задача без единственного ответа: одну и ту же точку можно описать гладкой
  поверхностью, набором плоскостей или сеткой; выбор зависит от цели.
- Результат надо **сравнить с номиналом** (CAD-моделью) — это снова задача о расстоянии между
  поверхностями (P-08), но для миллионов точек и с построением карты отклонений.

**Где «взрывается».** Скан крупной детали (10^9 точек, 120 сканов): регистрация — часы; реконструкция
даёт «мыло» вместо точных граней; карта отклонений строится на упрощённой сетке и показывает не те зоны.

**Бюджет и что видит пользователь.** Минуты-часы. При отказе: склеенная модель «поплыла» (две половины
совмещены с ошибкой 1 мм); поверхность с шумом, по которой нельзя построить чертёж; сравнение с номиналом
показывает «всё в допуске», хотя отклонение реальное.

**Чувствительность.** К начальному совмещению, к степени перекрытия сканов, к порогу отсева выбросов,
к плотности точек.

что видит пользователь и к чему результат чувствителен.
