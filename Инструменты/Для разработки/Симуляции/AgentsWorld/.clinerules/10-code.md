# Конвенции кода, тестов и документации

Стиль взят из уже существующего кода репозитория `catalog` — придерживаться его,
а не приносить свой.

## Код

- ESM: `import` / `export`, файлы `.js`, никакого CommonJS (`require`).
- Отступ — 4 пробела, кавычки — одинарные, точки с запятой в конце инструкций.
- Приватные поля и методы класса — через `#` (`#root`, `#size`).
- Имена: классы — `PascalCase`, функции и переменные — `camelCase`,
  константы-настройки — `UPPER_SNAKE_CASE`.
- `Map`/`Set` предпочтительнее объектов-словарей там, где нужны частые
  вставки/удаления и произвольные ключи.
- JSDoc — по-русски, кратко: что делает класс/функция, что означает поле,
  какая сложность (`O(1)`, `O(n)`), если это важно.
- Комментарий объясняет причину решения и подводные камни, а не пересказывает код.

## Тесты

- Фреймворк — встроенный в Node: `node:test` + `node:assert/strict`
  (`import { describe, it } from 'node:test'`).
- Файл теста лежит рядом с реализацией и называется `<Имя>.test.js`.
- `describe` — имя класса/модуля, `it` — короткое описание сценария по-русски.
- В одном `it` — один сценарий; сначала пустое/крайнее состояние, затем обычные
  случаи, затем ошибочные входы.
- Проверяем поведение, а не внутреннее устройство (никаких проверок приватных полей).
- Запуск: `node --test` (или `node --test путь/к/файлу.test.js`).

### Первый шаг при появлении кода в этой папке

`AgentsWorld` — отдельная подпапка внутри репозитория, своего `package.json` в ней
нет. Прежде чем писать ESM-модули, создать локальный `package.json`:

```json
{
  "name": "agents-world",
  "version": "1.0.0",
  "type": "module",
  "main": "index.js",
  "scripts": {
    "test": "node --test"
  },
  "license": "ISC"
}
```

Без `"type": "module"` Node считает `.js` файлы CommonJS и `import` в них падает.

## Документация

- К каждой реализации — рядом `.md` с описанием идеи, схемы и сложности
  (как `Trie.md` рядом с `Trie.js`).
- Markdown — по-русски, заголовки с эмодзи допустимы, таблицы и списки
  предпочтительнее длинных абзацев.
- Ссылки на файлы — относительные, чтобы работали в редакторе и на GitHub.
- Большие темы (курс, серия уроков) ведутся в связке `README.md` (точка входа) +
  `PLAN.md` (план) + `PROGRESS.md` (где остановился).
