# `lib/world.ts` — мир

Главная абстракция: принимает статистику агентов и подключает их модули.

## Жизненный цикл

```js
import * as myAgent from '../agents/myAgent.ts';
import { World } from '../lib/index.ts';

const world = new World(new Map([[myAgent, 4]]));
await world.run();   // потоки подняты, агенты работают параллельно
await world.stop();  // агенты остановлены, потоки погашены
```

`run()` ждёт готовности всех потоков и возвращает управление: мир продолжает жить
до `stop()`, блокирующего ожидания нет.

## Что экспортирует

| Имя | Назначение |
|---|---|
| `WorldOptions` | `threadPoolSize`, `print` — всё, что не касается состава агентов |
| `World` | `actors`, `population`, `running`, `threadCount`, `run`, `stop`, `send`, `ask` |

## Что мир знает об агентах

Только две вещи на каждого: **имя типа** и **адрес модуля**. Импортов из `agents/`
в этом файле нет. Единственная зависимость ядра на «агента» — служебный реестр
(`lib/rosterAgent.ts`): его `World` поднимает сам (см. раздел ниже).

Состав мира приходит одним аргументом — `Map`, где ключ это модуль агента:

```js
new World(new Map([
    [echoAgent, 6],                                      // просто количество
    [myAgent, { count: 3, options: { speed: 'fast' } }], // количество + настройки
]));
```

Что происходит дальше:

- из каждого ключа берутся `type` и `moduleUrl`, а `options` копируются в наряд
  каждого агента (`lib/stats.ts`) — так агент получает свои настройки из состава мира;
- получается 6 + 3 задания на создание акторов с адресами модулей;
- адрес уезжает в поток, и поток сам загружает код (`lib/agentLoader.ts`).

Поэтому новый агент не требует правок в `lib`: в `Map` добавляется ещё одна пара
«модуль → количество».

## Распределение по потокам

```
workerCount = min(threadPoolSize ?? число ядер, число агентов)
поток агента = индекс агента % workerCount
```

- 4 агента и 4 потока — каждый в своём потоке;
- 6 агентов и 4 потока — 2, 2, 1, 1 (см. `docs/demo.md`);
- агентов больше, чем потоков, — нормально: нагрузка размазывается по кругу;
- потоков больше, чем агентов, — не бывает: лишние потоки не поднимаются.

Распределение по кругу, а не подряд, выбрано специально: соседние по статистике
агенты попадают в разные потоки, и мир не простаивает, пока один поток делает всё.

## Служебный агент-реестр

`World` всегда поднимает один служебный актор — `RosterAgent` (`lib/rosterAgent.ts`,
адрес `RosterAgent-1`). Он не входит в состав мира, который задаёт пользователь:
его нет ни в `actors`, ни в `population`, — это инфраструктура ядра.

- реестр распределяется по потокам как обычный актор;
- после запуска всех потоков `run()` шлёт реестру `roster-snapshot` со списком
  агентов (`[{ id, type }]`), взятым из состава мира;
- любой агент может спросить реестр по типам (`roster-query`) или подписаться на
  появление новых (`roster-subscribe`) — подробности в `docs/rosterAgent.md`;
- благодаря реестру, например, `TickAgent` не хранит адреса, а берёт их по типу.

Просить об этом мир не нужно: реестр есть в любом мире.

## Кто знает адреса

`World` — единственное место, где есть карта `id → индекс потока`. Поэтому:

- сообщение между потоками всегда идёт через мир (`deliver` → `send` → нужный поток);
- акторы не знают, где живут остальные, и не могут обратиться к ним напрямую;
- внешний код может послать сообщение в мир через `world.send(from, to, message)`;
- ответить самому миру можно сообщением на адрес `мир` (`WORLD_ID`) — такое
  сообщение не ищет актора, а попадает в мир;
- в этой же карте есть и служебный реестр (`RosterAgent-1`), поэтому
  `world.ask('RosterAgent-1', …)` работает как для любого агента.

## Как мир разговаривает с агентами

`ask(to, message, timeoutMs)` отправляет сообщение от имени мира и ждёт ответа:

```js
const reply = await world.ask('HumanAgent-1', { type: 'status-request', payload: { replyTo: 'мир' } });
// reply.payload → { id, type, details }
```

Внутри это обычные сообщения: актору уходит `deliver`, ответ приходит событием
`deliver` на адрес `мир` и попадает в ожидание `ask`. Поэтому состояния агентов
можно читать извне, не нарушая изоляцию: агент сам решает, что рассказать.

Поведение при ошибках:

- агента с таким адресом нет → промис отклоняется сразу: `нет агента с идентификатором X`;
- агент не ответил за `timeoutMs` → `агент X не ответил за N мс`;
- мир остановлен → все незавершённые ожидания отклоняются: `мир остановлен`;
- сообщение на адрес `мир` без ожидающего `ask` просто печатается в лог.

## Печать

Строки агентов выводятся через `print` (по умолчанию `console.log`) в формате:

```
[EchoAgent-3 · поток 3] эхо: EchoAgent-3: сообщение 1
```

Номер потока — настоящий `threadId` воркера, поэтому по логу видно параллельность.

## Ошибки

| Ситуация | Поведение |
|---|---|
| некорректная статистика | исключение в конструкторе |
| состав передан обычным объектом | исключение: `статистика мира задаётся как Map «модуль агента → количество»` |
| один тип указан дважды | исключение: `тип агента «X» подключён дважды` |
| модуль агента неправильной формы | исключение из `assertAgentPlugin` (см. `lib/agentPlugin.ts`) |
| повторный `run()` | исключение `мир уже запущен` |
| `stop()` без `run()` | ничего не делает |
| сообщение неизвестному адресату | строка `[мир] нет агента с идентификатором …` |
| запрос к агенту через `ask` без ответа | отклонение промиса по таймауту |

## Тест

`test/world.test.ts` — состав мира из статистики, запуск и остановка, работа
минимум в двух потоках, ограничение числа потоков числом агентов, автоматически
поднятый служебный реестр (отвечает составом по типам), ошибки конструктора
(обычный объект вместо `Map`, дубль типа, пустой мир), безопасный повторный `stop`,
лог для неизвестного адресата, `ask` к агенту и к несуществующему адресу.

## Разложение на подмодули

Класс держал 12 свойств и 14 методов. Теперь состояние — один объект `WorldStatus`,
а помощники вынесены:

| Подмодуль | Что содержит |
|---|---|
| `lib/world/routes.ts` | `assignRoutes` — раскладка агентов по потокам и карта маршрутов |
| `lib/world/waitFor.ts` | `waitFor` — ожидание готовности/остановки всех потоков |
| `lib/world/pendingReplies.ts` | `PendingReplies` — ожидающие ответов на `ask` с таймаутами |

Геттеров (`actors`, `population`, `running`, `threadCount`) больше нет: они отдаются
одним снимком `world.state()`. Сервер (`server/snapshot.ts`) и подпись в консоли
берут данные оттуда.
