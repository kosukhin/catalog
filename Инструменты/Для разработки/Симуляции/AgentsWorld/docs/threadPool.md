# `lib/threadPool.ts` — пул потоков

Поднимает настоящие потоки ОС через `worker_threads`.

## Зачем потоки, а если просто «параллельно»

JavaScript исполняет код в одном потоке: `Promise.all` и таймеры дают переключение,
но не одновременность. Настоящий параллелизм возможен только на разных потоках.
Поэтому один `Worker` — один поток ОС, а пул — их набор.

## Что экспортирует

| Имя | Назначение |
|---|---|
| `ThreadPoolOptions` | `size`, `maxWorkers`, `workerScript`, `onEvent`, `onWorkerError` |
| `ThreadPool` | `size`, `threadIndexes`, `post`, `postAll`, `terminate` |

## Как считается размер

```
size = max(1, min(size ?? availableParallelism(), maxWorkers ?? ∞))
```

- по умолчанию — по числу ядер (`os.availableParallelism()`);
- `maxWorkers` — верхняя граница; мир передаёт туда число агентов, чтобы не держать
  потоки без работы;
- ноль потоков невозможен — минимум один.

## Что пул НЕ делает

Он не решает, кто где живёт: распределение агентов по потокам — задача мира
(`lib/world.ts`). Пул только поднимает потоки, передаёт команды и отдаёт события
вместе с индексом потока, поэтому вызывающий код всегда знает, от кого пришло
событие.

## Инварианты

- `post` в несуществующий индекс — ошибка с номером индекса.
- После `terminate()` команды не принимаются.
- Сбой самого воркера (не актора) уходит в `onWorkerError`, а не роняет мир молча.

## Тест

`test/threadPool.test.ts` — расчёт размера (в том числе минимум один поток),
доставка команды в конкретный поток и событие с его индексом, отказ после остановки,
ошибка на несуществующем индексе.
