# `lib/workerEntry.ts` — точка входа воркера

Код, который исполняется внутри отдельного потока ОС. Создаёт акторов по наряду,
доставляет им сообщения и отдаёт наверх всё, что они хотят сообщить.

## Что делает поток

```
parentPort.on('message') → handle(command)
  start   → для каждого наряда: import(moduleUrl) → createAgent → start → ready
  deliver → положить сообщение в ящик нужного актора своего потока
  stop    → остановить всех акторов, ответить done
```

## Код агента грузится по адресу

В наряде приходит `moduleUrl` — строка. Поток вызывает
`loadAgentFactory(moduleUrl)` (`lib/agentLoader.ts`), получает `createAgent` и
создаёт агента. Мир при этом не знает ни одного класса агента, а поток — ни одного
конкретного типа: он умеет работать с любым модулем, где есть `createAgent`.

Практическое следствие: чтобы добавить агента, не нужно трогать `lib` — достаточно
добавить пару «модуль → количество» в `Map`, который получает `World`.

## Три правила изоляции

1. **Свой поток — напрямую.** Если адресат живёт в этом же потоке, сообщение
   кладётся в его ящик без выхода наружу.
2. **Чужой поток — через мир.** У потока нет доступа к чужим ящикам: сообщение
   уходит событием `deliver`, а адресата ищет мир. Иначе акторы получили бы общую
   память и перестали быть изолированными.
3. **Лог — наверх.** Агент пишет в `context.log`, поток отправляет событие `log`
   с `threadId`. Печать остаётся в одном месте (в мире), поэтому строки не
   перемешиваются и их можно проверять в тестах.

## Ошибки, которые видит пользователь

| Ситуация | Событие |
|---|---|
| модуль агента не загрузился | `error`: `не удалось загрузить модуль агента <url>: <причина>` |
| в модуле нет `createAgent` | `error`: `в модуле агента <url> нет экспорта createAgent` |
| `createAgent` упал (например, плохие настройки) | `error` с сообщением исключения |
| сообщение неизвестному адресату | `error`: `в потоке N нет агента …` |
| исключение в обработчике актора | `error` с id актора (цикл продолжает работу) |

Во всех случаях остальные агенты потока продолжают работать: один битый модуль не
останавливает поток.

## Тест

`test/workerEntry.test.ts` — поток поднимается напрямую, создаёт агентов по наряду,
отвечает `ready` с их id, печатает через `log` с числовым `threadId`, доставляет
сообщение извне, сообщает об ошибках (нет модуля, нет `createAgent`, нет адресата)
и корректно завершается по `stop`.
