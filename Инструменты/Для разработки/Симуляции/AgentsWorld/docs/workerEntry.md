# `lib/workerEntry.ts` — точка входа воркера

Код, который исполняется внутри отдельного потока ОС. Поднимает акторов по наряду,
доставляет им сообщения и отдаёт наверх всё, что они хотят сообщить.

## Что делает поток

```
parentPort.on('message') → handle(command)
  start   → создать акторов из реестра, вызвать start, ответить ready
  deliver → положить сообщение в ящик нужного актора своего потока
  stop    → остановить всех акторов, ответить done
```

## Три правила изоляции

1. **Свой поток — напрямую.** Если адресат живёт в этом же потоке, сообщение
   кладётся в его ящик без выхода наружу.
2. **Чужой поток — через мир.** У потока нет доступа к чужим ящикам: сообщение
   уходит событием `deliver`, а адресата ищет мир. Иначе акторы получили бы общую
   память и перестали быть изолированными.
3. **Лог — наверх.** Агент пишет в `context.log`, поток отправляет событие `log`
   с `threadId`. Печать остаётся в одном месте (в мире), поэтому строки не
   перемешиваются и их можно проверять в тестах.

## Ошибки, которые видит пользователь

| Ситуация | Событие |
|---|---|
| в наряде неизвестный тип агента | `error`: `неизвестный тип агента «…»`, актор не создаётся |
| сообщение неизвестному адресату | `error`: `в потоке N нет агента …` |
| исключение в обработчике актора | `error` с id актора (цикл продолжает работу) |

## Ограничение

Реестр в потоке — это `createDefaultRegistry()`. Свои агенты нужно добавлять там,
и тогда они станут доступны и миру, и воркерам.

## Тест

`test/workerEntry.test.ts` — поток поднимается напрямую, создаёт агентов по наряду,
отвечает `ready` с их id, печатает через `log` с числовым `threadId`, доставляет
сообщение извне, сообщает об ошибках и корректно завершается по `stop`.
