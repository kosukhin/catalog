# `server/snapshot.ts` — снимок мира для дашборда

Собирает состояние мира «снаружи»: сколько агентов, какие типы, кто в каком
состоянии и который час по виртуальным часам мира.

## Зачем нужен опрос

Состояния агентов живут внутри потоков. Из главного потока их не видно и не
скопировать — у потоков нет общей памяти. Единственный способ узнать состояние —
**спросить сообщением**:

```
takeSnapshot → каждому актору status-request  (replyTo = 'мир')
актор (AbstractActor) → status-report { id, type, details }
мир (World.ask) → ответ возвращается вызывающему
```

Отсюда два важных свойства:

- снимок всегда **актуален** (это не кэш, а живой опрос);
- агент, который не ответил за таймаут, попадает в снимок как `alive: false`, а
  не ломает дашборд целиком.

## Что экспортирует

| Имя | Назначение |
|---|---|
| `WorldQuery` | минимум от мира: `running`, `threadCount`, `actors`, `ask` |
| `AgentSnapshot` | `{ id, type, alive, details }` |
| `WorldSnapshot` | `{ running, threadCount, total, byType, clock, agents }` |
| `takeSnapshot(world, clockId, timeoutMs)` | собирает снимок |

`WorldQuery` — узкий интерфейс, а не сам `World`: снимок можно тестировать на
заглушке, без потоков и агентов.

## Виртуальное время

Отдельным запросом `time-request` у агента `clockId` берётся `TimeReport` — с
уже ускоренным временем (`DayAgent` по умолчанию идёт в 10× быстрее реального).
Если часы не ответили, `clock` равен `null`, остальной снимок остаётся рабочим.

## Стоимость

На каждый HTTP-запрос выполняется `N + 1` сообщений (N агентов и часы).
Для сотен агентов это заметно, поэтому опрос идёт параллельно (`Promise.all`), а
таймаут по умолчанию — 500 мс. Если понадобится, снимок легко закэшировать в
`server/app.ts`, не меняя этот модуль.

## Тест

`test/server-snapshot.test.ts` — подсчёт агентов и типов, перенос подробностей,
`alive: false` для молчащего агента, часы мира и их отсутствие, работа с коротким
таймаутом.
