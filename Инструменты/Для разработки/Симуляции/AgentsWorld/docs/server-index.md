# `server/index.ts` — запуск приложения

Точка входа: поднимает мир, потом сервер, и отдаёт объект с `stop()`.

## Запуск

```bash
npm start                 # порт 3000, 12 человек
PORT=8080 HUMANS=50 npm start
```

Если файл запущен напрямую (`node server/index.ts`), приложение стартует само и
печатает адрес дашборда. При импорте из теста ничего не запускается — это
проверяется сравнением `process.argv[1]` с `import.meta.url`.

## Что экспортирует

| Имя | Назначение |
|---|---|
| `startServer(config?)` | `{ world, config, url, stop() }` после того, как порт открыт |
| `RunningServer` | тип результата |

## Почему сначала мир, потом порт

Если открыть порт раньше, первые запросы дашборда увидят пустой мир и покажут «0
агентов». Поэтому `startServer` сначала ждёт `world.run()`, затем `listening`.

`stop()` закрывает HTTP-сервер и останавливает мир (агенты завершают работу,
потоки гасятся) — в этом порядке, чтобы в момент остановки ещё можно было ответить
на запросы.

## Порт 0

`PORT=0` — любой свободный порт. `startServer` возвращает фактический адрес в
`url`, поэтому тесты не конфликтуют друг с другом и с запущенным приложением.

## Тест

`test/server-index.test.ts` — полный цикл: мир запущен, `/api/world` отдаёт состав
и потоки, `/api/agents` отдаёт живого человека с состоянием, `DayAgent` сообщает
`timeScale: 800`, дашборд раздаётся, виртуальное время идёт вперёд, `stop()`
останавливает мир.
