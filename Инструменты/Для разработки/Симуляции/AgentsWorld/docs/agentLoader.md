# `lib/agentLoader.ts` — загрузка кода агента по адресу

Работает внутри потока: получает строку `moduleUrl`, делает `import(moduleUrl)` и
возвращает `createAgent`.

## Зачем загрузка, а не готовая фабрика

Функцию нельзя передать в другой поток (передаются только данные). Поэтому поток
получает адрес модуля — а код грузит сам. Это и есть причина, по которой в проекте
нет реестра: миру не нужна таблица «тип → класс», ему достаточно «вот адрес, сходи
и загрузи».

## Что экспортирует

| Имя | Назначение |
|---|---|
| `loadAgentFactory(moduleUrl)` | `Promise<ActorFactory>`; грузит модуль и берёт `createAgent` |

## Как работает

```
loadAgentFactory(url)
  ├─ есть в кэше → вернуть сохранённый промис
  └─ нет → import(url)
            ├─ упало → «не удалось загрузить модуль агента <url>: <причина>»
            └─ ок, но нет createAgent → «в модуле агента <url> нет экспорта createAgent»
```

## Инварианты

- **Кэш на поток.** Модуль грузится один раз; повторные вызовы с тем же адресом
  возвращают тот же промис. Агентов одного типа может быть много, модуль — один.
- **Ошибка загрузки не кэшируется**, чтобы повторная попытка могла сработать
  (например, файл появился позже).
- **Ошибка содержит адрес модуля.** Без него в логе из потока невозможно понять,
  что именно не загрузилось.
- Загрузчик не знает, какого типа агент: он работает с любым модулем, где есть
  `createAgent`.

## Тест

`test/agentLoader.test.ts` — загрузка настоящего модуля агента, кэш (тот же промис),
ошибка с адресом для несуществующего модуля, ошибка для модуля без `createAgent`.
