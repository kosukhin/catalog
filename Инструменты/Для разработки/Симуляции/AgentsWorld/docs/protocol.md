# `lib/protocol.ts` — протокол мира

Словарь системы: типы сообщений акторов и служебные команды между главным потоком
и воркерами. Не импортирует ничего, поэтому от него могут зависеть все остальные
модули без риска циклических связей.

## Что экспортирует

| Имя | Назначение |
|---|---|
| `ActorId` | строковый идентификатор актора |
| `Message` | сообщение: `{ type, payload? }` |
| `ActorAssignment` | задание на создание актора: `{ id, type, moduleUrl, options }` |
| `WorkerCommand` | `start` / `deliver` / `stop` — команды воркеру |
| `WorkerEvent` | `ready` / `deliver` / `log` / `error` / `done` — события из воркера |
| `WORLD_ID` | адрес самого мира: сообщение на него попадает в мир, а не актору |
| `STATUS_REQUEST`, `STATUS_REPORT` | запрос и ответ состояния любого агента |
| `TICK` | импульс времени: слать может любой тикер, реагировать — любой агент |
| `StatusReport` | `{ id, type, details }` — что агент рассказал о себе |
| `createMessage` | создаёт сообщение и проверяет тип |
| `isMessage` | проверяет, что значение похоже на сообщение |

## Два независимых канала

1. **Сообщения акторов** (`Message`) — единственный способ общения акторов.
   Актор не вызывает методы другого актора, он кладёт сообщение в его ящик.
2. **Служебный канал** (`WorkerCommand` / `WorkerEvent`) — общение потоков с миром.
   Это не часть ActorModel: акторы о нём не знают.

## Инварианты

- `type` сообщения — непустая строка; `createMessage('  ')` бросает исключение.
- `payload` необязателен: если его не передали, ключа в объекте нет
  (`'payload' in message === false`).
- Нагрузка должна переживать structured clone: воркеры передают её копированием,
  поэтому функции, классы и `Symbol` использовать нельзя. По той же причине в
  `ActorAssignment` едет `moduleUrl` (строка), а не фабрика агента.
