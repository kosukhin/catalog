# `lib/actorRuntime.ts` — почтовый цикл актора

Связка «почтовый ящик + актор». Рантайм выдаёт актору ящик и контекст, а затем
в цикле вынимает сообщения и передаёт их в `receive`.

## Что экспортирует

- `ActorPorts` — внешние зависимости: `send` в чужой поток, `log`, `onError`.
- `ActorRuntimeOptions` — `{ id, actor, ports }`.
- `ActorRuntime` — сам рантайм.

## Как работает

```
start()  → actor.start(context) → запускается #pump()
#pump()  → цикл: take() → actor.receive(message) → take() → …
stop()   → mailbox.close() → дождаться цикла → actor.stop(context)
```

| Член | Назначение |
|---|---|
| `id`, `type` | кто этот актор |
| `pending` | сколько сообщений ещё не обработано |
| `context` | контекст актора (нужен тестам и внешним отправителям) |
| `start()` | запускает `start` и цикл; повторный вызов — ошибка |
| `deliver(from, message)` | кладёт сообщение в ящик; `false` после остановки |
| `stop()` | мягкая остановка с дочитыванием очереди |

## Инварианты

- **Одно сообщение за раз.** Цикл ждёт завершения `receive`, поэтому состояние
  актора не требует блокировок. Параллелизм достигается между акторами на разных
  потоках, а не внутри одного актора.
- **Ошибка не убивает цикл.** Исключение из `receive` уходит в `ports.onError`,
  следующее сообщение всё равно обрабатывается — иначе один сбойный обработчик
  остановил бы весь поток.
- **`stop()` дочитывает очередь:** накопленные сообщения будут обработаны, и только
  потом вызовется `actor.stop`.
- Прямых вызовов других акторов нет: всё, что актор хочет сообщить, уходит через
  `ports.send`.
