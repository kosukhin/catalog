# `lib/rosterAgent.ts` — служебный реестр агентов

Единственный агент, который живёт в ядре (`lib/`), а не в `agents/`: это
**инфраструктура**, а не модель мира. `World` поднимает его всегда, поэтому любому
агенту есть у кого спросить «какие агенты есть в мире» и «кто появится потом».

## Что экспортирует

| Экспорт | Назначение |
|---|---|
| `type` | `'RosterAgent'` |
| `moduleUrl`, `createAgent` | контракт модуля агента |
| `RosterAgent` | класс |
| `ROSTER_AGENT_ID` | `'RosterAgent-1'` |
| `ROSTER_SNAPSHOT`, `ROSTER_QUERY`, `ROSTER_REPORT`, `ROSTER_SUBSCRIBE`, `ROSTER_UPDATE` | типы сообщений |
| `RosterEntry`, `RosterReport`, `RosterUpdate` | типы данных |

## Откуда реестр знает состав

Реестр не может «посмотреть» на других акторов: у акторов нет общей памяти. Поэтому
состав ему присылает **мир**: после запуска потоков `World` отправляет
`roster-snapshot` со списком всех агентов (`[{ id, type }]`). Реестр хранит
`id → type` и отдаёт эту карту по запросу.

## Сообщения

| Сообщение | Кто шлёт | Полезная нагрузка | Что делает реестр |
|---|---|---|---|
| `roster-snapshot` | `World` | `{ agents: [{ id, type }] }` | заменяет состав; о новичках уведомляет подписчиков |
| `roster-query` | любой агент | `{ types, replyTo }` | отвечает `roster-report` на `replyTo` |
| `roster-report` | реестр | `{ types, ids }` | ответ на запрос, его отправляет реестр |
| `roster-subscribe` | любой агент | `{ types, replyTo }` | запоминает подписчика и сразу шлёт ему текущих подходящих |
| `roster-update` | реестр | `{ agents: [{ id, type }] }` | уведомление о новых агентах подходящего типа |

Пустой список `types` значит «любой тип».

## Подписка на новых агентов

Агент подписывается сообщением `roster-subscribe` с `replyTo` (и необязательным
фильтром `types`). Реестр:

1. сразу отправляет `roster-update` со всеми текущими подходящими агентами — чтобы
   подписчик был в курсе, даже если снимок пришёл раньше подписки (гонка порядка);
2. дальше уведомляет `roster-update` о каждом **новом** агенте — как только состав
   изменился.

Агент, который уже был известен, повторно не уведомляется: сравнивается пара
`id → type`.

На это опирается `TickAgent` (`agents/tickAgent.ts`): он спрашивает людей по типу и,
если появляется новый человек, сам решает, будить ли его.

## Инварианты

- Реестр — актор: обратиться к нему можно только сообщением.
- `roster-query` и `roster-subscribe` без `replyTo` отвечают только строкой в лог.
- Битый снимок (нет массива `agents`, у агента нет `id` или `type`) — исключение с
  понятным текстом; состав не меняется.
- На незнакомое сообщение — строка в лог, без падения.
- `describe()` отдаёт число известных агентов и подписчиков — виден в дашборде.

## Как спросить из своего агента

```ts
import { ROSTER_AGENT_ID, ROSTER_QUERY, ROSTER_REPORT } from '../lib/rosterAgent.ts';

start(context: ActorContext): void {
    context.send(ROSTER_AGENT_ID, createMessage(ROSTER_QUERY, { types: ['HumanAgent'], replyTo: context.id }));
}

protected handle(message: Message, context: ActorContext): void {
    if (message.type === ROSTER_REPORT) {
        // пришёл список id нужного типа
    }
}
```

## Тест

`test/rosterAgent.test.ts` — контракт модуля, запись снимка, поиск по типам и «все
типы», ответ спрашивающему, отказ без `replyTo`, подписка и её повтор, уведомление
о новом агенте, отсутствие повторных уведомлений, битый снимок и запрос, состояние
для дашборда, незнакомое сообщение.
