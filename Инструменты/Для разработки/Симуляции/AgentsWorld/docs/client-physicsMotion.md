# `client/physicsMotion.ts` — линейное движение тел

Чистая математика движения для сцены. По каждому телу держится один отрезок прямой
`start → end` и длительность, за которую его надо пройти. Кадр просто спрашивает
положение тела на момент времени, поэтому тело едет **линейно** — с постоянной
скоростью, без разгона-торможения, рывков и зависимости от частоты кадров.

Модуль не знает ни про three.js, ни про DOM: время приходит аргументом в секундах,
поэтому он полностью проверяется в Node. Импортов нет.

## Как считается отрезок

`setTarget(id, point, now)` вызывается на каждый опрос `/api/physics`:

- тела ещё нет — оно ставится в точку, длительность нулевая;
- точка не изменилась — отрезок не перезапускается, тело продолжает текущий
  (именно поэтому редкие обновления «размазываются» в ровное движение);
- точка изменилась — открывается новый отрезок. Началом становится **текущее**
  положение тела, а не прошлая цель: если сэмпл пришёл раньше конца отрезка,
  скачка не будет. Длительность — измеренный интервал между прошлым и новым
  изменением цели, зажатый в `0.05…5` с.

`position(id, now)` возвращает линейную интерполяцию внутри текущего отрезка:
`t = clamp((now - startedAt) / duration, 0, 1)`. Пройденный отрезок держит тело в
конечной точке, поэтому остановившееся тело просто стоит. Для неизвестного тела — `null`.
Трекер — курсор текущего отрезка, историю он не хранит: запрашивать положение нужно
на текущий (идущий вперёд) момент времени.

`prune(seen)` забывает тела, которых больше нет в состоянии физики.

## Что экспортирует

| Экспорт | Назначение |
|---|---|
| `createMotionTracker()` | трекер движения: `setTarget`, `position`, `prune` |
| `MotionTracker` | тип трекера |
| `MotionPoint` | точка `{ x, y, z }` |

## Ограничения

Началом нового отрезка берётся текущее положение, а длительность ограничена сверху
`5` с: если сервер обновляет цель реже, чем раз в 5 секунд, тело успеет доехать и
коротко подождать. Периода тика клиент не знает — он измеряет его по своим сэмплам.
