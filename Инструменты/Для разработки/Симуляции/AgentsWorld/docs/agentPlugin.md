# `lib/agentPlugin.ts` — контракт модуля агента

Единственное, что ядро знает об агентах. Реестра в проекте нет: конкретные модули
подключает приложение, а `lib` проверяет только форму того, что ему дали.

## Что экспортирует

| Имя | Назначение |
|---|---|
| `AgentPlugin` | тип: `{ type, moduleUrl, createAgent }` |
| `assertAgentPlugin(value)` | проверяет форму модуля и объясняет, чего не хватает |
| `toModuleMap(plugins)` | строит карту «тип агента → адрес модуля» |

## Контракт модуля агента

```ts
export const type = 'МойАгент';                // имя для статистики мира
export const moduleUrl = import.meta.url;      // адрес модуля: уедет в поток
export function createAgent(id, options) {…}   // как создать экземпляр
```

Приложение передаёт такие модули в мир как есть:

```js
import * as myAgent from '../agents/myAgent.ts';
new World({ [myAgent.type]: 4 }, { agents: [myAgent] });
```

## Почему адрес, а не фабрика

В другой поток можно передать только данные, а функция — не данные. Поэтому в
поток уезжает строка `moduleUrl`, и воркер сам делает `import(moduleUrl)`
(`lib/agentLoader.ts`). Функция `createAgent` нужна там же, внутри потока; в
главном потоке она используется только для проверки, что модуль настоящий.

## Инварианты

- `type` — непустая строка, `moduleUrl` — непустая строка, `createAgent` — функция.
- Ошибки говорят, чего именно не хватает: `в модуле агента «X» нет экспорта moduleUrl`.
- Один тип нельзя подключить дважды: `тип агента «X» подключён дважды`.
- Модуль ничего не знает про мир: он не импортирует `world.ts` и не знает, кто его вызовет.
