# `lib/stats.ts` — статистика мира

Превращает состав мира в список заданий на создание акторов и проверяет данные,
чтобы ошибка всплывала до запуска потоков.

## Формат: `Map` «модуль агента → количество»

Ключ — сам модуль агента, поэтому сведения об агенте не дублируются: из ключа
берутся и имя типа (`type`), и адрес кода (`moduleUrl`).

```js
import * as echoAgent from '../agents/echoAgent.ts';

new World(new Map([[echoAgent, 6]]));
```

**Почему `Map`, а не обычный объект.** В объекте ключ всегда приводится к строке:
`{ [echoAgent]: 6 }` дало бы `{ '[object Module]': 6 }`, и агент потерялся бы. В
`Map` ключом может быть сам объект модуля — запись остаётся однозначной.

## Что экспортирует

| Имя | Назначение |
|---|---|
| `Population` | тип: `ReadonlyMap<AgentPlugin, number>` |
| `normalizePopulation(population)` | разворачивает состав в `ActorAssignment[]` |
| `summarizePopulation(assignments)` | обратная сводка: тип → количество |

## Во что разворачивается

```js
new Map([[echoAgent, 2]])
// →
[
  { id: 'EchoAgent-1', type: 'EchoAgent', moduleUrl: 'file:///…/echoAgent.ts', options: {} },
  { id: 'EchoAgent-2', type: 'EchoAgent', moduleUrl: 'file:///…/echoAgent.ts', options: {} },
]
```

## Инварианты

- Аргумент обязан быть `Map`; на обычный объект приходит подсказка
  `статистика мира задаётся как Map «модуль агента → количество»`.
- Форма модуля проверяется через `assertAgentPlugin` — ошибки называют, чего нет.
- Количество — целое неотрицательное: `-1`, `1.5`, `NaN` — ошибка.
- Ноль допустим и означает «агентов этого типа нет».
- Один тип нельзя указать дважды (два разных модуля с одинаковым `type`).
- Мир не может быть пустым: сумма количеств должна быть больше нуля.
- Порядок агентов — как в `Map`; на этом порядке строится распределение по потокам.

## Тест

`test/stats.test.ts` — разворачивание `Map`, адрес из ключа, нулевые количества,
пустой мир, отказ на обычном объекте, дробные и отрицательные значения, дубль типа,
битый модуль, `summarizePopulation`.
