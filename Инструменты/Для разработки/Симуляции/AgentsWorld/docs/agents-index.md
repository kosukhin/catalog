# `agents/index.ts` — все агенты в одном месте

Точка сборки модулей агентов. Это **не реестр** «тип → класс» (ядро про такое не
знает), а просто список: тот, кто собирает мир, берёт модули отсюда и решает, кого
и сколько запустить.

```js
import * as agents from '../agents/index.ts';

new World(new Map([
    [agents.dayAgent, { count: 1, options: { timeScale: 10 } }],
    [agents.humanAgent, 12],
    [agents.tickAgent, { count: 1, options: { intervalMs: 1000, recipients } }],
]));
```

## Что экспортирует

| Имя | Модуль |
|---|---|
| `dayAgent` | `agents/dayAgent.ts` |
| `humanAgent` | `agents/humanAgent.ts` |
| `humanCatalogAgent` | `agents/humanCatalogAgent.ts` |
| `tickAgent` | `agents/tickAgent.ts` |

`echoAgent` сюда не входит: это тестовый агент для проверки рантайма, в мире из
моделей он не участвует.

## Зачем нужен

- **Мир собирается из одного места.** Приложению и демо не нужно перечислять
  импорты агентов по одному — и они не упираются в правило «не больше четырёх
  импортов на модуль».
- **Каждый элемент — ровно то, что ждёт `Map` состава мира**: `type`, `moduleUrl`,
  `createAgent`. Это проверяется тестом через `assertAgentPlugin`.
- **Новый агент подключается двумя строками**: экспорт здесь и пара в составе мира.

## Что он НЕ делает

- Не создаёт агентов и не знает, сколько их будет.
- Не связан с `lib`: зависимость идёт только `agents/ → lib/`.
- Не заменяет контракт: если модуль агента перестанет экспортировать `type` или
  `createAgent`, тест упадёт сразу.

## Тест

`test/agents-index.test.ts` — состав списка, соответствие контракту
`AgentPlugin` у каждого модуля, уникальность типов.
