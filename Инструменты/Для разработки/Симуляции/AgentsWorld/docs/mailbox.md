# `lib/mailbox.ts` — почтовый ящик актора

Очередь входящих сообщений. Реализует главное правило ActorModel: сообщение
не вызывается, а кладётся в ящик получателя; отправитель не ждёт обработки.

## Что экспортирует

- `Envelope` — `{ from, message }`: сообщение вместе с отправителем.
- `Mailbox` — сам ящик.

## Как работает

| Метод / свойство | Поведение |
|---|---|
| `put(envelope)` | отдаёт сообщение ожидающему `take` либо ставит в очередь; `false`, если ящик закрыт |
| `take()` | `Promise<Envelope \| undefined>`; при пустой очереди ждёт; `undefined` — ящик закрыт и сообщений не будет |
| `close()` | закрывает ящик и будит всех ожидающих |
| `size` | сколько сообщений в очереди |
| `closed` | закрыт ли ящик |

Совмещены две стратегии: если актор уже ждёт сообщение, оно передаётся напрямую
без промежуточной очереди; иначе встаёт в очередь и выдаётся по FIFO.

## Инварианты

- Порядок FIFO сохраняется всегда — иначе актор видел бы события мира в случайном
  порядке.
- `close()` — мягкая остановка: уже накопленные сообщения можно дочитать, и только
  после опустошения очереди `take()` вернёт `undefined`.
- Двойной `close()` безопасен.
- Сам по себе ящик ничего не знает о потоках и акторах: его можно тестировать без
  рантайма.

## Тест

`test/mailbox.test.ts` — FIFO, ожидание сообщения, отказ после закрытия, `undefined`
для ожидающего `take`, сохранность накопленных сообщений после `close()`.

## Без геттеров

Геттеры `size` и `closed` убраны: длина очереди читается методом `pending()`.
Признак закрытия наружу не нужен — `put()` и так возвращает `false`, а `take()`
отдаёт `undefined`.
