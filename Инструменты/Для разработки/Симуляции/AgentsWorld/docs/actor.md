# `src/actor.ts` — контракт актора

Описывает, что такое актор в этой системе, и даёт удобную базу для реализации.

## Что экспортирует

| Имя | Назначение |
|---|---|
| `ActorContext` | то, что рантайм даёт актору: `id`, `send(to, message)`, `log(text)` |
| `Actor` | интерфейс: `type`, `start?`, `receive`, `stop?` |
| `ActorFactory` | `(id, options) => Actor` — фабрика для реестра |
| `AbstractActor` | база: реализует `receive`, наследник пишет только `handle` |

## Почему так

- **Нет ссылок на других акторов.** В `ActorContext` нет коллекции соседей и нет
  методов вида `callOther()`. Единственный способ повлиять на другого актора —
  `send`, то есть сообщение в чужой почтовый ящик. Так ActorModel невозможно
  нарушить случайно.
- **`receive` вместо `handle`.** Рантайм вызывает `receive`, а наследник
  `AbstractActor` реализует `protected handle` — снаружи обработчик не вызвать,
  поэтому актор нельзя «дёрнуть» в обход ящика.
- **`start`/`stop` необязательны.** Актору, которому нечего делать при запуске и
  остановке, не нужно писать пустые методы.
- **`log` — телеметрия, а не сообщение.** Строка уходит в мир, а не другому актору.

## Инварианты

- `type` — ключ реестра, по нему создаётся актор.
- `receive` может быть асинхронным; рантайм дожидается завершения перед следующим
  сообщением, поэтому внутреннее состояние актора не нужно защищать блокировками.
- Исключение из `receive`/`handle` не должно «убивать» актора — это забота
  рантайма (`src/actorRuntime.ts`).
