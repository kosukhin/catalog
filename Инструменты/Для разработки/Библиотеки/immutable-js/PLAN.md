# 📚 План изучения библиотеки Immutable.js

> **Immutable.js** — библиотека постоянных (persistent) иммутабельных коллекций для JavaScript:
> `List`, `Map`, `OrderedMap`, `Set`, `OrderedSet`, `Stack`, `Record`, ленивые `Seq`, `Range`, `Repeat`.
> Официальная документация: https://immutable-js.com/docs/v5/
>
> Версия курса: **immutable 5.2.1** (ноябрь 2026). Примеры — под v5: только именованные
> импорты, default-экспорта у пакета больше нет. Отличия v4 и v3 разбираются в уроке 6.3.

## Как работать с планом

Проходи уроки по порядку — каждый следующий опирается на предыдущий. После каждого урока
я буду объяснять теорию с примерами, а ты сможешь задавать вопросы и просить практические
задания.

Слои курса (по мере написания уроков):

- **конспект** — `Урок-N.M-Тема.md` в корне: цель, теория, примеры, ловушки, резюме, чек-лист;
- **теория** — `Теория/` с теми же именами файлов: откуда взялись persistent-структуры,
  почему они устроены именно так и где проходят границы применимости;
- **практика** — `Практика/`: задания с проверкой ответов в браузере;
- **демо** — `Демо/`: интерактивные сцены (структурное разделение, стоимость операций,
  ленивые цепочки `Seq`).

Правила примеров: каждый блок кода самодостаточен (свои импорты и данные), копируется
в `.mjs` и запускается как есть. Версия библиотеки фиксируется в `package.json`,
ожидаемые результаты проверяются скриптами (`npm run check`, `npm run check:practice`,
`npm run check:demo` — появятся вместе с первыми уроками).

> 🧠 Прогресс удобно отмечать в таблице статусов в конце плана: пройдено / есть вопросы.

## Что будет уметь после курса

- объяснять, что такое persistent-структуры, structural sharing и чем это отличается
  от глубокого копирования;
- выбирать коллекцию (`List`, `Map`, `Set`, `OrderedMap`, `Stack`, `Record`, `Seq`)
  под операции и их сложность, а не «по привычке»;
- обновлять вложенное состояние без мутаций: `setIn`, `updateIn`, `mergeDeep`, `deleteIn`;
- писать ленивые пайплайны на `Seq`, включая бесконечные `Range` и `Repeat`;
- описывать схемы данных через `Record` и типизировать их в TypeScript;
- ускорять массовые изменения через `withMutations` и измерять эффект, а не верить на слово;
- встраивать Immutable.js в React, Redux и SSR, не протаскивая коллекции через границы API;
- мигрировать проект с v4 на v5 и осознанно выбирать между Immutable.js, Immer и обычными
  объектами.

**Уровни:**

- 🟢 Базовый — обязательно
- 🟡 Средний — важно для реальных задач
- 🔴 Продвинутый — для глубокого понимания

**Предварительные требования:** ES2015+ (деструктуризация, spread, итераторы, нативные
`Map`/`Set`), базовый React для этапа 5 и TypeScript для урока 5.3 (его можно пропустить).

## Этап 0. Подготовка 🟢 (~2–3 ч)

### Урок 0 — Иммутабельность и persistent-структуры
- Мутация, защитное копирование и `Object.freeze`: почему заморозка поверхностная
- Ссылочное равенство и `is()`: почему `===` не видит «такое же» значение
- Persistent data structure: structural sharing, hash array mapped trie (`Map`/`Set`),
  vector trie (`List`), сложность `O(log32 N)`
- Коллекции как значения, а не объекты: что это меняет в архитектуре приложения
- Что библиотека даёт и чего не делает: не заменяет дизайн состояния и не «делает безопасно»
- Альтернативы и границы: Immer, `structuredClone`, ручные копии, `readonly` в TypeScript
- Практика: сравнить копирование объекта и `set` на `Map`, сделать вывод о цене и выгоде

### Урок 0.1 — Установка, импорты, TypeScript и первые проверки
- `npm install immutable@5`, фиксация версии; ветки v4 (4.3.9) и v6 (beta) — что выбрать
- Именованные импорты: `import { Map, List } from 'immutable'`; почему `import Immutable`
  больше не работает и когда уместен `import * as Immutable`
- ESM/CJS-сборки, дерево-шейкинг, подключение через `<script>`
- Встроенные типы TypeScript: `MapOf`, `RecordOf`, `RecordFactory`, `List<T>`, `Collection<K, V>`
- Предикаты: `isCollection`, `isKeyed`, `isIndexed`, `isAssociative`, `isOrdered`,
  `isList`, `isMap`, `isRecord` и остальные
- `is()`, `hash()`, `isImmutable()`, `isValueObject()` — первые инструменты сравнения
- REPL/Playground и чтение `toString()` у коллекций
- Кратко о миграции v4 → v5: нет default-экспорта, удалён `Map.of`, `Collection.is*`
  заменены функциями, `Range` требует минимум два аргумента
- Практика: скрипт, который создаёт, читает, сравнивает и печатает коллекции

## Этап 1. Базовые коллекции 🟢 (~6–8 ч)

### Урок 1.1 — `List`: иммутабельный массив
- Создание: `List()`, `List([...])`, `List.of(...)`, из итерируемого и array-like; `List.isList`
- Чтение: `size`, `get` (включая отрицательные индексы), `first`/`last`, `has`, `includes`,
  `indexOf`/`lastIndexOf`
- Изменения: `set`, `insert`, `delete`/`remove`, `push`/`pop`, `unshift`/`shift`, `splice`,
  `setSize`, `clear`
- Стоимость: `get`/`set` — `O(log32 N)`, `push`/`pop` — `O(1)`, `insert`/`delete`/`splice` — `O(N)`
- Переупорядочивание и срезы: `concat`, `slice`, `reverse`, `shuffle`, `sort`/`sortBy`,
  `interpose`/`interleave`
- Ловушки: у `List` нет «дыр», `set` за границей размера заполняет промежуток `undefined`,
  `forEach` обходит все индексы; `sort` — стабильная, но материализует коллекцию
- Практика: очередь, стек, буфер истории, пагинация

### Урок 1.2 — `Map`: иммутабельный словарь
- Создание из объекта, пар `[k, v]` и другой коллекции; `Map.isMap`; `Map.of` удалён в v5
- Ключи любого типа: равенство через `is`, `NaN` как ключ, коллекции и `ValueObject` как ключи,
  обычные объекты — по ссылке
- Чтение и запись: `get`, `has`, `set`, `delete`/`remove`, `deleteAll`, `clear`, `update`
- Итерация не определена, но стабильна; `keySeq`/`valueSeq`/`entrySeq`, `keys`/`values`/`entries`
- Преобразование ключей и значений: `mapKeys`, `mapEntries`, `flip`; `sort`/`sortBy` → `OrderedMap`
- No-op оптимизация: `set` тем же значением возвращает тот же объект
- Ловушки: ключи-строки при создании из объекта (`{ 1: 'one' }` → ключ `'1'`),
  нельзя полагаться на порядок обхода
- Практика: нормализованный справочник, кеш, счётчики, обновление записи по `id`

### Урок 1.3 — `Set` и `OrderedSet`: уникальные значения
- Создание: `Set()`, `Set.of(...)`, `Set.isSet`; уникальность через `is()`, а не `===`
- Операции: `add`, `delete`/`remove`, `has`, `clear`, `union`, `intersect`, `subtract`,
  `isSubset`, `isSuperset`
- Порядок обхода `Set` не гарантирован; `OrderedSet` сохраняет порядок добавления и стоит дороже
- `sort`/`sortBy` на `Set` возвращают `OrderedSet`
- Ловушки: объекты в `Set` сравниваются по ссылке; операции возвращают новую коллекцию
- Практика: теги, дедупликация, права доступа, сравнение наборов

### Урок 1.4 — `OrderedMap` и `Stack`: порядок и LIFO
- `OrderedMap`: гарантия порядка вставки и цена этой гарантии; когда порядок действительно нужен
  (порядок строк в UI, стабильный diff, детерминированный вывод)
- `Stack`: LIFO-коллекция, `push`/`pop`/`peek` и `unshift`/`shift` работают с начала;
  `Stack.of`, `Stack.isStack`
- Сравнительная таблица коллекций: порядок, сложность операций, типичные сценарии
- Ловушки: `Map` → `OrderedMap` через `toOrderedMap()` не восстанавливает порядок, если он уже потерян
- Практика: выбрать коллекцию для пяти сценариев и обосновать выбор

### Урок 1.5 — Вложенность и конвертация
- `fromJS` и `toJS` (глубоко), `toJSON` (неглубоко), `toArray`, `toObject`
- Переходы между типами: `toMap`, `toOrderedMap`, `toSet`, `toOrderedSet`, `toList`, `toStack`, `toSeq`
- Глубокое чтение и обновление: `getIn`, `setIn`, `updateIn`, `removeIn`/`deleteIn`, `hasIn`
- Reviver в `fromJS`: ключ, последовательность и путь к значению
- Ловушки: `toJS` теряет тип `Record` и дорог на больших данных; `JSON.stringify`
  вызывает `toJSON`; `getIn` по отсутствующему пути возвращает `undefined`, а не бросает ошибку
- Практика: обновление `state.setIn(['users', id, 'name'], name)` без мутаций
- Границы: конвертировать на границе API/компонента, а не в горячем пути

## Этап 2. Функциональная работа с коллекциями 🟡 (~6–8 ч)

### Урок 2.1 — Обход, поиск и агрегаты
- `forEach`, `map`, `filter`/`filterNot`, `reduce`/`reduceRight`, `every`/`some`, `join`
- Поиск: `find`/`findLast`, `findEntry`/`findLastEntry`, `findKey`/`findLastKey`,
  `keyOf`/`lastKeyOf`, `indexOf`/`findIndex`
- Агрегаты: `count`/`countBy`, `max`/`min`, `maxBy`/`minBy`, `isSubset`/`isSuperset`
- Три семейства коллекций: `Collection.Keyed`, `Collection.Indexed`, `Collection.Set` —
  что общего, чем отличаются и почему метод ведёт себя по-разному
- Итераторы: `keys`/`values`/`entries`, протокол ES6, `for...of`, spread, `Array.from`
- Аргументы колбэков `(value, key, iter)` и `context`
- Ловушки: `map` на `Map` сохраняет ключи; `filter` возвращает коллекцию того же типа;
  `reduce` без начального значения на пустой коллекции бросает ошибку
- Практика: отчёты по массиву заказов, поиск первого подходящего, агрегаты по группам

### Урок 2.2 — Группировка и разбиение
- `groupBy` → `Map`, `partition` → массив из двух коллекций, `countBy` → `Map`: три способа делить данные
- Как выбрать между `filter` + `map`, `groupBy` и `partition`
- `flatten` и `flatMap`: глубина, поведение на keyed-коллекциях
- `zip`, `zipWith`, `zipAll`, `interpose`, `interleave`
- Ловушки: `groupBy` и `countBy` — не ленивые операции; порядок групп и ключей не гарантирован
- Практика: разложить заказы по статусам, посчитать топ-N, сравнить два набора

### Урок 2.3 — Сортировка, срезы и слияния
- `sort`/`sortBy` (стабильная сортировка), `reverse`; `Map#sort` → `OrderedMap`,
  `Set#sort` → `OrderedSet`
- Срезы и окна: `slice`, `rest`, `butLast`, `skip`/`skipLast`, `skipWhile`/`skipUntil`,
  `take`/`takeLast`, `takeWhile`/`takeUntil`
- `concat` и слияние: `merge`, `mergeWith`, `mergeDeep`, `mergeDeepWith`, `mergeIn`, `mergeDeepIn`
- Разница между `merge` и `mergeDeep`, политика конфликтов и `merger`-функция
- Стоимость: сортировка материализует коллекцию, `concat` копирует, глубокое слияние дороже
- Практика: пагинация, «последние N», слияние настроек с значением по умолчанию

### Урок 2.4 — `Seq`: ленивые последовательности
- `Seq()`, `Seq.Keyed`, `Seq.Indexed`, `Seq.Set`, `Seq.isSeq`
- Ленивость: цепочка `map`/`filter` без промежуточных коллекций; пример из документации,
  где `filter` вызывается три раза, а `map` — один
- Когда `Seq` материализуется: `toList`/`toMap`/`toJS`/`toArray`, `size`/`count`, `reduce`, `sort`
- `cacheResult()`: кеширование результата и повторный обход
- `Range(start, end, step)` и `Repeat(value, times)`; бесконечные последовательности
  с `take`/`takeWhile`
- Ловушки: повторный обход ленивой цепочки повторяет вычисления; побочные эффекты в `map`;
  бесконечная `Seq` в `toJS`, `sort` или `count` не завершится
- Практика: ленивый пайплайн по большому массиву, первые N подходящих элементов

## Этап 3. `Record`, `ValueObject` и равенство 🟡 (~4–5 ч)

### Урок 3.1 — `Record`: объекты с фиксированной схемой
- `Record(defaultValues, name?)` создаёт фабрику; вызов фабрики создаёт экземпляр,
  `new` нужен только для class-формы
- Чтение и изменение: `get`, `set`, `update`, `remove`/`delete` (сбрасывает к значению
  по умолчанию), `clear`, `merge`, `mergeDeep`
- Глубокие операции: `setIn`, `updateIn`, `mergeIn`, `mergeDeepIn`, `deleteIn`; `toJS`,
  `toJSON`, `toObject`, `toSeq`
- `Record` — не `Collection`: другой набор методов и другая механика равенства
- Ограничения: нельзя определять ключи с именами методов (`get`, `set` и т. п.);
  `record.b = 5` бросает ошибку; лишние ключи конструктора игнорируются
- `Record.isRecord`, `Record.Factory`, типы `RecordOf` и `RecordFactory` в TypeScript
- Ловушки: в `withMutations` у `Record` разрешён только `set`; сериализация в plain object
  не бесплатна; нюанс равенства: записи из разных фабрик с одинаковыми ключами и значениями
  считаются равными
- Практика: схемы `User`, `Todo`, настройки приложения; значения по умолчанию

### Урок 3.2 — `ValueObject`: собственные значения
- Контракт `equals(other)` + `hashCode()`; требования согласованности
- `is()`, `hash()`, `isValueObject()`: как библиотека понимает «равные значения»
- Зачем: ключи `Map` и элементы `Set` по значению, кеши, мемоизация
- 31-битный хеш, коллизии и почему hashCode обязан совпадать у равных объектов
- `===`, `Object.is` и `Immutable.is`: три разных вопроса «это одно и то же?»
- Ловушки: мутируемый объект в роли значения; несогласованные `equals`/`hashCode`;
  глубокая проверка равенства стоит времени
- Практика: классы `Money`, `Point`, `UserId`; использование как ключей `Map`

### Урок 3.3 — `Record` + вложенность + сериализация
- `Record` внутри `Map`/`List`; обновление через `setIn` и `updateIn`
- `fromJS` с reviver: превращение узлов по ключевому пути в `Record`
- `toJS`, `toJSON`, `JSON.stringify` и обратная гидрация
- Версионирование схемы и значения по умолчанию при добавлении полей
- Ловушки: `mergeDeep` с `Record`, неполные объекты, потеря прототипа при сериализации
- Практика: модель состояния приложения на `Record` + `Map` + сериализация в JSON

## Этап 4. Производительность и память 🟡 (~5–6 ч)

### Урок 4.1 — Как устроены структуры внутри
- HAMT (hash array mapped trie) для `Map`/`Set` и vector trie для `List`: 32-ветвление,
  structural sharing, почему `get`/`set` — `O(log32 N)`
- Хеширование и коллизии; почему `OrderedMap` и `OrderedSet` дороже обычных версий
- Порядок обхода `Map` не определён, но стабилен: что это значит на практике
- Память: какие узлы разделяются, где появляются копии, почему `insert`/`delete` в `List` — `O(N)`
- Как читать сложность в документации и не путать её с фактическим временем
- Практика: предсказать сложность десяти операций и проверить замером

### Урок 4.2 — `withMutations`, `asMutable`, `asImmutable`
- `withMutations`: временная mutable-копия и одна новая коллекция вместо N промежуточных
- `asMutable`/`asImmutable`/`wasAltered`: ручной режим и его правила
- Почему mutable-копию нельзя возвращать наружу, хранить в состоянии и использовать для равенства
- Не все методы безопасны в `withMutations`: ориентироваться на пометки в документации;
  `List#delete`, `insert`, `splice` переиндексируют коллекцию и не годятся
- `merge` и `mergeDeep` уже используют батчинг внутри — не нужно оборачивать их повторно
- Ловушки: забытый `asImmutable`, ссылка на mutable-объект после операции, `wasAltered`
  не заменяет проверку результата
- Практика: массовая вставка 10 000 записей тремя способами и сравнение

### Урок 4.3 — Бенчмарки и профилирование
- Методика: прогрев, несколько прогонов, `performance.now()`, изоляция сценария,
  осторожность с JIT и микробенчмарками
- Где Immutable.js выигрывает (большие данные, частые обновления, undo-история)
  и где проигрывает (маленькие коллекции, частые `toJS`, случайный доступ)
- `toJS` в рендере или цикле — главный антипаттерн; селекторы и мемоизация
- Стоимость `is()` при глубоком сравнении и способы её уменьшить
- Размер бандла, tree-shaking и случаи, когда библиотека не нужна
- Практика: профиль реального сценария, отчёт «что было медленно и почему»

## Этап 5. Интеграция с приложениями 🟡 (~6–7 ч)

### Урок 5.1 — React: `memo`, `PureComponent`, `useState`/`useReducer`
- Ссылочное равенство и почему мутация ломает `React.memo`/`shouldComponentUpdate`
- `useState` и `useReducer` с Immutable: обновления через `setIn`, `updateIn`, `withMutations`
- Селекторы, `useMemo`, `reselect`; сравнение результатов через `is()`
- Границы: `toJS` на входе в презентационные компоненты, а не в глубине дерева
- Списки и ключи: `List`/`OrderedMap` как источник данных
- Ловушки: новый `toJS`-объект на каждый рендер; Immutable в props без необходимости
- Практика: todo- или канбан-доска с undo/redo

### Урок 5.2 — Redux и управление состоянием
- Редьюсеры на Immutable, начальное состояние; `combineReducers` из Redux рассчитан
  на plain-объект, для Immutable-корня нужен `redux-immutable` или ручная композиция
- `Record` как модель состояния, actions и чистые обновления
- `withMutations` для массовых изменений; нормализованные сущности в `Map`
- DevTools, time-travel и сериализация состояния
- Сравнение с Immer/redux-toolkit: Proxy и draft против persistent-структур;
  эргономика против предсказуемости и строгого равенства
- Практика: стор с сущностями и порядком + Undo/Redo

### Урок 5.3 — TypeScript и границы типов
- `MapOf`, `RecordOf`, `RecordFactory`, `List<T>`, `Collection<K, V>`, `Seq`
- Строгая типизация `Map`: в v5 `Map({ length: 3 })` выводится как `MapOf<{ length: number }>`,
  и `get('inexistant')` — ошибка компиляции
- Когда нужно явно расширять тип (`Map<{ a: string; b?: string }>`), чтобы разрешить `set`
- Типизация селекторов, редьюсеров и `getIn`; `MapOf` и `RecordOf` в публичном API
- `Readonly` vs Immutable: где хранить коллекции, где обычные объекты
- Практика: типизированная модель и селекторы без `any`

### Урок 5.4 — SSR, API и сериализация
- `toJS`/`toJSON` при формировании JSON-ответа и `fromJS` при гидрации
- Правило границы: наружу API отдаются обычные объекты, Immutable остаётся внутри
- Размер ответа, дублирование данных и стоимость глубокой конвертации
- SSR-кеш, мемоизация и передача состояния на клиент
- Практика: API-ответ + гидрация стора на клиенте

## Этап 6. Продвинутое и альтернативы 🔴 (~5–6 ч)

### Урок 6.1 — Расширение и интероп с нативным JavaScript
- `ValueObject` и `Record.Factory` как точки расширения; собственные фабрики значений
- Протокол итерации: `Symbol.iterator`, `for...of`, spread, `Array.from`,
  `Promise.all` над `Seq`
- Интероп с нативными `Map`/`Set`/`Array`: когда `toJS`, когда `toArray`, а когда
  итератор без материализации
- `Collection.Keyed`/`Indexed`/`Set` и `OrderedCollection`: как устроена иерархия типов
- Границы расширения: не патчить прототипы, не наследоваться от коллекций без необходимости
- Практика: обёртка над доменным типом + интеграция с нативным кодом

### Урок 6.2 — Ленивые алгоритмы и бесконечные структуры
- `Range`, `Repeat`, генераторы и `Seq` поверх произвольных итераторов
- Бесконечные пайплайны: `take`, `takeWhile`, `zip`, комбинация источников
- `cacheResult`: когда кеш помогает, а когда превращается в утечку памяти
- Отладка ленивых цепочек: где происходит материализация и сколько раз вызывается функция
- Ловушки: повторные вычисления, бесконечный `toJS`, скрытые побочные эффекты
- Практика: ленивый генератор первых N подходящих элементов, `zip` бесконечных источников

### Урок 6.3 — Миграции: v3 → v4 → v5
- v3 → v4: `Iterable` переименован в `Collection`, `Record` больше не коллекция,
  изменилась семантика `merge`/`mergeDeep`, появился протокол ES6-итерации
- v4 → v5: удалён default-экспорт, `Map.of` удалён, `Collection.is*` заменены функциями
  `is*`, `Range` требует минимум два аргумента, исправлен `hashCode` у
  `OrderedMap`/`OrderedSet`, улучшена типизация `Map`
- Актуальные ветки: 5.2.1, 4.3.9 (исправления безопасности), 6.0.0-beta — за чем следить
- Стратегия миграции: тесты на поведение, постепенная замена импортов, кодовые моды,
  фиксация версии
- Практика: миграция небольшого проекта с v4 на v5 и разбор поломок

### Урок 6.4 — Альтернативы и выбор инструмента
- Immer: Proxy и draft, `produce`, поддержка `Map`/`Set`, эргономика и цена
- Нативный `structuredClone`, `Object.freeze`, «просто не мутировать» и `readonly` в TypeScript
- Immutable.js vs Immer vs redux-toolkit vs обычные объекты: критерии выбора
- Когда Immutable.js — оверинжиниринг: маленькое состояние, редкие обновления,
  простая команда
- Практика: разобрать три кейса и обосновать выбор инструмента, а не «что модно»

## Этап 7. Итоговый проект 🎯

### Урок 7.1 — Большая практика
Собираем всё вместе. Варианты проекта (выбрать один):

- **Undo/Redo-редактор**: `Record` документа, `List` истории, `withMutations` для массовых
  правок, сериализация снимков и восстановление.
- **Нормализованный стор**: `Map` сущностей + `OrderedMap` порядка + `Record` схемы +
  селекторы + React-интерфейс с `memo`.
- **Симуляция или игра**: `Map` клеток, `Seq` для ленивых расчётов, time-travel по состояниям.
- **CLI/API-парсер**: `fromJS` + `Record`-схемы + валидация + JSON-вывод.

Критерии приёмки:

- ни одной мутации исходных данных; обновления только через API коллекций;
- нет `toJS` в горячем пути и на каждом рендере;
- осознанный выбор каждой коллекции с объяснением сложности операций;
- тесты на равенство, сериализацию и граничные случаи;
- замер «до/после» для хотя бы одной оптимизации (`withMutations` или ленивая `Seq`);
- README с описанием архитектуры и принятых компромиссов.

## Формат уроков (чтобы примеры не «падали»)

- Каждый блок кода самодостаточен: свои импорты и свои данные. Копируется в `.mjs`
  и запускается как есть.
- Импорты только именованные: `import { List, Map } from 'immutable'`.
- Ожидаемые ошибки обёрнуты в `try/catch`, чтобы блок доходил до конца.
- В конце урока: «Резюме» + «Чек-лист перед следующим уроком».
- Проверка: `npm run check` (все уроки) или
  `node scripts/check-examples.mjs Урок-1.1-List.md` (один урок).
