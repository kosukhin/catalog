# Урок 3.1 — `State`: вычисления с состоянием 🔴

> Цель: научиться описывать **изменение состояния без мутаций** — как рецепт,
> который выполняется только при запуске, и в котором состояние передаётся
> явно, а не лежит в глобальной переменной. Ключевые слова: `State(fn)`,
> `Pair(значение, состояние)`, `runWith`, `evalWith`, `execWith`, `State.get`,
> `State.put`, `State.modify`.
> Все примеры печатают результат в консоль и проверены на crocks 0.12.
>
> Документация: https://crocks.dev/docs/crocks/State.html

## 1. Зачем нужен State

Обычный счётчик с мутацией:

```js
let counter = 0
const tick = () => { counter += 1; return 'шаг' + counter }
```

Проблемы: состояние живёт **снаружи** функции, его нельзя сбросить без
«перезапуска мира», его меняют любые части программы, а тестировать нужно
с оглядкой на порядок вызовов. Ещё хуже — связанные цепочки: следующий шаг
зависит от того, что накопили предыдущие.

`State` переворачивает картину: **состояние — это параметр вычисления, а не
внешняя переменная**. Вычисление становится чистым «рецептом»: пока не вызовешь
`runWith(начальноеСостояние)`, **ничего не происходит**. Сколько раз запустишь —
столько раз и получишь свой независимый результат.

---

## 2. Форма State: `s -> Pair(значение, состояние)`

`State` оборачивает функцию, которая берёт текущее состояние и возвращает
`Pair` из **двух** вещей:

- `fst` (первый компонент) — **значение** шага (что «вернуло» вычисление);
- `snd` (второй компонент) — **новое состояние** (что осталось «в памяти»).

```js
import crocks from 'crocks'
const { State, Pair } = crocks

// значение = текущее состояние, состояние НЕ меняем
const peek = State(s => Pair(s, s))

// значение = текущее состояние, состояние увеличиваем
const inc = State(s => Pair(s, s + 1))

console.log(peek.runWith(5).toString())   // Pair( 5, 5 )
console.log(inc.runWith(0).toString())    // Pair( 0, 1 )
```

> ⚠️ **Порядок компонентов — главная ловушка State.** Именно
> `Pair(значение, состояние)` (как в исходнике crocks: `evalWith` берёт `fst`,
> `execWith` — `snd`). Перепутаешь — **ошибки не будет**: просто `evalWith` и
> `execWith` молча вернут не то, что ждёшь. Всегда проверяй себя этим правилом.

> 📖 Важно: `Pair` здесь — тот самый из урока 2.1, и это не случайно: State —
> «дедушка» Writer-паттерна, где рядом с результатом проносится контекст.

## 3. Три способа запустить

```js
import crocks from 'crocks'
const { State, Pair, runWith, evalWith, execWith } = crocks

const inc = State(s => Pair(s, s + 1))

// метод — возвращает целый Pair
console.log(inc.runWith(0).toString()) // Pair( 0, 1 )

// только ЗНАЧЕНИЕ (fst)
console.log(inc.evalWith(0)) // 0

// только СОСТОЯНИЕ (snd)
console.log(inc.execWith(0)) // 1

// pointfree-версии (каррированы: сначала начальное состояние)
console.log(runWith(0)(inc).toString()) // Pair( 0, 1 )
console.log(evalWith(0)(inc))           // 0
console.log(execWith(0)(inc))           // 1
```

Правило выбора: получил `Pair` и дальше работаешь с ним (`fst`/`snd`/`merge`) —
`runWith`; нужен только результат — `evalWith`; нужно только итоговое
состояние — `execWith`.

## 4. Конструкторы: `of`, `get`, `put`, `modify`

Писать `State(s => Pair(...))` руками почти не нужно — есть готовые:

```js
import crocks from 'crocks'
const { State } = crocks

// State.of(5) — «вернуть значение, состояние не трогать»
console.log(State.of(5).runWith(0).toString()) // Pair( 5, 0 )
console.log(State.of(5).evalWith(0))           // 5

// State.get() — «отдать текущее состояние в значение»
console.log(State.get().evalWith(42))          // 42

// State.get(fn) — «отдать функцию от состояния»
console.log(State.get(s => s.length).evalWith('abc')) // 3

// State.put(x) — «заменить состояние целиком», значение — Unit (())
console.log(State.put(9).runWith(0).toString())       // Pair( (), 9 )

// State.modify(fn) — «преобразовать состояние», значение — Unit
console.log(State.modify(x => x * 2).runWith(3).toString()) // Pair( (), 6 )
```

Обрати внимание на `()` в первом компоненте у `put`/`modify`: crocks не
изобретает «пустое значение» — там лежит `Unit` (пустой тип-заглушка). Он нужен,
чтобы честно занять место значения.

> ⚠️ `get` и `modify` — **статические методы** класса State: `State.get()`,
> `State.get(fn)`, `State.modify(fn)`, `State.put(x)`. Отдельных pointfree-функций
> `get`/`modify` в главном экспорте crocks 0.12 **нет** (проверено: `crocks.get`
> и `crocks.modify` — `undefined`). А `runWith`/`evalWith`/`execWith` — есть.

## 5. `map` и `chain` — собираем цепочки

`map` преобразует **значение**, состояние проносится как есть:

```js
import crocks from 'crocks'
const { State, Pair } = crocks

const inc = State(s => Pair(s, s + 1))

console.log(inc.map(n => 'n=' + n).evalWith(0)) // 'n=0'
```

`chain` — главный инструмент: следующий шаг получает значение предыдущего, а
**состояние автоматически передаётся дальше**. Это и есть «нить», которую ты
раньше таскал вручную:

```js
import crocks from 'crocks'
const { State, Pair } = crocks

// каждый шаг: значение — подпись, состояние +1
const step = State(s => Pair('шаг' + (s + 1), s + 1))

const pipeline = step
  .chain(r1 => step.chain(r2 => step.map(r3 => [r1, r2, r3])))

console.log(pipeline.runWith(0).toString())
// Pair( [ "шаг1", "шаг2", "шаг3" ], 3 ) — значения собрались, счётчик = 3
```

Счётчик, который «сам» считает шаги:

```js
const count = State(s => Pair(1, s + 1))
const total = count.chain(a => count.chain(b => count.map(c => a + b + c)))

console.log(total.runWith(0).toString())
// Pair( 3, 3 ) — три шага, каждый вернул 1, состояние = 3
```

Вложенность `chain`/`map` выглядит тяжеловато — в уроке 6.1 (`pipeK`) и в
`Reader`/`ReaderT` (уроки 3.2–3.3) увидишь, как это линеаризуется.

## 6. Состояние — любая структура: стек

Состояние не обязано быть числом. Стек на массиве:

```js
import crocks from 'crocks'
const { State, Pair } = crocks

// положить в стек: значение шага не важно, состояние = новый массив
const push = x => State(st => Pair(undefined, [x].concat(st)))

// снять со стека: значение = верхушка, состояние = остаток
const pop = State(st => Pair(st[0], st.slice(1)))

const program = push(1).chain(() => push(2)).chain(() => pop)

console.log(program.runWith([]).toString())
// Pair( 2, [ 1 ] ) — сняли 2, в стеке осталось [1]
```

Здесь видно разделение ролей: `push` возвращает `undefined` (ему нечего
«отдавать»), а `pop` отдаёт значение и меняет состояние. Программа целиком —
**чистая функция от начального стека**: `runWith([])` можно вызывать сколько
угодно раз, и результат всегда один и тот же.

## 7. `ap` и почему State — «рецепт»

```js
import crocks from 'crocks'
const { State } = crocks

console.log(State.of(x => x * 2).ap(State.of(21)).evalWith(0)) // 42
```

`ap` работает как у всех аппликативов (урок 1.4): контейнер с функцией —
получатель, контейнер со значением — аргумент; состояния при этом «сшиваются»
последовательно.

Главная мысль урока: `State` — это **описание** вычисления, а не вычисление.
Ни одна строка выше ничего не выполнила, пока не появился `runWith`. Отсюда
практические бонусы:

- **тестируемость**: `program.runWith(начальное)` — чистая функция, никакого
  сброса глобального состояния между тестами;
- **переиспользуемость**: один и тот же `State` запускается с разными
  начальными состояниями;
- **композиция**: шаги склеиваются, не зная друг о друге.

## 8. Полный пример: корзина покупок

Состояние — объект; шаги меняют его, финальный шаг читает:

```js
import crocks from 'crocks'
const { State, Pair } = crocks

const addItem = (name, price) => State(st => Pair(undefined, {
  items: st.items.concat(name),
  total: st.total + price
}))

// «отдать» сводку: значение — строка, состояние не меняем
const summary = State.get(st => `${st.items.join(', ')} = ${st.total}`)

const program = addItem('яблоко', 100)
  .chain(() => addItem('хлеб', 50))
  .chain(() => summary)

const initial = { items: [], total: 0 }

console.log(program.evalWith(initial)) // 'яблоко, хлеб = 150'
console.log(program.execWith(initial)) // { items: [ 'яблоко', 'хлеб' ], total: 150 }

// запуск дважды с одним и тем же initial даёт один и тот же результат
console.log(program.evalWith(initial) === program.evalWith(initial)) // true

console.log(initial) // { items: [], total: 0 } — исходный объект НЕ мутирован
```

`initial` не меняется: `State` работает на копиях. Тот же `program` можно
прогнать с другим стартом — и это не потребует «перезапуска» ничего:

```js
console.log(program.evalWith({ items: ['сыр'], total: 300 }))
// 'сыр, яблоко, хлеб = 450'
```

## 9. Резюме урока

| Инструмент | Роль |
|---|---|
| `State(fn)`, `fn: s -> Pair(значение, состояние)` | описание вычисления с состоянием ⚠️ порядок компонентов |
| `State.of(x)` | вернуть значение, состояние не менять |
| `State.get()` / `State.get(fn)` | прочитать состояние (или функцию от него) |
| `State.put(x)` | заменить состояние целиком (значение — `Unit`) |
| `State.modify(fn)` | преобразовать состояние (значение — `Unit`) |
| `.map(f)` | преобразовать **значение**, состояние проносится |
| `.chain(f)` | следующий шаг получает значение, **состояние течёт дальше** |
| `.ap(m)` | аппликатив: состояния «сшиваются» |
| `.runWith(s)` | запуск → целый `Pair(значение, состояние)` |
| `.evalWith(s)` | запуск → только значение (`fst`) |
| `.execWith(s)` | запуск → только итоговое состояние (`snd`) |

> ⚠️ В плане курса были имена `runState` / `evalState` / `execState` — в crocks
> 0.12 их **нет** (проверено): это `runWith` / `evalWith` / `execWith`. Названия
> `runState`/`evalState`/`execState` встретишь в других библиотеках и статьях.
