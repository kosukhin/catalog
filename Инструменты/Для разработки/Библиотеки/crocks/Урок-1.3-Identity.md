# Урок 1.3 — `Identity`: простейший контейнер 🟢

> Цель: познакомиться с «обёрткой без эффекта» и через неё понять, что такое
> законы `map`/`chain` и почему они превращают рефакторинг в математику.
> Ключевые слова: `Identity`, `of`, `valueOf`, законы функтора, `identity`.
> Все примеры печатают результат в консоль и проверены на crocks 0.12.
>
> Документация: https://crocks.dev/docs/crocks/Identity.html

## 1. Зачем нужен Identity

`Maybe` кодирует «значения может не быть», `Either` — «успех или ошибка».
`Identity` — контейнер, который **ничего не кодирует**: просто держит значение.
У него нет веток: у `Maybe` их две (`Just`/`Nothing`), у `Either` — две
(`Left`/`Right`), а у `Identity` — ровно одна: «значение есть».

```js
import crocks from 'crocks'
const { Identity } = crocks

console.log(Identity(5).toString())      // Identity 5
console.log(Identity.of(5).toString())   // Identity 5 — то же самое
```

На первый взгляд — бесполезная штука. На деле у неё три роли:

1. **Эталон для законов.** У нее нет веток, чтобы «прятать» различия, поэтому
   на `Identity` проще всего увидеть, чему обязаны подчиняться `map`/`chain` (раздел 4).
2. **Тестовая «песочница».** Одна и та же функция, написанная «под контейнер»,
   работает и с `Maybe`, и с `Identity` — удобно проверять логику без веток (раздел 5).
3. **Нейтральный элемент композиции.** Обернуть значение в `Identity` — ничего
   не изменить. В комбинации с другими ADT (`ReaderT` в уроке 3.3, линзы с
   `Const` в уроке 3.4) эта «незаметность» — именно то, что нужно.

## 2. Создание и разворачивание

- `Identity(x)` или `Identity.of(x)` — обернуть (разницы нет, `of` возвращает
   то же самое);
- `.valueOf()` — точка выхода: развернуть в обычное значение.

```js
import crocks from 'crocks'
const { Identity } = crocks

console.log(Identity.of(42).valueOf()) // 42
console.log(Identity('hi').valueOf())  // 'hi'
console.log(Identity('hi').inspect())  // Identity "hi" — то же, что toString
```

> ⚠️ У `Identity` **нет** метода `run()` (он появится у `Reader`/`State` в
> уроках 3.1–3.2). Единственная точка выхода — `valueOf()`. Аналог `option()`
> у Maybe и `either()` у Either — но без функций, потому что веток нет:
> разворачивать не из чего выбирать.

## 3. `map`, `chain`, `ap` — те же правила, но всегда «успех»

Сигнатуры те же, что у Maybe/Either, но применяются **всегда** — ветки
«пусто»/«ошибка», которую можно было бы пропустить, просто нет:

```js
import crocks from 'crocks'
const { Identity } = crocks

console.log(Identity(21).map(x => x * 2).toString())
// Identity 42

console.log(Identity(5).chain(n => Identity(n + 1)).toString())
// Identity 6

// ap: контейнер с функцией применяем к контейнеру со значением
console.log(Identity(n => n * 3).ap(Identity(2)).toString())
// Identity 6 (подробнее про ap — урок 1.4)
```

Контраст с `Maybe`: там проверка на «пусто» выполняется при **создании**
контейнера (`safe`, `prop`, `getPath`), а `map` дальше ничего не проверяет.
`Identity` честно показывает это «сырое» поведение — `map` применяет функцию
к чему угодно, даже к `null` внутри:

```js
console.log(Identity.of(null).map(x => x).toString())
// Identity null — map вызван, веток для пропуска нет
```

## 4. Законы `map` — почему Identity служит эталоном

У всех контейнеров crocks `map` обязан соблюдать **два закона**. На `Identity`
их видно без посторонних эффектов:

**Закон тождества** — бессмысленное оборачивание можно убрать:
`m.map(identity) === m`

**Закон композиции** — шаги можно склеивать и разрезать как угодно:
`m.map(compose(f, g)) === m.map(g).map(f)`

```js
import crocks from 'crocks'
const { Identity, identity, compose } = crocks

const f = n => n + 1
const g = n => n * 10

// 1) map(identity) ничего не меняет
console.log(Identity(5).map(identity).valueOf() === Identity(5).valueOf())
// true

// 2) один map с композицией == два map по очереди
console.log(
  Identity(5).map(compose(f, g)).valueOf() ===
  Identity(5).map(g).map(f).valueOf()
)
// true
```

Почему это важно на практике: законы — это **гарантии для рефакторинга**.
Зная их, ты бесплатно получаешь: «лишний» `map(identity)` можно выкинуть;
два `map` подряд можно слить в один (и наоборот — разбить для читаемости);
перестановка «оборачивания» и вычисления не меняет результат. С `Maybe`/`Either`
те же законы работают и там — просто с ними нужно ещё помнить про ветки.

«Нейтральность» оборачивания — прямое следствие законов:

```js
import crocks from 'crocks'
const { Identity } = crocks

const double = n => n * 2
const inc = n => n + 1

const plain = n => inc(double(n))                          // без контейнера
const wrapped = n => Identity(n).map(double).map(inc).valueOf() // через контейнер

console.log(plain(5) === wrapped(5)) // true — оба 11
```

Обрати внимание: `identity` (функция `x => x` из crocks) — отдельный
pointfree-комбинатор, а `Identity` — контейнер. Не путай: одно — функция
«ничего не делать», другое — обёртка «ничего не менять» (комбинаторы — урок 6.1).

## 5. Обобщённый код: одна функция — любой контейнер

Ключевой практический приём с `Identity`: писать шаги пайплайна так, чтобы они
не знали, в каком контейнере работают. Тогда логику можно проверить на
`Identity` (где выполняются **все** шаги всегда) и переиспользовать на
`Maybe`/`Either` (где ветки добавятся автоматически):

```js
import crocks from 'crocks'
const { Identity, Maybe } = crocks

const double = n => n * 2
const inc = n => n + 1

// m — ЛЮБОЙ контейнер с map
const steps = m => m.map(double).map(inc)

console.log(steps(Identity(5)).valueOf())       // 11
console.log(steps(Maybe.Just(5)).option())      // 11
console.log(steps(Maybe.Nothing()).option(-1))  // -1 — шаги проскочили, дефолт
```

`steps` — чистая «трансформация», и `Identity` доказывает это: раз на нём
результат всегда `11`, значит функция не зависит от веток, и её поведение на
`Maybe` полностью предсказуемо. В таком стиле пишут библиотечные функции и
тесты к ним.

## 6. Бонус: Identity — ещё и моноид

Если внутри `Identity` лежит **моноид** (урок 5.1), то и сам `Identity`
становится моноидом: `concat` складывает содержимые:

```js
import crocks from 'crocks'
const { Identity, Sum } = crocks

console.log(Identity(Sum(1)).concat(Identity(Sum(2))).toString())
// Identity Sum 3 — значения сложились
console.log(Identity(Sum(1)).concat(Identity(Sum(2))).valueOf().toString())
// Sum 3
```

Для базового уровня достаточно запомнить: `Identity` — «прозрачная» обёртка,
она не меняет поведение того, что внутри (`map`, `chain`, `concat` — всё
работает так, будто обёртки нет). Это свойство и делает его нейтральным
элементом в композиции ADT.

> 📖 Инструменты `traverse`/`sequence` тоже есть у `Identity`, но для них нужен
> контекст списков и Applicative — разберём их в уроке 1.4 и далее.

## 7. Резюме урока

| Инструмент | Роль |
|---|---|
| `Identity(x)` / `Identity.of(x)` | обернуть значение «без эффекта» |
| `.valueOf()` | развернуть в обычное значение (точка выхода) |
| `.map(f)` / `.chain(f)` / `.ap(f)` | те же сигнатуры, применяются всегда |
| `.equals(other)` / `.inspect()` | сравнение / строка для отладки |
| законы `map` | гарантии рефакторинга: `map(id) === id`, `map(f∘g) === map(g).map(f)` |
| `identity` (pointfree) | комбинатор `x => x` — не путать с контейнером |

**Где реально используется `Identity`:** в прикладном коде — редко; в
библиотечном и обобщённом — как тестовая «песочница» и нейтральный элемент
(`ReaderT`, линзы). Даже если ты ни разу не напишешь его в своём проекте,
теперь ты понимаешь, **откуда берутся гарантии** у `map` у всех остальных ADT.
