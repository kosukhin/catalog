# Урок 1.1 — `Maybe`: обработка отсутствия значения 🟢

> Цель: научиться заменять `null`/`undefined`-проверки и `if/else` на декларативные
> цепочки с `Maybe`. Ключевые слова урока: `Just` / `Nothing`, `safe`, `option`,
> `either`, `alt`, `coalesce`, `chain`.
> Все примеры печатают результат в консоль — их можно копировать в файл и запускать.
>
> Документация: https://crocks.dev/docs/crocks/Maybe.html

## 1. Зачем нужен Maybe

`Maybe` — контейнер, который кодирует контекст «**значение может отсутствовать**».
У него ровно два варианта:

- `Maybe.Just(x)` — значение есть (успех);
- `Maybe.Nothing()` — значения нет (без ошибки, «пусто»).

Проблема обычного JS:

```js
function getCity(user) {
  if (user && user.address && user.address.city) {
    return user.address.city
  }
  return 'не указан' // вызывающий код обязан помнить об этом
}
```

Каждое обращение к вложенному полю — потенциальный `TypeError: Cannot read
property ... of undefined`. С `Maybe` мы делаем отсутствие значения **явной частью
типа результата**, и вся проверка переносится внутрь контейнера:

```js
import crocks from 'crocks'
const { getPath } = crocks

const getCity = getPath(['address', 'city']) // (obj) -> Maybe city

console.log(getCity({ address: { city: 'Москва' } }).toString())
// Just 'Москва'
console.log(getCity({ address: {} }).toString())
// Nothing — без ошибок!
console.log(getCity(null).toString())
// Nothing — даже null безопасен
```

## 2. Создание Maybe

```js
import crocks from 'crocks'
const { Maybe } = crocks

// вручную
console.log(Maybe.Just(42).toString()) // Just 42
console.log(Maybe.Nothing().toString()) // Nothing

// Maybe.of — обёртка любого значения (обязательно, не nullable!)
console.log(Maybe.of(1).toString()) // Just 1
console.log(Maybe.of(null).toString()) // Just null ← ловушка! of НЕ превращает null в Nothing
```

> ⚠️ `Maybe.of(null)` даёт `Just null`. Контейнер не «угадывает», отсутствует ли
> значение. Поэтому в crocks есть конструкторы-проверки из следующего раздела.

### `safe` — самый частый способ создания

`safe` оборачивает предикат в функцию, которая возвращает `Just` при выполнении
предиката и `Nothing` иначе:

```js
import crocks from 'crocks'
const { safe } = crocks

// (предикат) -> (значение) -> Maybe значение
const toNumber = safe(x => typeof x === 'number')

console.log(toNumber(5).toString()) // Just 5
console.log(toNumber('5').toString()) // Nothing
console.log(toNumber(null).toString()) // Nothing
```

## 3. `map` — преобразование значения внутри контейнера

```js
import crocks from 'crocks'
const { Maybe } = crocks

console.log(Maybe.Just(21).map(x => x * 2).toString())
// Just 42
console.log(Maybe.Nothing().map(x => x * 2).toString())
// Nothing — функция просто не вызывается

// ⚠️ Ловушка: map НЕ проверяет результат на null/undefined!
// «Схлопывание» в Nothing происходит только при СОЗДАНИИ контейнера:
// safe/prop/getPath сами проверяют значение на входе. Если функция внутри
// map вернула null — получится Just null (проверено на crocks 0.12):
console.log(Maybe.Just(5).map(() => null).toString())
// Just null — null надо отсекать на входе: safe(предикат) или chain(safe(предикат))
```

Классическая цепочка без единого `if`:

```js
import crocks from 'crocks'
const { getPath } = crocks

console.log(
  getPath(['user', 'profile', 'name'])({ user: { profile: { name: 'Ivan' } } })
    .map(s => s.trim())
    .map(s => s.toUpperCase())
    .map(s => s + '!')
    .toString()
)
// Just 'IVAN!'

console.log(getPath(['user', 'profile', 'name'])({}).map(s => s.trim()).toString())
// Nothing — map на Nothing всегда даёт Nothing
```

## 4. `chain` — соединение шагов, каждый из которых может «отсутствовать»

`map` не подходит, когда сама функция уже возвращает Maybe (иначе получится
`Just (Just x)` — двойная обёртка). Для этого есть `chain`: он берёт функцию
`x -> Maybe b` и «схлопывает» вложенность:

```js
import crocks from 'crocks'
const { safe, getPath } = crocks

const isEmail = safe(s => s.includes('@'))

// chain: функция возвращает Maybe, результат остаётся одинарной обёрткой
console.log(
  getPath(['user', 'email'])({ user: { email: 'ivan@mail.ru' } })
    .chain(isEmail)
    .toString()
)
// Just 'ivan@mail.ru'

console.log(
  getPath(['user', 'email'])({ user: { email: 'не-email' } })
    .chain(isEmail)
    .toString()
)
// Nothing (предикат не прошёл)
```

Правило выбора:

- шаг возвращает **обычное значение** → `map`;
- шаг возвращает **Maybe** → `chain`.

### Как выбрать `map` или `chain`: смотри на тип колбэка

Ты не угадываешь структуру возвращаемого значения — ты смотришь на **сигнатуру
функции, которую вызываешь**:

```ini
map   : (a -> b)   -> F a -> F b   — колбэк возвращает голое значение
chain : (a -> F b) -> F a -> F b   — колбэк САМ возвращает контейнер
```

`chain` существует ровно для одного: если функция уже возвращает `Maybe b`,
`map` дал бы `Maybe (Maybe b)` — двойную обёртку. `chain` = `map` + «развернуть
один слой».

Пример с двумя функциями crocks и их типами (из документации):

```js
import crocks from 'crocks'
const { Maybe, prop, getPath } = crocks

// prop        :: String -> Object -> b         — голое значение, НЕ контейнер
// getPath     :: [String] -> Object -> Maybe b — САМА возвращает Maybe

const user = { name: 'Ivan', address: { city: 'Москва' } }

// prop возвращает голое значение → map
console.log(Maybe.Just(user).map(prop('name')).toString())
// Just 'Ivan'

// getPath возвращает Maybe → chain (map дал бы двойную обёртку!)
console.log(Maybe.Just(user).chain(getPath(['address', 'city'])).toString())
// Just 'Москва'
```

Что произойдёт при ошибочном выборе:

```js
import crocks from 'crocks'
const { Maybe, getPath } = crocks

const user = { name: 'Ivan', address: { city: 'Москва' } }

console.log(Maybe.Just(user).map(getPath(['address', 'city'])).toString())
// Just (Just "Москва") — двойная обёртка. Увидел её в консоли → меняй map на chain
```

**Как узнать тип функции, не читая доку каждый раз:**

1. **Запусти и напечатай** — самый честный способ (в контексте блока выше,
   где `user` и `getPath` уже определены):

   `console.log(getPath(['address', 'city'])(user).toString())` → `Just 'Москва'`,
   значит функция возвращает Maybe и нужна `chain`.

2. **По имени в crocks**: pointfree-функции, связанные с отсутствием значения
   (`prop`, `getPath`, `safe`, `eitherToMaybe`...), чаще всего возвращают
   контейнер — их `chain`-ят. Функции-преобразователи данных (`s.toUpperCase()`,
   арифметика, форматирование) возвращают голые значения — их `map`-ят.
3. **Свои функции**: ты сам пишешь тело — значит, сам знаешь, оборачиваешь ли
   ты результат.

Кстати, `chain` подчиняется закону монады, который гарантирует: сколько бы
`chain` подряд ни было, обёртка всегда ровно одна — `Maybe (Maybe b)` не может
«просочиться» сквозь цепочку корректных `chain`-ов.

### Шпаргалка

| Колбэк | Инструмент | Почему |
|---|---|---|
| `x => x * 2`, `s => s.toUpperCase()` | `map` | возвращает голое значение |
| `prop('name')` | `map` | возвращает голое значение |
| `getPath(...)`, `safe(pred)`, любая функция `a -> Maybe b` | `chain` | сама возвращает контейнер |
| колбэк возвращает контейнер, но ты применил `map` | почти всегда баг | получится `Maybe (Maybe b)` |

### 🔀 А если значение лежит в `Either`? Смешивать типы нельзя

`chain` — не «универсальный разворачиватель»: он требует, чтобы колбэк вернул
контейнер **того же типа** (`Maybe.chain` ждёт `a -> Maybe b`, `Either.chain` —
`a -> Either e b`). Поэтому `getPath` внутрь `Either` не вставить:

```js
import crocks from 'crocks'
const { Either, getPath } = crocks
const { Right, Left } = Either

const user = { name: 'Ivan', address: { city: 'Москва' } }

try {
  Right(user).chain(getPath(['address', 'city']))
} catch (e) {
  console.log(e.message) // Either.chain: Function must return an Either
}
```

⚠️ Ловушка: на `Left` колбэк вообще не вызывается (short-circuit), поэтому
`TypeError` вылезет только на успешной ветке — баг легко пропустить (блок ниже
продолжает предыдущий, `Left`, `getPath`, `user` там уже определены):

```js
console.log(Left('нет юзера').chain(getPath(['address', 'city'])).toString())
// Left "нет юзера" — без ошибки, цепочка просто не дошла до колбэка
```

Правильный ход — **конвертировать на границе** один раз, а внутри цепочки
держать один тип (та же идея, что `ReaderT(Maybe)` в уроке 3.3):

| Задача | Приём | Результат |
|---|---|---|
| нужны оба контекста (ошибка + «пусто») | `.map(getPath(path))` | `Right (Just 'Москва')` |
| `Either` → `Maybe` (причина теряется) | `eitherToMaybe(e).chain(getPath(path))` | `Just 'Москва'` / `Nothing` |
| остаться в `Either` и сохранить причину | `chain(maybeToEither('город не указан', getPath(path)))` | `Right 'Москва'` / `Left 'город не указан'` |
| нужен голый город | `map(u => getPath(path, u).option('не указан'))` | `Right 'Москва'` / `Right 'не указан'` |

```js
import crocks from 'crocks'
const { Either, getPath, eitherToMaybe, maybeToEither } = crocks
const { Right, Left } = Either

const path = ['address', 'city']
const user = { name: 'Ivan', address: { city: 'Москва' } }

// 1) map: контейнер в контейнере — ни ошибка, ни «пусто» не теряются
console.log(Right(user).map(getPath(path)).toString())  // Right Just "Москва"
console.log(Right({}).map(getPath(path)).toString())    // Right Nothing
console.log(Left('нет юзера').map(getPath(path)).toString()) // Left "нет юзера"

// 2) Either -> Maybe: дальше обычный Maybe-конвейер
console.log(eitherToMaybe(Right(user)).chain(getPath(path)).toString())
// Just "Москва"
console.log(eitherToMaybe(Left('нет юзера')).chain(getPath(path)).toString())
// Nothing

// 3) Maybe -> Either: остаёмся в Either и получаем причину
const getCity = maybeToEither('город не указан', getPath(path)) // Object -> Either String String
console.log(Right(user).chain(getCity).toString()) // Right "Москва"
console.log(Right({}).chain(getCity).toString())   // Left "город не указан"

// 4) нужен голый город (Left при этом не трогаем)
console.log(Right({}).map(u => getPath(path, u).option('не указан')).toString())
// Right "не указан"
```

`maybeToEither` и `eitherToMaybe` — штатные «переходники» между ADT
(проверено на crocks 0.12); подробнее — урок 1.2, раздел 9. `getPath` при этом
каррирован, так что `getPath(path)(u)` и `getPath(path, u)` равнозначны.
Обратное тоже верно: `Maybe.chain` с функцией, возвращающей `Either`, даст
`TypeError: Maybe.chain: Function must return a Maybe`.

## 5. `option` и `either` — разворачивание контейнера

`option` подставляет дефолт вместо `Nothing`:

```js
import crocks from 'crocks'
const { getPath } = crocks

console.log(getPath(['address', 'city'])({ address: { city: 'Москва' } }).option('не указан'))
// 'Москва'

console.log(getPath(['address', 'city'])({}).option('не указан'))
// 'не указан'
```

`either` — точка, где Maybe «взрывается» обратно в обычный код. Получает две
функции: для `Nothing` и для `Just`:

```js
import crocks from 'crocks'
const { getPath, either } = crocks

const render = either(
  () => 'город не указан',       // ветка Nothing
  city => `город: ${city}`       // ветка Just
)

console.log(render(getPath(['address', 'city'])({ address: { city: 'Москва' } })))
// 'город: Москва'
console.log(render(getPath(['address', 'city'])({})))
// 'город не указан'
```

> Отличие: `option` подставляет одно **значение**, `either` выбирает между двумя
> **функциями** (можно логировать, форматировать, менять тип результата).

> 📖 **Термин (необязательный):** такие методы, которые разворачивают
> контейнер в обычное значение, в теории ФП называют **катаморфизмами**
> («схлопывание» структуры). Подробнее — в уроке 1.2 (раздел про `either`).

## 6. `alt` и `coalesce` — запасное значение внутри цепочки

`alt` (pointfree или метод) заменяет `Nothing` другим Maybe:

```js
import crocks from 'crocks'
const { Maybe, getPath } = crocks

const getCity = o =>
  getPath(['address', 'city'])(o)
    .alt(Maybe.Just('город не указан')) // Nothing -> Just 'город не указан'
    .option()

console.log(getCity({ address: { city: 'Москва' } })) // 'Москва'
console.log(getCity({}))                              // 'город не указан'
```

`coalesce` — то же, но принимает две функции: для Nothing и для Just
(у метода — оба аргумента в одном вызове):

```js
import crocks from 'crocks'
const { Maybe } = crocks

// метод: coalesce(fNothing, fJust)
console.log(Maybe.Nothing().coalesce(() => 0, x => x).option())    // 0
console.log(Maybe.Just(21).coalesce(() => 0, x => x * 2).option()) // 42
```

Разница с `alt`: `alt` ожидает готовый Maybe (лениво строить сложное значение не
получится), `coalesce` — функции, поэтому «дорогой» дефолт вычисляется только
при необходимости.

## 7. Замена `if/else` и null-проверок: полный пример

```js
import crocks from 'crocks'
const { Maybe, safe, prop, getPath, pipe, chain, option } = crocks

const user = {
  profile: { age: 30, email: 'ivan@mail.ru' },
  settings: { theme: 'dark' },
}

const isNumber = safe(x => typeof x === 'number')
const isPositive = x => x > 0 ? Maybe.Just(x) : Maybe.Nothing()

// императивный оригинал
function getAgeOld(u) {
  const age = u?.profile?.age
  if (typeof age !== 'number') return null
  if (age <= 0) return null
  return Math.floor(age)
}

// версия с Maybe
const getAge = pipe(
  getPath(['profile', 'age']), // Just age | Nothing
  chain(isNumber),             // проверка типа
  chain(isPositive),           // проверка значения
  chain(x => Maybe.of(Math.floor(x)))
)

console.log(getAge(user).toString())             // Just 30
console.log(getAge({}).toString())               // Nothing — нет поля
console.log(getAge({ profile: { age: -5 } }).toString()) // Nothing — отрицательный возраст

// и точка входа в «нормальный» мир:
console.log(getAge(user).option(0))              // 30
```

Обрати внимание: `prop` и `getPath` — уже Maybe-безопасные производители:
`prop('profile')(user)` даёт `Just {...}` или `Nothing`, так что их можно
просто соединять через `chain` без всяких `safe`.

```js
import crocks from 'crocks'
const { prop } = crocks

const user = { profile: { age: 30 } }

console.log(prop('profile')(user).toString()) // Just {...} — объект внутри
console.log(prop('nope')(user).toString())    // Nothing — ключа нет, без ошибок
```

## 8. Когда Maybe — не лучший выбор

`Nothing` не несёт информации о **причине**. Если нужно сообщить, почему значения
нет (код ошибки, текст), используй `Either` / `Result` — урок 1.2.

Также заметь: хелпер `maybe` из документации crocks в версии 0.12 отсутствует —
его роль выполняют `option`, `coalesce` и `either`.

## 9. Резюме урока

| Инструмент | Сигнатура / роль |
|---|---|
| `Maybe.Just(x)` / `Maybe.Nothing()` | создать контейнер «есть» / «нет» |
| `Maybe.of(x)` | обёртка значения (null превращает в `Just null` — осторожно!) |
| `safe(предикат)` | `(a) -> Maybe a` в зависимости от предиката |
| `map(f)` | преобразовать Just-значение, Nothing пропускает |
| `chain(f: a -> Maybe b)` | соединить шаги, каждый из которых может отсутствовать |
| `option(дефолт)` | развернуть: значение или дефолт |
| `either(fNothing, fJust)` | развернуть в две ветки кода |
| `alt(другойMaybe)` | запасной Maybe вместо Nothing |
| `coalesce(fNothing, fJust)` | две функции вместо Nothing/Just |
| `prop`, `getPath`, `find` | готовые Maybe-производители из crocks |
