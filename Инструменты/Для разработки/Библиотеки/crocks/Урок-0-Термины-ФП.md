# Урок 0 — Термины ФП: функтор, аппликатив, монада 🟢

> Цель: раз и навсегда разложить три слова, на которых держится вся библиотека
> crocks. После урока ты будешь определять их не по названию типа, а по одной
> операции: `map` → функтор, `ap` → аппликатив, `chain` → монада.
> Ключевые слова: контейнер, `of`, `map`, `ap`, `chain`, законы.
> Все примеры печатают результат в консоль и проверены на crocks 0.12.
>
> Документация: https://crocks.dev/docs/getting-started.html
> Спецификация интерфейсов: https://github.com/fantasyland/fantasy-land
>
> 📦 **Каждый блок в уроке самодостаточен.** Импорты и все определения уже
> включены: скопируй блок в файл `.mjs` в проекте с установленным `crocks`
> (`npm install crocks`, если его ещё нет) и запусти `node файл.mjs`.

## 1. Контейнер и `of` — кирпич, из которого всё собрано

**Контейнер** — это значение, «завёрнутое» вместе с контекстом: `Maybe`
добавляет контекст «значение может отсутствовать», `Either` — «может быть
ошибка», `Async` — «вычисление асинхронное». Контейнер не даёт работать со
значением напрямую — только через свои операции. Именно поэтому `Maybe` — не
`null`, а `Either` — не `throw`.

Первая операция, с которой начинается почти любой контейнер, — `of` (в Haskell
её зовут `return`, в спецификации Fantasy Land — `of`, в других библиотеках —
`pure`). Она превращает обычное значение в контейнер:

```js
import crocks from 'crocks'
const { Maybe, Either, Result } = crocks

console.log(Maybe.of(42).toString())   // Just 42
console.log(Either.of(42).toString())  // Right 42
console.log(Result.of(42).toString())  // Ok 42

// of не проверяет значение — он кладёт его в МИНИМАЛЬНЫЙ контекст
console.log(Maybe.of(null).toString()) // Just null — ловушка из урока 1.1

// pointfree-функции `of` в crocks 0.12 нет:
console.log(typeof crocks.of)          // 'undefined'
```

Смысл `of`: завернуть готовое значение, ничего не вычисляя. Это «точка входа»
в контейнер и одновременно — единица измерения для законов ниже.

> 📖 У `of` есть важное свойство: он не смотрит на значение. `Maybe.of(null)` —
> это `Just null`, а не `Nothing`; `Either.of(null)` — `Right null`. Если нужно
> «отсутствие» или «ошибка», нужен не `of`, а `safe`/`Nothing`/`Left`.
>
> `of` есть у `Maybe`, `Either`, `Result`, `Identity`, `Async`, `Reader`,
> `State`. Но не у всех контейнеров: например, у `Pair` и `Tuple` его нет
> (см. раздел 5) — и тогда строгое определение аппликатива/монады к ним не
> применяется, хотя отдельные операции (`map`, `ap`) могут работать.

## 2. Функтор — тот, кто умеет `map`

**Функтор** — это тип-контейнер, для которого определена операция

```html
map :: (a -> b) -> f a -> f b
```

То есть `map` применяет **обычную** функцию `a -> b` к значению внутри
контейнера и возвращает контейнер **той же формы**.

```js
import crocks from 'crocks'
const { Maybe, Either, Pair } = crocks
const { Just, Nothing } = Maybe
const { Left, Right } = Either

const toUpper = s => s.toUpperCase()

console.log(Just('ivan').map(toUpper).toString())   // Just "IVAN"
console.log(Nothing().map(toUpper).toString())      // Nothing — контекст сохранён
console.log(Right('ivan').map(toUpper).toString())  // Right "IVAN"
console.log(Left('err').map(toUpper).toString())    // Left "err" — ошибку map не трогает
console.log(Pair('log', 2).map(n => n * 10).toString())
// Pair( "log", 20 ) — первый компонент (контекст) не тронут
```

Что важно:

- `map` **не меняет форму контекста**: `Nothing` остаётся `Nothing`, `Left`
   остаётся `Left`;
- `map` не умеет «выйти» из контейнера — на выходе всегда контейнер;
- у `Pair` (урок 2.1) `map` трогает только **второй** компонент: первый — это
   накапливаемый контекст, его нельзя потерять;
- `Tuple` (урок 2.2) тоже функтор — `map` меняет последний компонент.

### Два закона функтора

Законы — это не бюрократия, а **гарантии для рефакторинга**: по ним можно
переписывать код, не меняя поведение.

1. **Тождество:** `m.map(identity) ≡ m` — бесполезный `map` можно убрать.
2. **Композиция:** `m.map(compose(f, g)) ≡ m.map(g).map(f)` — два `map` можно
   слить в один (и наоборот — разбить длинную функцию на читаемые шаги).

```js
import crocks from 'crocks'
const { Maybe, identity, compose } = crocks
const { Just } = Maybe

const f = n => n + 1
const g = n => n * 10
const m = Just(5)

console.log(m.map(identity).equals(m))
// true — тождество

console.log(m.map(compose(f, g)).equals(m.map(g).map(f)))
// true — композиция: f(g(x)) == x -> g -> f
```

> ⚠️ **Функтор — это не «коллекция».** `map` у `Maybe` не перебирает значения
> и не «делает что-то для каждого»: значение ровно одно. Функтор — про
> **сохранение формы**, а не про количество элементов.

### Чего `map` не умеет

Если функция сама возвращает контейнер, `map` не «сплющит» его — получится
вложенность:

```js
import crocks from 'crocks'
const { Maybe } = crocks
const { Just } = Maybe

console.log(Just(5).map(x => Just(x + 1)).toString())   // Just Just 6
console.log(Just(5).chain(x => Just(x + 1)).toString()) // Just 6
```

`chain` — операция следующего уровня, монады. О ней в разделе 4.

## 3. Аппликатив — тот, кто умеет `of` + `ap`

**Аппликатив** — это функтор, у которого есть `of` и операция

```html
ap :: f (a -> b) -> f a -> f b
```

Отличие от `map` в одном: функция тоже лежит **в контейнере**. Зачем это нужно?
Чтобы комбинировать **независимые** контейнеры, когда значения известны
заранее и не зависят друг от друга.

```js
import crocks from 'crocks'
const { Maybe, curry, liftA2, ap } = crocks
const { Just, Nothing } = Maybe

const add = curry((a, b) => a + b)

// ap: контейнер с функцией .ap(контейнер со значением)
console.log(Maybe.of(add(10)).ap(Just(5)).toString())   // Just 15
console.log(Maybe.of(add(10)).ap(Nothing()).toString()) // Nothing

// liftA2 делает то же самое, но читается как обычный вызов функции
console.log(liftA2(add, Just(10), Just(5)).toString())   // Just 15
console.log(liftA2(add, Just(10), Nothing()).toString()) // Nothing

// pointfree-версия: порядок аргументов ОБРАТНЫЙ методу
console.log(ap(Just(5))(Maybe.of(add(10))).toString())   // Just 15
```

⚠️ **Две ловушки `ap`.**

1. Порядок: метод — `контейнерСФункцией.ap(контейнерСоЗначением)`, а
   pointfree — `ap(контейнерСоЗначением)(контейнерСФункцией)`.
2. `liftA2` требует **каррированную** функцию: внутри он делает
   `m1.map(fn).ap(m2)`, и после `map` в контейнере должна остаться функция,
   ждущая второй аргумент.

Проверим обе ошибки (обёрнуты в `try/catch`, чтобы блок доработал до конца):

```js
import crocks from 'crocks'
const { Maybe, liftA2 } = crocks
const { Just } = Maybe

try {
  Maybe.of(x => x).ap(5)
} catch (e) {
  console.log(e.name + ': ' + e.message)
  // TypeError: Maybe.ap: Maybe required
}

try {
  liftA2((a, b) => a + b, Just(1), Just(2))
} catch (e) {
  console.log(e.name + ': ' + e.message)
  // TypeError: Maybe.ap: Wrapped value must be a function
}
```

### Аппликатив комбинирует, а не «продолжает»

Ключевое отличие от монады: в `ap`/`liftA2` **второе вычисление не может
зависеть от результата первого**. Зато именно поэтому аппликатив умеет
накапливать независимые ошибки:

```js
import crocks from 'crocks'
const { Result, curry, liftA2 } = crocks
const { Ok, Err } = Result

const add = curry((a, b) => a + b)

const isPositive = n => n > 0 ? Ok(n) : Err(['должно быть > 0'])
const isEven = n => n % 2 === 0 ? Ok(n) : Err(['должно быть чётным'])

console.log(liftA2(add, isPositive(-2), isEven(3)).toString())
// Err [ "должно быть > 0", "должно быть чётным" ] — обе ошибки

console.log(liftA2(add, isPositive(2), isEven(3)).toString())
// Err [ "должно быть чётным" ]

console.log(liftA2(add, isPositive(2), isEven(4)).toString())
// Ok 6
```

> 📖 Накопление ошибок — свойство `Result.ap` (урок 1.2), а не аппликатива
> «вообще». У `Either.ap` две ошибки не складываются: `Either.of(add)
> .ap(Left('a')).ap(Left('b'))` даёт `Left "a"`. Хочешь собрать все ошибки —
> бери `Result` со списком/массивом в `Err`.

### Четыре закона аппликатива

Записаны в порядке методов crocks (получатель — контейнер с функцией):

| Закон | Формула |
|---|---|
| Тождество | `of(identity).ap(v) ≡ v` |
| Гомоморфизм | `of(f).ap(of(x)) ≡ of(f(x))` |
| Перестановка | `u.ap(of(x)) ≡ of(fn => fn(x)).ap(u)` |
| Композиция | `of(f => g => x => f(g(x))).ap(u).ap(v).ap(w) ≡ u.ap(v.ap(w))` |

```js
import crocks from 'crocks'
const { Maybe, identity } = crocks
const { Just } = Maybe

const v = Just(5)
const u = Just(n => n * 2)
const f = n => n + 1
const g = n => n * 10
const compose3 = f => g => x => f(g(x))

console.log(Maybe.of(identity).ap(v).equals(v))                 // true
console.log(Maybe.of(f).ap(Just(5)).equals(Just(f(5))))        // true
console.log(u.ap(Just(5)).equals(Maybe.of(fn => fn(5)).ap(u))) // true
console.log(
  Maybe.of(compose3).ap(u).ap(Just(g)).ap(v)
    .equals(u.ap(Just(g).ap(v)))
)                                                              // true
```

## 4. Монада — тот, кто умеет `of` + `chain`

**Монада** — это аппликатив, у которого есть операция

```html
chain :: (a -> m b) -> m a -> m b
```

`chain` (он же `bind`, он же `flatMap` в других библиотеках) нужен, когда
**следующий шаг зависит от значения** и сам возвращает контейнер. `chain`
применяет функцию и «сплющивает» один слой — поэтому вложенности не возникает:

```js
import crocks from 'crocks'
const { Maybe } = crocks
const { Just, Nothing } = Maybe

// шаг зависит от значения и сам возвращает Maybe
const half = n => n % 2 === 0 ? Just(n / 2) : Nothing()
const addTen = n => Just(n + 10)

console.log(Just(8).chain(half).toString())   // Just 4
console.log(Just(7).chain(half).toString())   // Nothing — нечётное
console.log(Nothing().chain(half).toString()) // Nothing — сбой не «продолжается»
console.log(Just(4).chain(half).chain(addTen).toString()) // Just 12
```

Почему здесь нельзя обойтись `map`:

```js
import crocks from 'crocks'
const { Maybe } = crocks
const { Just, Nothing } = Maybe

// half — тот же шаг, что и в примере выше
const half = n => n % 2 === 0 ? Just(n / 2) : Nothing()

console.log(Just(4).map(half).toString())   // Just Just 2 — лишний слой
console.log(Just(4).chain(half).toString()) // Just 2
```

`chain` — тот самый «протыкатель» двух слоёв из уроков 1.1–1.2. У `Reader`
(урок 3.2) он проносит окружение, у `State` (урок 3.1) — состояние, у `Async`
(урок 4.1) — выстраивает последовательность асинхронных шагов.

### Три закона монады

1. **Левая идентичность:** `of(a).chain(f) ≡ f(a)`
2. **Правая идентичность:** `m.chain(of) ≡ m`
3. **Ассоциативность:** `m.chain(f).chain(g) ≡ m.chain(x => f(x).chain(g))`

```js
import crocks from 'crocks'
const { Maybe } = crocks
const { Just, Nothing } = Maybe

const f = n => n > 0 ? Just(n * 2) : Nothing()
const g = n => n < 100 ? Just(n + 1) : Nothing()
const m = Just(7)

console.log(Just(7).chain(f).equals(f(7)))                           // true
console.log(m.chain(Just).equals(m))                                 // true
console.log(m.chain(f).chain(g).equals(m.chain(x => f(x).chain(g)))) // true
```

Что это даёт на практике:

- **левая** — `of` нейтрален на входе: обернуть и сразу `chain` — то же самое,
   что просто вызвать функцию;
- **правая** — `chain(of)` ничего не меняет: `of` нейтрален и на выходе;
- **ассоциативность** — цепочку `chain` можно группировать как угодно:
   `a.chain(f).chain(g)` и `a.chain(x => f(x).chain(g))` эквивалентны. Именно
   поэтому длинные цепочки можно разбивать на функции и склеивать обратно.

⚠️ `chain` ждёт функцию, которая возвращает **контейнер**, а не голое значение:

Проверим (в `try/catch`, чтобы увидеть сообщение):

```js
import crocks from 'crocks'
const { Maybe } = crocks
const { Just } = Maybe

try {
  Just(5).chain(x => x + 1)
} catch (e) {
  console.log(e.name + ': ' + e.message)
  // TypeError: Maybe.chain: Function must return a Maybe
}
```

Для обычных преобразований — `map`; для шагов, возвращающих контейнер, —
`chain`. Правило выбора подробно разобрано в уроке 1.1.

### `ap` или `chain`: что выбрать

| | `ap` / `liftA2` | `chain` |
|---|---|---|
| Зависимость шагов | **независимые** | каждый следующий зависит от предыдущего |
| Что делает шаг | функция уже лежит в контейнере | функция `a -> m b` |
| Ошибки | могут копиться (`Result`) | короткое замыкание на первой |
| Пример | проверить два поля формы | найти пользователя, затем его заказы |

## 5. Иерархия и проверка в crocks

Три интерфейса вложены друг в друга — каждый следующий добавляет операцию и
сохраняет законы предыдущего:

```sh
Functor       map
Applicative   map + of + ap
Monad         map + of + ap + chain
```

**Монада — это не конкретный тип, а интерфейс.** `Maybe`, `Either`, `Result`,
`Identity`, `Async`, `Reader`, `State` — все они монады, потому что у них есть
`of` и `chain`. При этом `Tuple` — только функтор, а `Sum` — вообще моноид
(урок 5), а не функтор.

Проверить интерфейс можно предикатами crocks:

```js
import crocks from 'crocks'
const {
  Maybe, Pair, Tuple, Sum,
  isFunctor, isApply, isApplicative, isChain, isMonad
} = crocks

console.log(isFunctor(Maybe.of(1)))     // true
console.log(isApply(Maybe.of(1)))       // true
console.log(isApplicative(Maybe.of(1))) // true
console.log(isChain(Maybe.of(1)))       // true
console.log(isMonad(Maybe.of(1)))       // true

console.log(isMonad(Pair(['log'], 1)))  // false — у Pair нет `of`
console.log(isFunctor(Tuple(2, 1, 2)))  // true — только map
console.log(isFunctor(Sum(1)))          // false — это моноид (урок 5)
```

Предикаты в crocks 0.12 устроены ровно по определениям выше (проверено по
исходникам):

| Предикат | Что проверяет |
|---|---|
| `isFunctor` | есть `map` |
| `isApply` | `isFunctor` + есть `ap` |
| `isApplicative` | `isApply` + есть `of` |
| `isChain` | `isApply` + есть `chain` |
| `isMonad` | `isApplicative` + есть `chain` |

| Тип | `map` | `of` | `ap` | `chain` | Кто он |
|---|---|---|---|---|---|
| `Maybe`, `Either`, `Result`, `Identity`, `Async`, `Reader`, `State` | ✔ | ✔ | ✔ | ✔ | функтор + аппликатив + монада |
| `Pair` | ✔ | ✘ | ✔ | ✔ | функтор + apply/chain, но без `of` |
| `Tuple` | ✔ | ✘ | ✘ | ✘ | только функтор |
| `Pred` | ✘ | ✘ | ✘ | ✘ | contravariant: есть `contramap`, нет `map` |
| `Sum`, `All` | ✘ | ✘ | ✘ | ✘ | моноид (урок 5) |

> 📖 Про `Pair` есть тонкость. В уроке 2.1 он назван аппликативом по
> **операциям** (`ap` и `chain` работают и складывают контексты). Но предикат
> `isApplicative` в crocks дополнительно требует `of`, а у `Pair` его нет.
> Поэтому `isApplicative(Pair(...))` и `isMonad(Pair(...))` возвращают `false`.
> Это не противоречие: определение через операции и проверка библиотеки чуть
> расходятся в строгости.

## 6. Три операции на одном примере

Форма с двумя **независимыми** полями и одним **зависимым** шагом:

```js
import crocks from 'crocks'
const { Result, curry, liftA2 } = crocks
const { Ok, Err } = Result

// вход: значение -> Result
const validateName = v => v.trim() ? Ok(v.trim()) : Err(['имя пустое'])
const validateAge = v => v >= 18 ? Ok(v) : Err(['нужен 18+'])

// map: преобразовать значение ВНУТРИ Result (форма контекста не меняется)
const normalizeName = v =>
  validateName(v).map(s => s[0].toUpperCase() + s.slice(1))

const makeUser = curry((name, age) => ({ name, age }))

// ap / liftA2: скомбинировать НЕЗАВИСИМЫЕ проверки
const form = liftA2(makeUser, normalizeName('  Ivan  '), validateAge(17))
console.log(form.toString())
// Err [ "нужен 18+" ] — имя проверено и нормализовано, возраст не прошёл

// обе проверки независимы — ошибки накапливаются
console.log(liftA2(makeUser, normalizeName('   '), validateAge(17)).toString())
// Err [ "имя пустое", "нужен 18+" ]

// chain: следующий шаг ЗАВИСИТ от результата проверки
const load = user =>
  user.name === 'Ivan' ? Ok({ ...user, id: 1 }) : Err(['нет такого'])

console.log(form.chain(load).toString())
// Err [ "нужен 18+" ] — load даже не вызвался

console.log(
  liftA2(makeUser, normalizeName('  Ivan  '), validateAge(21))
    .chain(load)
    .toString()
)
// Ok { name: "Ivan", age: 21, id: 1 }
```

Разбор по операциям:

- **`map`** изменил имя, но не тронул `Ok`/`Err` — контекст сохранён;
- **`liftA2`** объединил два независимых результата в один объект и собрал
   обе ошибки;
- **`chain`** выполнил загрузку только после успешной валидации, потому что
   `load` зависит от `user`.

## 7. Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `Just Just 6` | `map` получил функцию, возвращающую контейнер | `chain` |
| `TypeError: Maybe.chain: Function must return a Maybe` | в `chain` передали функцию с голым значением | `map` |
| `TypeError: Maybe.ap: Maybe required` | в `ap` передали не контейнер | обернуть значение через `of` |
| `TypeError: Maybe.ap: Wrapped value must be a function` | `liftA2` без `curry` | `curry(fn)` |
| `Left "a"` вместо двух ошибок | `Either.ap` не накапливает | `Result` с массивом в `Err` |
| `Just null` вместо `Nothing` | поверили, что `of` проверяет значение | `safe`, `Nothing`, `Left` |

## 8. Резюме урока

| Термин | Операция | На какой вопрос отвечает | Законов | Примеры в crocks |
|---|---|---|---|---|
| **Функтор** | `map` | «преобразовать значение, сохранив контекст» | 2 | `Maybe`, `Either`, `Pair`, `Tuple` |
| **Аппликатив** | `of` + `ap` | «скомбинировать независимые контексты» | 4 | `Maybe`, `Either`, `Result`, `Async` |
| **Монада** | `of` + `chain` | «связать зависимые шаги» | 3 | `Maybe`, `Either`, `Reader`, `State`, `Async` |

Одной строкой:

```ini
функтор    = map
аппликатив = map + of + ap
монада     = map + of + ap + chain
```

И главное: **это интерфейсы, а не классы типов.** Один и тот же `Maybe` —
и функтор, и аппликатив, и монада одновременно, потому что у него есть все три
операции и он соблюдает все законы.
