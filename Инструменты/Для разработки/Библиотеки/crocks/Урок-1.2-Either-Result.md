# Урок 1.2 — `Either` и `Result`: ошибки как значения 🟢

> Цель: научиться работать с вычислениями, которые могут **упасть с ошибкой**,
> без `try/catch` и `throw`. Ключевые слова: `Left` / `Right`, `Err` / `Ok`,
> `tryCatch`, `bimap`, `bichain`, `swap`, `either`.
> Все примеры печатают результат в консоль и проверены на crocks 0.12.
>
> Документация: https://crocks.dev/docs/crocks/Either.html

## 1. Зачем нужен Either

`Maybe` из урока 1.1 умеет сказать «значения нет», но не умеет сказать **почему**.
`Either` кодирует контекст «**успех или ошибка с описанием**». У него два варианта:

- `Either.Right(x)` — успех (правильный путь);
- `Either.Left(e)` — ошибка (обычно в `e` кладут `Error`, строку или код).

`Result` — то же самое с «Result-именованием»: `Ok` / `Err`. Выбирай тот, который
больше нравится по стилю; в crocks это два отдельных ADT с идентичным поведением.

```js
import crocks from 'crocks'
const { Either, Result } = crocks
const { Left, Right } = Either
const { Ok, Err } = Result

console.log(Right(2).toString())            // Right 2 — успех
console.log(Left('нет доступа').toString()) // Left 'нет доступа' — ошибка
console.log(Ok(2).toString())               // Ok 2
console.log(Err('нет доступа').toString())  // Err 'нет доступа'
```

## 2. Правило работы с ветками: все преобразования идут только по «успеху»

Как и `map` в `Maybe` (который не трогает `Nothing`), здесь `map`/`chain`
работают только с `Right`/`Ok`. Ветка ошибки «пропускается» без изменений —
ошибка протекает по цепочке до самого конца:

```js
import crocks from 'crocks'
const { Either } = crocks
const { Left, Right } = Either

console.log(Right(2).map(x => x * 2).toString())
// Right 4 — функция применилась

console.log(Left('err').map(x => x * 2).toString())
// Left 'err' — map НЕ трогает ошибку

console.log(Right(2).chain(x => Right(x + 1)).toString())
// Right 3

console.log(Left('err').chain(x => Right(x + 1)).toString())
// Left 'err' — ошибка «протекла» насквозь
```

Это значит: длинная цепочка из 10 шагов прервётся на первом же `Left`, и тебе
не нужно проверять успех после каждого шага.

## 3. `tryCatch` — превращаем исключения в Either/Result

`tryCatch` оборачивает функцию, которая может `throw`, в функцию, которая
возвращает `Ok` / `Right` при успехе и `Err` / `Left` с объектом ошибки при падении:

```js
import crocks from 'crocks'
const { tryCatch } = crocks

// нативные функции оборачиваем в обычную (стрелку) — с ними curry работает надёжнее
const parseJSON = tryCatch(s => JSON.parse(s))

const good = parseJSON('{"a":1}')
const bad = parseJSON('{bad json')

console.log(good.toString())
// Ok { a: 1 } — валидный JSON → Ok

console.log(bad.toString())
// Err SyntaxError: Expected property name or '}' in JSON at position 1 ...
// исключение поймано и стало значением

console.log(good.either(e => 'ERR', v => 'OK: ' + JSON.stringify(v)))
// OK: {"a":1}

console.log(bad.either(e => 'ERR: ' + e.message, v => 'OK'))
// ERR: Expected property name or '}' in JSON at position 1 (line 1 column 2)
```

`safe` из урока 1.1 работает с **предикатами** (значение есть/нет),
`tryCatch` — с **функциями, кидающими исключения**. Это разные способы
«войти» в Either-мир.

---

## 4. `bimap` — обработка обеих веток одним вызовом

`map` трогает только успех. `bimap` принимает две функции: для ошибки и для успеха:

```js
import crocks from 'crocks'
const { Either } = crocks
const { Left, Right } = Either

console.log(Right(2).bimap(e => 'E: ' + e, x => x * 10).toString())
// Right 20 — сработала правая функция

console.log(Left('oops').bimap(e => 'E: ' + e, x => x * 10).toString())
// Left 'E:oops' — сработала левая функция
```

---

## 5. `bichain` — восстановление после ошибки внутри цепочки

`bichain` — «монадический bimap»: две функции, обе возвращают Either. Позволяет
перехватить ошибку и продолжить цепочку:

```js
import crocks from 'crocks'
const { Either } = crocks
const { Left, Right } = Either

// ошибка → восстановление
console.log(Left('oops').bichain(
  l => Right('восстановились: ' + l),
  r => Right(r)
).toString())
// Right 'восстановились: oops'

// успех проходит через правую функцию
console.log(Right(5).bichain(
  l => Right(l),
  r => Right(r * 2)
).toString())
// Right 10
```

## 6. `either` — разворачивание в обычный код

Точка выхода из Either-мира, по аналогии с `option` у Maybe. Две функции:
для ошибки и для успеха:

```js
import crocks from 'crocks'
const { Either, either } = crocks
const { Left, Right } = Either

// метод
console.log(Right(42).either(e => 'ошибка', v => 'ок: ' + v))  // ок: 42
console.log(Left('timeout').either(e => 'ошибка: ' + e, v => 'ок')) // ошибка: timeout

// pointfree-версия: (fLeft, fRight) -> m -> значение
const show = either(e => 'ошибка: ' + e, v => 'успех: ' + v)
console.log(show(Right(7)))     // успех: 7
console.log(show(Left('nope'))) // ошибка: nope
```

> 📖 **Термин (необязательный):** такие «разворачивающие» методы в теории ФП
> называют **катаморфизмом** (греч. «вниз» + «форма»: свёрнутая структура
> «схлопывается» в обычное значение). Ты описываешь, что вернуть для каждого
> варианта структуры — здесь для `Left` и `Right`. Катаморфизмы в crocks —
> это `option`, `either`, `coalesce`, а у `Async` (урок 4.1) — `fork`.
> Признак: колбэки могут вернуть **что угодно** (строку, число, объект), и
> после вызова контейнера больше нет. Противоположность — упаковка обычного
> значения в контейнер (`safe`, `tryCatch`, `maybeToEither`) — это
> анаморфизм. На практике достаточно помнить «точка выхода из контейнера»,
> слово пригодится лишь при чтении статей по ФП.

## 7. `swap` — поменять ветки местами

Иногда нужно превратить «успех» в «ошибку» и наоборот (обе функции обязательны):

```js
import crocks from 'crocks'
const { Either } = crocks
const { Left, Right } = Either

console.log(Right(1).swap(x => 'L' + x, x => 'R' + x).toString())
// Left 'R1' — Right стал Left, применена правая функция

console.log(Left('a').swap(x => 'L' + x, x => 'R' + x).toString())
// Right 'La' — Left стал Right, применена левая функция
```

## 8. Полный пример: цепочка валидации с понятной ошибкой

Ключевое отличие от Maybe: на каждом шаге мы можем сказать, **что именно** не так.

```js
import crocks from 'crocks'
const { Either, tryCatch, resultToEither, pipe, chain } = crocks
const { Left, Right } = Either

// tryCatch возвращает Result (Ok/Err) — приводим к Either через resultToEither
const parseJSON = s => resultToEither(tryCatch(s => JSON.parse(s))(s))
const isObject = obj =>
  obj !== null && typeof obj === 'object' ? Right(obj) : Left('получен не объект')

// шаги, каждый из которых может стать ошибкой с причиной
const ensureUser = obj =>
  obj && typeof obj.name === 'string' && obj.name.length > 0
    ? Right(obj)
    : Left('поле name отсутствует или пусто')

const ensureAge = obj =>
  typeof obj.age === 'number' && obj.age > 0
    ? Right(obj)
    : Left('возраст должен быть положительным числом')

const getAge = pipe(
  parseJSON,        // Right obj | Left SyntaxError
  chain(isObject),  // проверка типа
  chain(ensureUser),
  chain(ensureAge),
  chain(obj => Right(obj.age))
)

console.log(getAge('{"name":"Ivan","age":30}').toString())
// Right 30

console.log(
  getAge('{bad json').either(
    e => 'не удалось разобрать JSON: ' + e.message,
    age => 'возраст: ' + age
  )
)
// не удалось разобрать JSON: Expected property name or '}' ...

console.log(
  getAge('{"name":"","age":30}').either(
    e => 'ошибка валидации: ' + e,
    age => 'возраст: ' + age
  )
)
// ошибка валидации: поле name отсутствует или пусто

console.log(getAge('{"name":"Ivan","age":-5}').toString())
// Left 'возраст должен быть положительным числом'
```

> ⚠️ Важно: `tryCatch` возвращает **Result** (`Ok`/`Err`), а `Either`-функции
> (`Right`/`Left`) дают другой тип. В одной цепочке `chain` можно соединять
> только шаги, возвращающие один и тот же тип — поэтому `tryCatch` сразу
> приводим через `resultToEither` (трансформации между ADT — раздел 9 и урок 6.4).

🔧 **Замечание к стилю:** `isObject`, `ensureUser`, `ensureAge` выше — это не
предикаты, а **валидаторы**: предикат + причина отказа. И то, и другое —
чистые функции (`Right`/`Left` — обычные значения, как `true`/`false`),
разница в переиспользовании: предикат — универсальная деталь (его берут
`safe`, `filter`, комбинируют `and`/`or`/`not` из logic), валидатор —
доменная (несёт сообщение и встраивается в `chain`, которому нужен именно
`a -> Either b`). Для простых проверок валидатор лучше не писать руками,
а собирать из деталей:

```js
const { isObject, safe, maybeToEither, pipe } = crocks

// предикат → Maybe (safe) → Either с причиной (maybeToEither)
const ensure = (pred, msg) => pipe(safe(pred), maybeToEither(msg))
const ensureObject = ensure(isObject, 'получен не объект')
```

Нюанс: crocks уже экспортирует свой предикат `isObject` (модуль
`crocks/predicates`) — наши функции выше названы так для краткости, но в
реальном коде лучше брать готовый предикат и/или не затенять его имя.
Явную функцию с `Right`/`Left` оправданно писать, когда логика зависит от
значения: несколько разных сообщений, проверка полей объекта (`ensureUser`).

Сравни с Maybe-версией из урока 1.1: там ответом на любую проблему был просто
`Nothing`. Здесь каждый шаг несёт осмысленную причину — это критично для API,
валидации форм, CLI-утилит.

## 9. Чем Either отличается от Maybe

| | Maybe | Either |
|---|---|---|
| Ветка «пусто» | `Nothing` (без данных) | `Left(e)` — с причиной |
| Разворачивание | `option(дефолт)` | `either(fLeft, fRight)` |
| «Схлопнуть» ошибку в отсутствие | — | `eitherToMaybe` |
| «Из отсутствия сделать ошибку» | — | `maybeToEither` |

Переходы между типами, когда одна цепочка мешает другой:

```js
import crocks from 'crocks'
const { eitherToMaybe, maybeToEither, Maybe, Either } = crocks
const { Left, Right } = Either

// Either -> Maybe: ошибка теряется, становится Nothing
console.log(eitherToMaybe(Left('x')).toString())  // Nothing
console.log(eitherToMaybe(Right(7)).toString())   // Just 7

// Maybe -> Either: нужно указать, чем «заменить» Nothing
console.log(maybeToEither('значения не было', Maybe.Nothing()).toString())
// Left 'значения не было'
console.log(maybeToEither('значения не было', Maybe.Just(3)).toString())
// Right 3
```

**Правило выбора:** отсутствие значения «нормально» по бизнес-логике (например,
«пользователь пока не заполнил поле») → `Maybe`. Отсутствие/неверность — это
**проблема**, о которой нужно сообщить → `Either`.

## 10. Резюме урока

| Инструмент | Роль |
|---|---|
| `Right(x)` / `Left(e)` (`Ok` / `Err`) | создать «успех» / «ошибку с причиной» |
| `map`, `chain` | работают только по ветке успеха |
| `tryCatch(fn)` | исключения → значения (`Ok`/`Err`) |
| `bimap(fL, fR)` | преобразовать обе ветки |
| `bichain(fL, fR)` | перехват и восстановление после ошибки |
| `either(fL, fR)` | развернуть в обычный код |
| `swap(fL, fR)` | поменять ветки местами |
| `eitherToMaybe`, `maybeToEither` | переходы между ADT |
