# Урок 1.4 — Ключевые методы-функции 🟢

> Цель: научиться работать с контейнерами **без методов** — через pointfree-функции
> `map`, `chain`, `ap`; комбинировать несколько контейнеров одной функцией
> (`liftA2`/`liftA3`/`liftN`) и собирать конвейеры «вход-выход» (`safe`, `option`,
> `either`, `curry`). Термины урока: Functor, Monad, Applicative.
> Все примеры печатают результат в консоль и проверены на crocks 0.12.
>
> Документация: https://crocks.dev/docs/functions/helpers.html

## 1. Методы vs функции: зачем обе версии

До сих пор мы вызывали методы: `m.map(f)`, `m.chain(f)`. У каждого метода есть
pointfree-близнец: `map(f)(m)`. Все такие функции **каррированы** и ставят
контейнер в конец — «сначала настройка, потом данные». Это позволяет строить
конвейеры через `pipe`/`compose` (урок 0.1) и переиспользовать шаги:

```js
import crocks from 'crocks'
const { Maybe, map, option } = crocks

console.log(Maybe.Just('hi').map(s => s.toUpperCase()).option(''))
// 'HI' — метод

console.log(map(s => s.toUpperCase())(Maybe.Just('hi')).option(''))
// 'HI' — то же самое pointfree: (функция) -> (контейнер)
```

Практическое правило: в цепочке методов удобнее методы; внутри `pipe`/`compose`
и при комбинировании — pointfree-функции.

---

## 2. Три термина: Functor, Monad, Applicative

Это не «типы из Haskell», а просто **интерфейсы контейнеров** — какими
операциями контейнер обладает:

| Термин | Операция | Смысл | Где уже встречал |
|---|---|---|---|
| Functor | `map(f)` | «преобразовать значение внутри» | уроки 1.1–1.3 |
| Monad | `chain(f)` | «соединить шаги, каждый возвращает такой же контейнер» | уроки 1.1–1.2 |
| Applicative | `ap(f)` / `liftA2` | «применить функцию из контейнера», «комбинировать несколько контейнеров» | этот урок |

Ключевое отличие `chain` от `ap`/`liftA2`: `chain` — **последовательные** шаги
(следующий зависит от предыдущего), `liftA2` — **параллельные** (значения
известны независимо друг от друга).

---

## 3. `map` и `chain` как функции

Сигнатуры: `map :: (a -> b) -> m a -> m b`, `chain :: (a -> m b) -> m a -> m b`.

```js
import crocks from 'crocks'
const { Maybe, map, chain } = crocks
const { Just, Nothing } = Maybe

console.log(map(x => x * 2)(Just(21)).toString())
// Just 42

console.log(map(x => x * 2)(Nothing()).toString())
// Nothing — как и метод, функция не трогает «пустую» ветку

console.log(chain(x => Just(x + 1))(Just(5)).toString())
// Just 6
```

Настоящая сила — в связке с `pipe` (вход через `safe`, выход через `option`):

```js
import crocks from 'crocks'
const { safe, map, option, pipe } = crocks

const isString = x => typeof x === 'string'
const upper = s => s.toUpperCase()

const shout = pipe(
  safe(isString),   // вход в мир Maybe
  map(upper),       // шаги внутри
  option('')        // выход в обычный код
)

console.log(shout('hi')) // 'HI'
console.log(shout(42))   // '' — не строка: safe дал Nothing, map проскочил
```

Обрати внимание: `pipe` собирает **обычные каррированные функции** — поэтому
pointfree-версии и нужны: метод `.map()` в `pipe` не вложишь.

## 4. `ap` — функция тоже в контейнере

`ap` отвечает на вопрос: «а если функция сама лежит в контейнере?». Сначала
зачем это: если применить `map` к **каррированной** функции, получим контейнер
с «недоприменённой» функцией:

```js
import crocks from 'crocks'
const { Maybe, curry, map, ap } = crocks
const { Just, Nothing } = Maybe

const add = curry((a, b) => a + b)

console.log(map(add)(Just(1)).toString())
// Just [Function] — внутри частично применённая функция «ждёт второй аргумент»

const mf = map(add)(Just(1)) // Just (b => 1 + b)

// МЕТОД: получатель — контейнер с функцией
console.log(mf.ap(Just(2)).toString())    // Just 3
console.log(mf.ap(Nothing()).toString())  // Nothing

// POINTFREE: порядок ДРУГОЙ — сначала контейнер со значением, потом с функцией!
console.log(ap(Just(2))(mf).toString())   // Just 3
```

> ⚠️ **Ловушка порядка:** метод — `контейнерСФункцией.ap(контейнерСоЗначением)`,
> а pointfree-функция — `ap(контейнерСоЗначением)(контейнерСФункцией)`.
> Аргументы переставлены местами. Если перепутать — получишь
> `TypeError: Wrapped value must be a function` (проверено на crocks 0.12).

## 5. `liftA2` / `liftA3` / `liftN` — комбинируем несколько контейнеров

Задача: сложить два числа, каждое «завёрнуто» в `Just`. `map` не берёт второй
контейнер, а `chain` заставит второй шаг зависеть от первого. Для независимых
значений есть `liftA2` — «поднять» обычную функцию **на два контейнера**:

```js
import crocks from 'crocks'
const { Maybe, Either, curry, liftA2 } = crocks
const { Just, Nothing } = Maybe
const { Left, Right } = Either

const add = curry((a, b) => a + b)

console.log(liftA2(add, Just(1), Just(2)).toString())
// Just 3

console.log(liftA2(add, Just(1), Nothing()).toString())
// Nothing — любая «пустая» ветка гасит всё

console.log(liftA2(add, Right(1), Right(2)).toString())
// Right 3 — работает с любым Apply (Maybe, Either, Result, Async...)

console.log(liftA2(add, Left('err'), Right(2)).toString())
// Left "err"

// вызов в карри-стиле тоже работает:
console.log(liftA2(add)(Just(1))(Just(2)).toString())
// Just 3
```

> ⚠️ **Главная ловушка `liftA2`: функция обязана быть каррированной.**
> Внутри он делает `m1.map(fn).ap(m2)`: `map` применяет `fn` к первому значению,
> и внутри контейнера должна остаться **функция**, ждущая второй аргумент.
> Передай обычную `(a, b) => a + b` — получишь `TypeError: Wrapped value must
> be a function`. Поэтому всегда: `curry(fn)`, `liftA2(curriedFn, m1, m2)`.
> То же верно для `liftA3` и `liftN`.

Три и N аргументов — `liftA3` и `liftN`:

```js
import crocks from 'crocks'
const { Maybe, curry, liftA3, liftN } = crocks
const { Just, Nothing } = Maybe

const add3 = curry((a, b, c) => a + b + c)

console.log(liftA3(add3, Just(1), Just(2), Just(3)).toString())
// Just 6
console.log(liftA3(add3, Just(1), Nothing(), Just(3)).toString())
// Nothing

console.log(liftN(3, add3, Just(1), Just(2), Just(3)).toString())
// Just 6 — универсальная версия для любого числа контейнеров
```

> 📖 Бонус: на **массивах** `liftA2` даёт декартово произведение:
> `liftA2(add, [1, 2], [10, 20])` → `[11, 21, 12, 22]`. Все комбинации пар —
> Applicative-семантика «все варианты», а не «одна из веток», как у Maybe.

### Полный пример: валидация формы из двух независимых полей

```js
import crocks from 'crocks'
const { safe, curry, liftA2 } = crocks

const isNonEmpty = s => typeof s === 'string' && s.trim().length > 0
const isPositive = n => typeof n === 'number' && n > 0
const format = curry((name, age) => `${name} (${age})`)

const makeLabel = (name, age) =>
  liftA2(format, safe(isNonEmpty)(name), safe(isPositive)(age))

console.log(makeLabel('Ivan', 30).toString())
// Just "Ivan (30)"
console.log(makeLabel('Ivan', -30).toString())
// Nothing — возраст не прошёл
console.log(makeLabel('   ', 30).toString())
// Nothing — имя не прошло
```

Каждое поле проверяется **независимо** и своим предикатом, а «сборка» — одна
строчка. Сравни с вложенными `if`: здесь порядок проверок не важен и его нельзя
запутать.

## 6. `curry` и контроль арности

`curry` ты знаешь из урока 0.1 — здесь он становится **обязательным клеем** для
`liftA2`/`liftA3`/`liftN` (см. ловушку выше). Рядом живут функции, которые
обрезают/фиксируют число аргументов:

```js
import crocks from 'crocks'
const { unary, binary, nAry } = crocks

const three = (a, b, c) => [a, b, c]

console.log(unary(three)(1, 2, 3))    // [1, undefined, undefined] — только первый
console.log(binary(three)(1, 2, 3))   // [1, 2, undefined] — первые два
console.log(nAry(2, three)(1, 2, 3)) // [1, 2, undefined] — ровно 2 аргумента (третий не передан)
```

Зачем: например, нативный `[1, 2].map(cb)` передаёт в колбэк ещё и индекс —
`unary(cb)` защищает от «лишний аргумент просочился».

> ⚠️ В главном экспорте crocks 0.12 **нет** helper-функции `maybe` и `curryN`
> (проверено). Роль `maybe` играют метод `.option()` и pointfree `option`,
> а вместо `curryN` — `curry`, `unary`, `binary`, `nAry`.

## 7. Вход и выход: `safe`, `option`, `either`

Любой конвейер выглядит так: **вход** (значение → контейнер) → **шаги**
(`map`/`chain`/`liftA2`) → **выход** (контейнер → значение):

```js
import crocks from 'crocks'
const { Maybe, safe, option, either } = crocks
const { Nothing, Just } = Maybe

// ВХОД: safe(предикат)(значение) -> Maybe (урок 1.1)
console.log(safe(x => typeof x === 'number')(5).toString()) // Just 5

// ВЫХОД pointfree: option(дефолт, контейнер) — разворачивает Maybe
console.log(option('нет данных', Nothing()))   // 'нет данных'
console.log(option('нет данных')(Nothing()))  // то же в карри-стиле

// ВЫХОД pointfree: either(fLeft, fRight, контейнер)
// работает с Either (урок 1.2) и с Maybe (метод .either есть и там — урок 1.1)
console.log(either(e => 'E:' + e, v => 'V:' + v, Left('x'))) // 'E:x'
console.log(either(() => 'пусто', v => 'v=' + v, Nothing())) // 'пусто'
console.log(either(() => 'пусто', v => 'v=' + v, Just(7)))   // 'v=7'
```

Каррированность всех этих функций — то, что позволяет собирать их в `pipe`:
вход, сколько угодно шагов, выход — одна функция на всё.

## 8. Резюме урока

| Инструмент | Сигнатура / роль |
|---|---|
| `map(f)(m)` | Functor: преобразовать значение внутри |
| `chain(f)(m)` | Monad: соединить последовательные шаги |
| `ap(mVal)(mFn)` | Applicative: применить функцию из контейнера (⚠️ порядок обратный методу) |
| `liftA2(curriedF, m1, m2)` | комбинировать два независимых контейнера |
| `liftA3`, `liftN(n, curriedF, ...)` | то же для трёх и N контейнеров |
| `curry(f)` | обязательный клей для liftA* |
| `unary` / `binary` / `nAry` | контроль числа аргументов |
| `safe(предикат)(значение)` | вход: значение → Maybe |
| `option(дефолт, m)` / `either(fL, fR, m)` | выход: контейнер → значение |
