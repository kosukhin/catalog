# Теория к уроку 3.5 — `Arrow`

> **О чём:** почему функция — это не только «код, который можно вызвать», но и значение, которое можно компоновать, адаптировать и анализировать.
>
> Практика: [`../Урок-3.5-Arrow.md`](../Урок-3.5-Arrow.md)

## 1. Проблема

Обычные функции прекрасно компонуются: `f ∘ g`. Но у монад есть особенность: следующий шаг выбирается **динамически**, по результату предыдущего. Это мощно, но иногда мешает:

- структуру вычисления нельзя узнать, не запустив его;
- нельзя заранее оптимизировать или проанализировать граф вычислений;
- нельзя переиспользовать одну и ту же «схему» с разными входами;
- композиция функций с несколькими входами/выходами становится громоздкой.

`Arrow` — это абстракция для вычислений, которые:

- имеют **статическую структуру**, известную до запуска;
- могут комбинироваться последовательно и параллельно;
- умеют работать с парами значений;
- не обязаны быть монадами.

## 2. История

### 2.1. Статья Хьюза 2000 года

Джон Хьюз опубликовал «Generalising Monads to Arrows» (Science of Computer Programming, 2000). Он заметил, что монады не всегда подходят для:

- парсеров с анализом;
- обработки потоков и событий;
- реактивного программирования;
- схем и роботов, где важна статическая топология.

Монада позволяет выбирать следующий шаг по значению; для этих задач такая динамика избыточна и мешает анализу. Хьюз предложил класс `Arrow` — обобщение монад с более статичной структурой.

В Haskell появился модуль `Control.Arrow` с операциями:

```haskell
arr   :: (b -> c) -> a b c
first :: a b c -> a (b, d) (c, d)
second:: a b c -> a (d, b) (d, c)
(>>>) :: a b c -> a c d -> a b d
(***) :: a b c -> a b' c' -> a (b, b') (c, c')
(&&&) :: a b c -> a b c' -> a b (c, c')
```

`arr` поднимает обычную функцию в стрелку; `first`/`second` пропускают одну половину пары; `***` применяет две стрелки параллельно; `&&&` дублирует вход и применяет две стрелки, собирая результаты в пару.

### 2.2. Профункторы

С точки зрения теории категорий тип стрелки можно рассматривать как **профунктор**: бифунктор `C^op × D -> Set`, который контравариантен по входу и ковариантен по выходу. В Haskell `Profunctor` описывает `dimap`:

```haskell
dimap :: (a -> b) -> (c -> d) -> p b c -> p a d
```

`Arrow` — это профунктор с дополнительной структурой («strong profunctor»): `first`/`second` позволяют протаскивать пары. Поэтому стрелку можно рассматривать как морфизм в категории, а не просто как функцию.

### 2.3. «Вход контравариантен, выход ковариантен» — разбор фразы

> **Фраза из практики:** «`Arrow` — не контейнер значения и не монада: это **профунктор**, обёртка над функцией, у которой вход контравариантен, а выход ковариантен.» В ней важно каждое слово, поэтому разберём её по частям.

#### Позиция параметра задаёт направление

`Arrow` — обёртка над унарной функцией, поэтому у неё ровно две «стороны»:

```text
Arrow a b  ≈  a -> b
              ↑    ↑
            вход  выход
```

В Haskell у стрелки три параметра (`a b c`: сама стрелка, её вход и выход); в `crocks` стрелка и есть обёртка, поэтому параметров два.

**Вариативность** (variance) — это правило, по которому параметр типа можно менять, не переписывая тело функции:

- **ковариантность** — «в ту же сторону»: из функции `b -> c` получается `Arrow a b -> Arrow a c`;
- **контравариантность** — «в обратную сторону»: из функции `c -> a` получается `Arrow a b -> Arrow c b`.

#### Шаг за шагом: одни и те же числа, два разных порядка

Возьмём стрелку «+1» и **один и тот же** адаптер «×10». Разница только в методе:

```js
import crocks from 'crocks'
const { Arrow } = crocks

const inc = Arrow(x => {
  console.log('  стрелка получила:', x)
  return x + 1
})

const times10 = x => {
  console.log('  адаптер получил:', x)
  return x * 10
}

console.log('--- map ---')
console.log('  результат:', inc.map(times10).runWith(3))

console.log('--- contramap ---')
console.log('  результат:', inc.contramap(times10).runWith(3))

console.log('--- promap ---')
console.log('  результат:', inc.promap(times10, times10).runWith(3))
```

Вывод (порядок строк — это и есть порядок вызовов):

```text
--- map ---
  стрелка получила: 3
  адаптер получил: 4
  результат: 40
--- contramap ---
  адаптер получил: 3
  стрелка получила: 30
  результат: 31
--- promap ---
  адаптер получил: 3
  стрелка получила: 30
  адаптер получил: 31
  результат: 310
```

Разбор по шагам:

| Шаг | `inc.map(times10)` | `inc.contramap(times10)` |
|---|---|---|
| 0 | `runWith(3)` | `runWith(3)` |
| 1 | стрелка: `3 + 1 = 4` | адаптер: `3 * 10 = 30` |
| 2 | адаптер: `4 * 10 = 40` | стрелка: `30 + 1 = 31` |
| Первым работает | стрелка | адаптер |
| Адаптер стоит | **после** стрелки | **до** стрелки |
| Формула | `r ∘ inc` | `inc ∘ l` |

То есть `map` меняет то, что стрелка **отдаёт**, а `contramap` — то, что она **принимает**. Конвейер выглядит так:

```text
вход ──► [l: c -> a] ──► [arrow: a -> b] ──► [r: b -> d] ──► выход
          contramap          стрелка              map
          новый вход                          новый выход
```

`promap(l, r)` заполняет оба места сразу: сначала `l`, потом стрелка, потом `r`.

> 🔌 **Бытовая аналогия.** Стрелка понимает только «свой» формат. Приходит чужой вход — его нужно перевести **до** стрелки, иначе она не поймёт; нужен чужой выход — переводим **после**. `contramap` — переходник на входе, `map` — переходник на выходе.

Названия отражают направление самого адаптера: у `map` он идёт `b -> c` — так же, как меняется тип (`Arrow a b` → `Arrow a c`), а у `contramap` — `c -> a`, **против** направления типа (`Arrow a b` → `Arrow c b`).

#### Выход ковариантен: `map`

```haskell
rmap :: (b -> c) -> p a b -> p a c        -- p = Arrow
```

```text
arrow.map(r) = r ∘ arrow          -- r приклеивается ПОСЛЕ стрелки
```

Параметр `b` стоит справа (`a -> b`), то есть описывает результат. Поэтому преобразование `b -> c` можно поставить **после** вычисления: стрелка по-прежнему принимает `a`, но теперь отдаёт `c`. Тип едет в ту же сторону, что и функция: `Arrow a b` → `Arrow a c` при `b -> c`. По сути это `Functor` по выходу: в `crocks` `Arrow` так и реализует `Functor`, а в профункторной нотации тот же метод называется `rmap`.

```js
import crocks from 'crocks'
const { Arrow } = crocks

const inc = Arrow(x => x + 1)

console.log(inc.map(n => n * 10).runWith(3)) // 40 — сначала 3 + 1, потом * 10
console.log(inc.map(String).runWith(3))      // '4' — выход стал строкой
```

Законы: `map` не меняет порядок применения функций.

```text
arrow.map(id)       = arrow
arrow.map(f).map(g) = arrow.map(x => g(f(x)))   -- f, затем g
```

#### Вход контравариантен: `contramap`

```haskell
lmap :: (c -> a) -> p a b -> p c b        -- p = Arrow
```

```text
arrow.contramap(l) = arrow ∘ l    -- l приклеивается ДО стрелки
```

Обратите внимание на направление функции: `c -> a`, то есть **из нового входа в старый**, тогда как сама стрелка меняется `Arrow a b` → `Arrow c b`. Функция идёт против направления типа — отсюда «контра». В `crocks` это интерфейс `Contravariant`, в профункторной нотации — `lmap`.

Почему иначе нельзя: чтобы получить стрелку, принимающую `c`, не трогая тело, остаётся только превратить `c` в `a` и скормить результат исходной стрелке. Обратное невозможно: в момент адаптации значения `a` ещё не существует — оно появится только при вызове. Короткое правило: **вход можно лишь подготовить, выход — лишь обработать**.

```js
import crocks from 'crocks'
const { Arrow } = crocks

const inc = Arrow(x => x + 1)

console.log(inc.contramap(x => x * 10).runWith(3))      // 31 — сначала 3 * 10, потом + 1
console.log(inc.contramap(s => s.length).runWith('abc')) // 4  — теперь стрелка «умеет» строки
```

Первый закон тот же (нейтральный элемент), а композиция переворачивает порядок: первым срабатывает адаптер, написанный **последним**.

```text
arrow.contramap(id)             = arrow
arrow.contramap(l).contramap(k) = arrow.contramap(x => l(k(x)))  -- k, затем l
```

Та же мысль через композицию: `map f ∘ map g = map (f ∘ g)` — порядок сохраняется, а `contramap f ∘ contramap g = contramap (g ∘ f)` — порядок перевёрнут. Это и есть формальное различие ковариантного и контравариантного функтора: закон один и тот же, но композиция в нём идёт в другую сторону.

#### Оба конца сразу: `promap`

```haskell
dimap :: (c -> a) -> (b -> d) -> p a b -> p c d   -- p = Arrow
```

```text
arrow.promap(l, r) = r ∘ arrow ∘ l
```

`l` — контравариантный адаптер входа (до стрелки), `r` — ковариантный адаптер выхода (после). Соответствие имён в Haskell и `crocks`:

| `Data.Profunctor` | `crocks` `Arrow` | Что меняет | Направление |
|---|---|---|---|
| `rmap` | `.map(r)` | выход | ковариантное |
| `lmap` | `.contramap(l)` | вход | контравариантное |
| `dimap` | `.promap(l, r)` | вход и выход | оба |

> 📖 В Haskell имена `lmap`/`rmap`/`dimap` живут в `Data.Profunctor`: у класса `Arrow` из `Control.Arrow` таких методов нет, там своя нотация (`>>>`, `***`, `&&&`). В `crocks` все три метода определены прямо у `Arrow`.

```js
import crocks from 'crocks'
const { Arrow } = crocks

const inc = Arrow(x => x + 1)
const fromString = inc.promap(s => Number(s), n => n * 10)

console.log(fromString.runWith('3')) // 40 — Number('3') + 1, затем * 10
```

#### Почему «не контейнер» и «не монада»

Слово «контейнер» предполагает, что внутри лежит **значение**, которое `map` преобразует на месте. В `Arrow` внутри лежит **код**, а значения до `runWith` вообще нет:

```js
import crocks from 'crocks'
const { Arrow } = crocks

const inc = Arrow(x => x + 1)

console.log(inc.toString())   // Arrow Function
console.log(typeof inc.of)    // 'undefined'
console.log(typeof inc.chain) // 'undefined'
```

- `of` не определён: чтобы положить значение в обёртку над функцией, пришлось бы сделать константную функцию, игнорирующую вход, — это уже не стрелка из `a` в `b`.
- `chain`/`ap`/`then` тоже нет: `chain` означал бы «запустить стрелку, по её результату выбрать следующую» — динамическую структуру, то есть монаду (`ArrowApply`). `crocks` сознательно оставляет `Arrow` статической.
- `map` ничего не «достаёт» и не «кладёт» — он лишь дописывает шаг в конец конвейера. Поэтому вариативность здесь — свойство **позиций в типе `a -> b`**, а не «значения внутри».

#### Откуда берётся направление: подтипы

В языках с типами это ровно правило подтипизации функций: функция, принимающая более общий тип, годится там, где нужен более узкий (`Animal -> String` можно использовать как `Dog -> String`), а возвращающая более узкий — там, где нужен более общий (`A -> Dog` как `A -> Animal`). В TypeScript это проверяет флаг `strictFunctionTypes`. Отсюда и разные направления адаптеров: вход расширяется «назад», выход — «вперёд».

#### Как не перепутать

| Вопрос | Какая функция нужна | Метод |
|---|---|---|
| Хочу принимать **другой вход** | `новый вход -> старый вход` | `.contramap(l)` |
| Хочу отдавать **другой выход** | `старый выход -> новый выход` | `.map(r)` |
| Хочу и то и другое | обе функции | `.promap(l, r)` |

> 🧭 **Мнемоника.** `map` — «после», `contramap` — «до». Адаптер входа похож на переходник-розетку: он стоит **перед** прибором и поэтому идёт от нового разъёма к старому.

В JS проверки типов нет, поэтому «неправильная сторона» не падает, а молча даёт странный результат:

```js
import crocks from 'crocks'
const { Arrow } = crocks

const inc = Arrow(x => x + 1)

console.log(inc.map(s => Number(s)).runWith('3'))      // 31 — не то, что ждали
console.log(inc.contramap(s => Number(s)).runWith('3')) // 4
```

`inc('3')` — это `'3' + 1`, то есть строка `'31'`, и только потом `Number('31')` даёт `31`. В Haskell такой код просто не скомпилировался бы: `map` ждёт функцию из выходного типа. В JS вариативность приходится держать в голове.

Крайний случай — `Pred`: у него есть только вход, поэтому определён только `contramap`, а `map` нет (см. [урок 0, раздел «Ковариантность, контравариантность и профунктор»](../Урок-0-Термины-ФП.md)). Если же параметр стоит и на входе, и на выходе (`a -> a`), он **инвариантен**: ни `map`, ни `contramap` для него не построить.

Итог разбора: «не контейнер» — потому что хранится не значение, а преобразование; «не монада» — потому что нет `of`/`chain` и нельзя выбрать следующий шаг по результату; «профунктор» — потому что оба конца типа `a -> b` являются параметрами, и каждый адаптируется в своём направлении:

```text
вход  a: contramap, функция c -> a  (назад)   ← контравариантность
выход b: map,       функция b -> d  (вперёд)  → ковариантность
оба:     promap     : c -> a и b -> d
```

### 2.4. `Arrow` в `crocks`

В `crocks` `Arrow` — не полный Haskell-класс `Arrow`. В версии 0.12.4 он реализует:

- `Semigroupoid` (композиция),
- `Category` (`id`),
- `Functor` (`map`),
- `Contravariant` (`contramap`),
- `Profunctor` (`promap`).

При этом в нём **нет** `arr`, `of`, `chain`, `ap`, `then`. `.compose` работает слева направо (как «сначала это, потом то»), а `fanout` — отдельная функция, аналог `&&&`. Это важно: `crocks` даёт практичный JS-инструмент для композиции функций, а не полную реализацию теории стрелок.

## 3. Теория

Стрелка `Arrow a b c` — это вычисление, которое принимает `b` и возвращает `c`. Законы категории:

```text
id >>> f = f
f >>> id = f
(f >>> g) >>> h = f >>> (g >>> h)
```

Законы стрелок (упрощённо):

- `arr(id) = id`;
- `arr(g ∘ f) = arr(f) >>> arr(g)`;
- `first(arr(f)) = arr(f × id)`;
- `first(f >>> g) = first(f) >>> first(g)`;
- `first(f) >>> arr(fst) = arr(fst) >>> f`;
- `first(first(f)) >>> arr(assoc) = arr(assoc) >>> first(f)`.

Смысл: `arr` сохраняет композицию, а `first` согласованно работает с парами.

### Стрелка против монады

- Монада: `chain :: (a -> M b) -> M a -> M b` — следующий шаг зависит от значения.
- Стрелка: структура фиксирована; можно комбинировать параллельно (`***`), дублировать вход (`&&&`), пропускать половину пары (`first`).
- `ArrowApply` (стрелка с `app`) эквивалентна монаде; обычная `Arrow` слабее.

Именно статичность делает стрелки полезными для анализа, оптимизации и визуализации вычислений.

## 4. Почему это полезно в JavaScript

- **Пайплайны преобразований.** `Arrow` позволяет собирать функции в композируемые значения и переиспользовать их.
- **Адаптеры.** `contramap`/`promap` удобны, когда нужно подстроить вход/выход функции под другой интерфейс.
- **Работа с парами.** `first`/`second`/`both` помогают обрабатывать данные, не разбирая их вручную.
- **Явная композиция.** В отличие от `pipe`, `Arrow` — это значение, которое можно передать, сохранить, скомбинировать.

## 5. Границы

- В `crocks` `Arrow` ограничен: нет `arr`, `of`, `chain`, `ap`; это не полноценная замена Haskell `Arrow`.
- Нет динамического выбора шага; для этого нужна монада или `ArrowApply`.
- Композиция функций в JS и так проста; `Arrow` оправдан, когда важна переиспользуемость и адаптация, а не в каждом пайплайне.
- Типы в JS отсутствуют, поэтому законы стрелок держатся на дисциплине.
