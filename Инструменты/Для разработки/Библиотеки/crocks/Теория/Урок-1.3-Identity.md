# Теория к уроку 1.3 — `Identity`

> **О чём:** зачем нужен контейнер, который ничего не делает, и почему он не бесполезен.
>
> Практика: [`../Урок-1.3-Identity.md`](../Урок-1.3-Identity.md)

## 1. Проблема

В математике и программировании часто нужен **нейтральный элемент**: число `0` для сложения, пустая строка для конкатенации, пустой массив для `concat`. Для контейнеров тоже нужен «никакой» контейнер — такой, который не добавляет ни отсутствия, ни ошибки, ни состояния, ни асинхронности.

Зачем?

- чтобы **проверять законы**: на `Identity` законы функтора и монады видны без помех;
- чтобы **писать обобщённый код**: функция, работающая с любым функтором, должна корректно работать и с «пустым» случаем;
- чтобы **строить трансформеры**: `IdentityT` — базовый случай стека монадных трансформеров;
- чтобы **явно отделять «эффект» от «значения»**: иногда полезно сказать «здесь эффекта нет», а не оставлять голое значение.

## 2. История

### 2.1. Единица в теории категорий

В категории есть тождественный функтор `Id`, который сопоставляет каждому объекту его самого, а каждому морфизму — его самого. Он играет роль единицы относительно композиции функторов: `Id ∘ F ≅ F`, `F ∘ Id ≅ F`.

В теории монад `Identity` — простейшая монада. Она показывает, что монада — это не обязательно «что-то сложное»; это структура, которая может быть тривиальной.

### 2.2. Haskell и трансформеры

В Haskell есть `Data.Functor.Identity`:

```haskell
newtype Identity a = Identity { runIdentity :: a }
```

Он реализует `Functor`, `Applicative`, `Monad`, `Foldable`, `Traversable`; в пакете `comonad` для него есть также экземпляр `Comonad`. `IdentityT` — простейший трансформер (`IdentityT m a = m a`); его часто используют как базовый слой стека, а `IdentityT Identity` — это, по сути, `Identity`.

`Identity` также удобен в `traverse`: если нужно просто пройтись по структуре и собрать результат без эффекта, `Identity` подходит идеально. Более того, `map` можно выразить через `traverse` с `Identity` — это показывает, насколько тесно связаны функтор и траверсабл.

### 2.3. В JavaScript

В `crocks` `Identity` — один из самых простых типов. Он нужен не для «настоящих» эффектов, а как учебный и как строительный блок: на нём удобно понять, что `map`, `chain`, `of` — это не магия, а конкретные операции, которые могут быть тривиальными.

## 3. Теория

```text
Identity a = a
```

Все операции — тождественные:

```text
map   f (Identity x) = Identity (f x)
chain f (Identity x) = f x
of    x              = Identity x
```

Законы выполняются «сами собой», потому что `Identity` ничего не делает. Это делает его идеальной моделью для проверки: если вы поняли законы на `Identity`, вы поняли их в чистом виде, без шума эффектов.

Если внутри `Identity` лежит моноид, то и сам `Identity` можно сделать моноидом: `empty = Identity(empty)`, `concat` применяется внутри. Аналогично с другими алгебрами.

## 4. Почему это нужно в курсе

- **Для обучения.** `Identity` показывает, что контейнер — это не обязательно «коробка с сюрпризом». Это просто тип с операциями.
- **Для обобщения.** Код, который требует `Functor`, должен работать и с `Identity`; это хороший тест на корректность абстракции.
- **Для трансформеров.** `ReaderT`, `StateT`, `MaybeT` строятся поверх базовой монады; `Identity` — самый простой базовый случай.
- **Для тестов.** Свойства `map`/`chain` проще проверить на `Identity`, чем на `Async` или `State`.

## 5. Границы

- В прикладном коде `Identity` обычно не нужен: он не решает ни одной практической проблемы.
- Он добавляет обёртку и накладные расходы без выгоды, если только вы не строите общую абстракцию.
- Не стоит тащить `Identity` в публичный API «на всякий случай»: это усложняет понимание.
- `Identity` не заменяет `Maybe`: он не умеет представлять отсутствие.
