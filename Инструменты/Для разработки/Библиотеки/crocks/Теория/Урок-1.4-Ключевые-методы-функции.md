# Теория к уроку 1.4 — ключевые методы-функции

> **О чём:** почему `map`, `chain` и `ap` существуют в двух видах — как методы контейнера и как отдельные функции, — и при чём тут point-free стиль.
>
> Практика: [`../Урок-1.4-Ключевые-методы-функции.md`](../Урок-1.4-Ключевые-методы-функции.md)

## 1. Проблема

В `crocks` одну и ту же операцию часто можно записать по-разному:

```js
Maybe.of(2).map(double)
map(double, Maybe.of(2))
```

Первый вариант — **метод**, второй — **функция**. Зачем дублировать?

Причины исторические и практические:

- В Haskell операции — это функции из классов типов, а не методы объектов. `fmap f x`, а не `x.fmap(f)`.
- В JavaScript естественнее выглядит цепочка методов: `x.map(f).chain(g)`. Но цепочка плохо комбинируется, если заранее неизвестно, с каким типом вы работаете.
- Для композиции нужны функции, которые можно передать в `pipe`, `compose`, `curry`, `liftA2`. Метод с `this` для этого неудобен.
- Point-free стиль требует, чтобы данные шли **последним** аргументом: тогда функцию можно частично применить и получить готовый пайплайн.

## 2. История

### 2.1. Комбинаторы и бесточечный стиль

Идея строить функции без упоминания аргументов восходит к комбинаторной логике Шёнфинкеля и Карри (1920–30-е). В программировании её популяризировали APL и J (1960–70-е), а также Джон Бэкус в лекции 1977 года: программа как композиция функций, а не как последовательность операций над переменными.

В Haskell бесточечный (point-free) стиль стал обычной практикой:

```haskell
sumOfSquares = sum . map (^ 2)
```

Здесь нет ни одного упоминания списка — только композиция функций.

### 2.2. JavaScript и библиотеки

В JS point-free пришёл через библиотеки Ramda, Sanctuary и `crocks`. Ramda сделала ставку на каррированные data-last функции; `crocks` добавил к этому алгебраические типы и модуль `pointfree`, где для каждого метода есть отдельная функция.

Спецификация Fantasy Land (2013) зафиксировала **методы** (`fantasy-land/map`, `fantasy-land/chain`), потому что в JS удобно вызывать их на объекте. `crocks` поддерживает и методы, и point-free обёртки — отсюда два API.

## 3. Теория

### Три операции

```text
map   :: (a -> b) -> F a -> F b
chain :: (a -> M b) -> M a -> M b
ap    :: F (a -> b) -> F a -> F b
```

- `map` — функтор: преобразовать значение внутри контекста.
- `chain` — монада: выполнить следующий шаг, который сам возвращает контекст.
- `ap` — аппликатив: применить функцию внутри контекста к значению внутри контекста.

`liftA2` собирает из них функцию двух аргументов:

```text
liftA2 f a b = ap(map(f, a), b)
```

Это не отдельная абстракция, а удобный комбинатор. `liftA3` — то же для трёх аргументов.

### Метод против функции

Метод — это динамическая диспетчеризация: конкретный объект решает, как выполнить `map`. Функция из `pointfree` обычно делает то же самое, но принимает объект аргументом.

Плюсы методов:

- привычная цепочка;
- автодополнение в редакторе;
- не нужно импортировать каждую операцию.

Плюсы функций:

- композиция: `pipe(map(f), chain(g))`;
- каррирование и частичное применение;
- единообразие для разных типов;
- проще тестировать и переиспользовать.

## 4. Почему в JavaScript это важно

- Методы теряют `this`, если передать их как колбэк: `arr.map(parseInt)` — классическая ловушка. Point-free функции такой проблемы не имеют.
- В pipeline-стиле `pipe(prop('user'), map(getName))` читается как описание преобразования, а не как последовательность мутаций.
- `crocks` даёт **data-last** API: сначала функция/конфигурация, потом данные. Это позволяет строить пайплайны без упоминания данных.
- Для обобщённого кода (например, `traverse`) нужны именно функции, а не методы.

## 5. Границы

- Point-free легко переусердствовать: `pipe(map(f), filter(g), reduce(h, 0))` может быть понятнее, чем десять вложенных методов, но только если читатель знает эти функции.
- В отладке цепочка методов даёт более понятный стек, чем длинная композиция.
- Не все методы имеют удобный point-free аналог; иногда проще написать лямбду.
- `curry` в JS не бесплатен: она добавляет обёртки и может путать при неполном применении.
