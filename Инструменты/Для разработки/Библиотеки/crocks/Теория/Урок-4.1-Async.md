# Теория к уроку 4.1 — `Async`

> **О чём:** почему асинхронное вычисление удобно описать как **значение** — ленивое, отменяемое и с ошибкой в отдельной ветке, — и как эта идея выросла из continuation-passing style и монады `IO`.
>
> Практика: [`../Урок-4.1-Async.md`](../Урок-4.1-Async.md)

## 1. Проблема

Асинхронность — это **эффект**: результат появляется не сразу, а «потом», и в это время мир продолжает жить. У эффекта есть три неприятных свойства:

- **порядок** — шаги зависят друг от друга и должны выполняться по очереди;
- **время** — между стартом и результатом проходит время, и операцию иногда нужно **отменить**;
- **провал** — операция может не удаться, и провал — обычное дело, а не исключительная ситуация.

Callback-стиль делает порядок вложенным («callback hell»), промисы возвращают порядок, но:

- `Promise` **начинается сразу** при создании — его нельзя «построить, но не запускать», нельзя переиспользовать описание;
- его **нельзя отменить** (нет стандартного способа прервать `fetch`);
- ошибка в промисах живёт как **исключение** (`catch`, `try/catch`), то есть на другом языке, чем успешный результат;
- два промиса нельзя соединить теми же операциями, что `Maybe`/`Either` — у них разные интерфейсы.

Идея `Async`: описать асинхронное вычисление теми же операциями, что и обычный контейнер (`map`, `chain`, `ap`, `alt`), но **не запускать** его до явного `fork`/`toPromise`.

## 2. История

### 2.1. CPS и «ад колбэков»

В Node (с 2009) асинхронность выражали continuation-passing style: функция получает колбэк-продолжение и вызывает его позже. Отсюда канонический node-стиль `fn(args…, (err, data) => …)` — «сначала ошибка». При росте цепочек получалась вложенность («callback hell») и разрозненная обработка ошибок.

Ключевое наблюдение: **продолжение — это значение**. Колбэк можно передавать, хранить и комбинировать. Именно на этом строится `Async`: его тело — функция `(reject, resolve) => …`, а запуск — это передача ей двух продолжений.

### 2.2. Promises и `async/await`

Спецификация Promises/A+ (около 2012, стандарт в ES6 2015) вернула порядок и единый `catch`. `async/await` (ES2017) синтаксически спрятал `.then`. Но промис остался **горячим** (работа начинается при создании), **неотменяемым** и трактующим ошибку как исключение. Это отличный инструмент для линейного кода и плохой — для описания вычислений как данных.

### 2.3. `IO`, `Cont` и `Task`

В Haskell эффекты описывают значением: `IO a` — «программа, которая при запуске даст `a`». Уодлер в «Monads for functional programming» (1992) показал, как монады дисциплинируют эффекты. Для асинхронности используют `ContT` (продолжения) и `Task` (async + ошибка) из библиотек вроде `purescript-aff` и `folktale`.

`crocks.Async` — прямой наследник `Task`/`Cont`: это **ленивое** вычисление с двумя ветками и отменой. Реализует Fantasy Land-интерфейсы (`map`, `ap`, `chain`, `of`), а также `alt` (`Alt`) и `bimap` (`Bifunctor`) — те же, что `Maybe`/`Either`, но поверх асинхронного эффекта.

### 2.4. `Async` в `crocks`

В версии 0.12.4 `Async` реализует `Functor`, `Apply`, `Applicative`, `Chain`, `Monad`, `Alt`, `Bifunctor`. Запуск — только `fork(err, ok)` или `toPromise()`; метода `.run` нет. Конструкторы: `Async(fn)`, `Async.Resolved`/`Async.of`, `Async.Rejected`, `Async.fromPromise`, `Async.fromNode`, `Async.resolveAfter`/`rejectAfter`, `Async.all`. Мостов между мирами тоже хватает: `asyncToPromise`, `maybeToAsync`, `eitherToAsync`, `resultToAsync`.

## 3. Теория

`Async` — это «монада поверх continuation-passing style». Его значение можно записать типом:

```text
Async e a  ≈  (e -> r) -> (a -> r) -> Canceler
                 reject    resolve
```

- `e` — тип ошибки (`Rejected`), `a` — тип успеха (`Resolved`);
- `fork(err, ok)` — это и есть применение к двум продолжениям;
- возвращаемое `Canceler` — функция отмены, «как освободить ресурс».

Значение **лениво**: пока продолжения не переданы, ничего не происходит. Отсюда сразу видны все операции:

```text
map(f)     = \rej res -> self(rej, res . f)          -- f поверх успеха
bimap(l,r) = \rej res -> self(rej . l, res . r)      -- l и r на обе ветки
chain(f)   = \rej res -> self(rej, x -> f(x)(rej, res))   -- запускается внутренний Async
alt(m)     = \rej res -> self(y -> m(y, res), res)   -- m запускается только при ошибке
race(m)    = оба fork'а; побеждает первый settle, отменяется второй
all(xs)    = sequence(Async.of, xs)                   -- аппликативная сборка
```

Иными словами, `map`/`bimap` — это **композиция продолжений**, `chain` — **вложенный fork**, `alt` — **условный fork**, а `race` — fork обоих с общим «одноразовым» продолжением.

Законы наследуются от структуры контейнера (см. урок 0): тождество функтора `map(id) = id`, композиция `map(g ∘ f) = map(f) . map(g)`, левая/правая единица монады и ассоциативность `chain`. Асинхронность их не меняет — меняется лишь **когда** выполняются шаги.

```js
import crocks from 'crocks'
const { Async } = crocks

// Async — это CPS: телу дают «продолжения» reject/resolve
const fromCps = fn => Async((reject, resolve) => fn(resolve, reject))
const later = fromCps(resolve => setTimeout(() => resolve('готово'), 5))
console.log(await later.toPromise())            // готово

// ленивость: построение не запускает, fork — запускает
let started = false
const task = Async((rej, res) => { started = true; res(1) })
console.log('до fork:', started)                // до fork: false
task.fork(() => {}, () => {})
console.log('после fork:', started)             // после fork: true

// левая единица монады: of(x).chain(f) === f(x)
const f = x => Async.of(x + 1)
console.log(await Async.of(2).chain(f).toPromise())  // 3
console.log(await f(2).toPromise())                  // 3
```

### 3.1. `Alt` вместо `catch`, `Bifunctor` вместо `try/catch`

У промиса две конструкции — «продолжение» (`.then`) и «обработка провала» (`.catch`), причём провал стирает тип ошибки. У `Async` ошибка живёт **в типе** (`Rejected e`), поэтому:

- `alt` — это «или»: `a.alt(b)` описывает выбор между двумя вычислениями, и он **композируем** (цепочки фолбэков);
- `coalesce` — это «схлопнуть обе ветки в одну» (отображение `e -> a` и `a -> a`), аналог `either` в `Either` (урок 1.2), только асинхронный;
- `bimap`/`bichain` — двусторонние преобразования, недоступные «одной» конструкции `catch`.

### 3.2. Отмена как ресурс

Промис нельзя отменить — в лучшем случае игнорируют его результат. `Async` возвращает **canceler**: `fork` отменяет работу, и построенные из «чистильщиков» цепочки освобождают ресурсы (таймеры, соединения). Это делает `Async` не просто «обещанием с задержкой», а описанием **жизненного цикла** операции.

## 4. Почему это полезно в JavaScript

- **Ленивость и переиспользование.** Одно описание `Async` можно запускать много раз и комбинировать до запуска.
- **Единый язык с `Maybe`/`Either`.** `map`/`chain`/`ap`/`alt` уже знакомы по урокам 1.1–1.4 — кривая обучения почти нулевая.
- **Ошибка как значение.** `bimap`/`alt`/`coalesce` дают предсказуемую обработку без `try/catch`.
- **`race` и `all` бесплатно.** «Кто первый» и «собрать все» — штатные операции монады, а не отдельные API.
- **Мосты.** `fromPromise`/`fromNode` — конвертация на границе, как `maybeToEither` в уроке 1.1.

## 5. Границы

- `Async` **не заменяет** `async/await` в линейном коде: `try/catch` там читается проще. `Async` выигрывает, когда важны ленивость, отмена и композиция ветвлений.
- В `crocks` `Async` ограничен: нет `Foldable`/`Traversable` (проверено), нет статика `race` и метода `run`, `coalesce`/`swap` требуют двух функций.
- Отмена работает, только если у вычисления есть «чистильщик»; «горячие» источники (например, уже запущенный `fetch`) так не прерываются по-настоящему.
- В JS нет типов, поэтому ветки `Resolved`/`Rejected` держатся на дисциплине, а не на проверке компилятора.
