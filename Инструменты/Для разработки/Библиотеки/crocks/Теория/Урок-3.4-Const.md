# Теория к уроку 3.4 — `Const`

> **О чём:** как функтор, который «ничего не хранит», помогает сворачивать структуры и почему для этого нужен моноид.
>
> Практика: [`../Урок-3.4-Const.md`](../Урок-3.4-Const.md)

## 1. Проблема

Свёртка (fold) отвечает на вопрос: «как из множества значений получить одно?» Сумма, минимум, список, конкатенация строк, проверка «все ли элементы удовлетворяют условию» — всё это свёртки.

Обычно свёртку пишут рекурсивно или через `reduce`. Но есть более общая точка зрения: свёртка — это **интерпретация структуры в моноид**. И здесь неожиданно оказывается полезным функтор, который не хранит значение, а только накапливает результат.

`Const` — это контейнер, у которого «значение» фиксировано: сколько бы вы ни применяли `map`, внутри остаётся одна и та же константа. Звучит бесполезно, пока не понимаешь, что именно так можно накапливать свёртку.

## 2. История

### 2.1. Постоянный функтор

В теории категорий для любого объекта `c` есть постоянный функтор `Δ_c`, который:

- каждому объекту `x` сопоставляет `c`;
- каждому морфизму `x -> y` сопоставляет тождественный морфизм `c -> c`.

В Haskell это `Const c`:

```haskell
newtype Const c a = Const { getConst :: c }
```

Параметр `a` — «фантомный»: он есть в типе, но не влияет на значение. `map` по нему ничего не делает.

### 2.2. Const и линзы

В библиотеках линз (`lens`, `profunctors`) `Const` играет ключевую роль: с его помощью описывают «получение» и «свёртку» как частный случай обхода. Идея: если функтор не меняет значение, а только накапливает, то `traverse` с `Const` превращается в `foldMap`.

### 2.3. Const в Haskell и crocks

В современном Haskell `Const` живёт в `Data.Functor.Const` (раньше — в пакетах вроде `transformers`). В `crocks` `Const` — отдельный тип с методами `concat`, `map`, `ap`, `of`, `empty`, `foldMap`, `fold`, `traverse`. Он реализует Functor и Applicative (при моноиде), но не Monad.

## 3. Теория

```text
Const c a = c
```

- `c` — накапливаемое значение (обычно моноид);
- `a` — фантомный параметр, который позволяет использовать `Const` там, где ожидается функтор от `a`.

Операции:

```text
map   _ (Const c) = Const c
concat (Const a) (Const b) = Const (a <> b)
ap (Const f) (Const x) = Const (f <> x)
of    _ = Const mempty
```

- `map` — **no-op**: значение не меняется.
- `concat`/`ap` требуют, чтобы `c` был полугруппой; `of`/`empty` — чтобы моноидом.
- `of(x)` игнорирует `x` и возвращает `empty`.
- `chain` невозможен: из `Const c` нельзя достать `a`, чтобы передать в функцию.

### Связь с foldMap

Ключевая формула:

```text
foldMap f = getConst . traverse (Const . f)
```

То есть свёртка — это `traverse` в аппликативе `Const m`, где `m` — моноид. Каждый элемент превращается в `Const (f x)`, а `ap`/`concat` собирают результаты через `<>`. В итоге `getConst` достаёт накопленное значение.

Это не трюк ради трюка: так `Foldable` выражается через `Traversable`, а свёртка становится частным случаем более общей операции обхода.

## 4. Почему это полезно в JavaScript

- **Агрегация.** Суммы, минимумы, максимумы, конкатенация списков — всё это `Const` с подходящим моноидом.
- **Валидация.** `Const (All ...)` или `Const (First ...)` позволяют собирать результаты проверки без изменения исходных значений.
- **Единый механизм.** Один `traverse` может работать и с эффектами (`Maybe`, `Either`), и со свёрткой (`Const`); это упрощает обобщённый код.
- **Понимание линз.** `Const` — один из ключей к тому, как устроены getters/folds в оптике.

## 5. Границы

- `Const` не хранит значение, поэтому не подходит для вычислений, где нужно преобразовывать данные.
- Нужен моноид; `Number` без обёртки (`Sum`) не всегда подходит, потому что у него нет канонического `concat`.
- `Const` — не монада; попытка использовать `chain` бессмысленна.
- В прикладном коде `reduce` часто проще; `Const` полезен, когда вы строите общую абстракцию или изучаете теорию.
