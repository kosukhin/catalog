# Урок 4.1 — `Async`: асинхронные вычисления без promises 🔴

> Цель: научиться описывать асинхронные вычисления как **значения** — ленивые,
> композируемые и отменяемые — и заменять ими `Promise`-цепочки там, где важны
> ленивость и ошибка как обычное значение.
> Ключевые слова: `Async(fn)`, `Resolved` / `Rejected` / `of`, `fork`, `toPromise`,
> `map`, `chain`, `ap`, `bimap`, `bichain`, `alt`, `coalesce`, `swap`, `race`,
> `all`, `fromPromise`, `fromNode`, `resolveAfter` / `rejectAfter`.
> Все примеры печатают результат в консоль и проверены на crocks 0.12.
>
> Документация: https://crocks.dev/docs/crocks/Async.html
>
> 📦 **Каждый блок в уроке самодостаточен.** Импорты и определения включены:
> скопируй блок в файл `.mjs` в проекте с `crocks` (`npm install crocks`, если
> его ещё нет) и запусти `node файл.mjs`. Примеры с ожидаемыми ошибками
> обёрнуты в `try/catch`, чтобы блок дорабатывал до конца и печатал сообщение.
> Так как результат `Async` приходит асинхронно, в блоках используется
> `await` — файл `.mjs` это позволяет на верхнем уровне.

## 1. Зачем нужен `Async` и чем он не похож на `Promise`

`Promise` в JavaScript начинается **сразу** в момент создания: `fetch(url)`
уже отправил запрос, к нему нельзя «прицепиться позже». `Async` наоборот —
это **описание** вычисления: пока его не запустили, ничего не происходит.

| | `Promise` | `Async` |
|---|---|---|
| Когда начинает работу | сразу при создании | только при `fork` / `toPromise` |
| Можно запустить повторно | нет (состояние фиксируется) | да — описание переиспользуемо |
| Отмена | нет | да, `fork` возвращает canceler |
| Ошибка | исключение в `catch` | значение в ветке `Rejected` |
| Композиция | `.then` / `.catch` | `map` / `chain` / `bimap` / `alt` |
| «Первый победивший» | `Promise.race` | `race` (метод и pointfree) |
| Собрать все | `Promise.all` | `Async.all` |

По интерфейсам `Async` — полноценная монада: `Functor`, `Apply`, `Applicative`,
`Chain`, `Monad`, плюс `Alt` (`alt`, `race`) и `Bifunctor` (`bimap`). То есть
всё, что вы знаете про `Maybe`/`Either` (уроки 1.1–1.4), работает и здесь, но
с ленивым асинхронным эффектом.

Про ленивость наглядно:

```js
import crocks from 'crocks'
const { Async } = crocks

const lazy = Async((reject, resolve) => {
  console.log('  вычисление выполняется')
  resolve(42)
})

console.log('до fork')
lazy.fork(e => console.log('  reject:', e), v => console.log('  resolve:', v))
console.log('после fork')

await new Promise(r => setTimeout(r, 10))
```

Вывод:

```text
до fork
  вычисление выполняется
  resolve: 42
после fork
```

Ключевое: до `fork` `Async` **не сделал ничего** — тело вычисления запускается
только в момент вызова. Тело вычисления — это функция
`(reject, resolve) => ...`, которую `crocks` называет **forkable**
(запускаемая): она получает два колбэка (`reject` и `resolve`) и вызывает ровно
один из них.

## 2. Форма: `Async(fn)`, `Resolved`, `Rejected`, `of`

```js
import crocks from 'crocks'
const { Async } = crocks

console.log(typeof Async.Resolved)          // 'function'
console.log(Async.of(1).type())             // Async
console.log(Async.Resolved(1).type())       // Async
console.log(Async.Rejected('boom').type())  // Async
console.log(Async.Resolved(1)['@@type'])    // crocks/Async@5

// состояние снаружи не видно: и Resolved, и Rejected печатаются одинаково
console.log(Async.Resolved(1).toString())   // 'Async Function'
console.log(Async.Rejected('boom').toString()) // 'Async Function'

try {
  Async(42)
} catch (e) {
  console.log(e.name + ': ' + e.message)
  // TypeError: Async: Function required
}
```

- `Async(fn)` принимает **унарную** функцию `(reject, resolve) => canceler?`;
- `Async.Resolved(x)` и `Async.of(x)` — одно и то же (успешная ветка);
- `Async.Rejected(x)` — неуспешная ветка со значением-ошибкой `x`;
- `toString`/`inspect` печатают `Async Function` для **любого** `Async`: чтобы
  узнать результат, вычисление нужно запустить — это следствие ленивости.

## 3. Запуск: `fork` и `toPromise`

`Async` — «холодное» значение, поэтому без запуска оно бесполезно. Есть две
точки входа:

```js
import crocks from 'crocks'
const { Async } = crocks

// fork(rejectFn, resolveFn) — запуск с двумя колбэками
Async.Resolved(7).fork(
  e => console.log('reject:', e),
  v => console.log('resolve:', v)   // resolve: 7
)

Async.Rejected('no data').fork(
  e => console.log('reject:', e),   // reject: no data
  v => console.log('resolve:', v)
)

await new Promise(r => setTimeout(r, 10))

// toPromise() — тот же запуск, но результат как Promise
console.log('toPromise:', await Async.Resolved(5).toPromise())   // toPromise: 5

try {
  await Async.Rejected('bad').toPromise()
} catch (e) {
  console.log('toPromise reject:', e)   // toPromise reject: bad
}
```

- порядок аргументов — **сначала ошибка, потом успех** (`fork(err, ok)`), как у
  Node-callback;
- `toPromise()` — мост в мир `async/await`; отклонение промиса несёт значение
  из `Rejected`;
- у `Async` **нет** метода `.run` (в отличие от `IO`): запуск — это `fork` /
  `toPromise`.

### Отмена — то, чего нет у `Promise`

`fork` возвращает функцию-отменитель. Если `Async` построен с «чистильщиком»
(canceler), отмена реально прерывает работу.

```js
import crocks from 'crocks'
const { Async } = crocks

let ran = false

const task = Async((reject, resolve) => {
  const token = setTimeout(() => {
    ran = true
    resolve('готово')
  }, 30)
  return () => clearTimeout(token)   // canceler
})

const cancel = task.fork(
  e => console.log('reject:', e),
  v => console.log('resolve:', v)
)

cancel()                            // отменяем до срабатывания таймера

await new Promise(r => setTimeout(r, 60))
console.log('ran =', ran)           // ran = false
```

## 4. `map` и `chain`: преобразование и зависимые шаги

Те же методы, что у `Maybe`/`Either`: `map` меняет успешное значение, `chain`
встраивает шаг, который **сам** возвращает `Async`. Обе ветки ошибки
пробрасываются насквозь.

```js
import crocks from 'crocks'
const { Async } = crocks

const show = a => a.fork(
  e => console.log('reject:', e),
  v => console.log('resolve:', v)
)

show(Async.Resolved(2).map(x => x * 10))                    // resolve: 20
show(Async.Resolved(2).chain(x => Async.of(x + 1)))         // resolve: 3
show(Async.Resolved(2).chain(x => Async.Rejected('нет')))   // reject: нет

// ошибку map/chain не трогают — она проходит мимо
show(Async.Rejected('err').map(x => x * 10))                // reject: err
show(Async.Rejected('err').chain(x => Async.of(1)))         // reject: err

await new Promise(r => setTimeout(r, 10))
```

> ⚠️ **`chain` возвращает `Async`, а не значение.** Колбэк `map` должен вернуть
> обычное значение, колбэк `chain` — новый `Async` (`Async.of(...)`,
> `Async.fromPromise(...)`). Иначе при запуске получите
> `TypeError: Async.chain: Function must return another Async`.
> Это ровно та же ловушка `map` vs `chain`, что в уроке 1.4.

## 5. `ap`: независимые асинхронные вычисления

`ap` применяет функцию, «завёрнутую» в `Async`, к значению, тоже «завёрнутому».
Если хотя бы одна сторона в `Rejected` — результат тоже `Rejected`.

```js
import crocks from 'crocks'
const { Async } = crocks

const show = a => a.fork(
  e => console.log('reject:', e),
  v => console.log('resolve:', v)
)

show(Async.of(x => x * 2).ap(Async.of(21)))               // resolve: 42
show(Async.of(x => x * 2).ap(Async.Rejected('ap error'))) // reject: ap error

await new Promise(r => setTimeout(r, 10))
```

> 💡 **Порядок аргументов, как всегда, «функция первая».** Метод читается
> `asyncFn.ap(asyncValue)`. Pointfree-хелпер `ap(value)(fn)` читается наоборот —
> см. урок 1.4, раздел про `ap`.

## 6. Работа с ошибкой: `bimap`, `bichain`, `alt`, `coalesce`, `swap`

У `Async` две ветки: `Rejected e` и `Resolved a`. Отсюда набор «двусторонних»
операций.

```js
import crocks from 'crocks'
const { Async } = crocks

const show = a => a.fork(
  e => console.log('reject:', e),
  v => console.log('resolve:', v)
)

// bimap(l, r) — преобразовать ОБЕ ветки, не выходя из Async
show(Async.Rejected('e').bimap(e => e.toUpperCase(), v => v * 2)) // reject: E
show(Async.Resolved(3).bimap(e => e.toUpperCase(), v => v * 2))   // resolve: 6

// bichain(l, r) — как chain, но для обеих веток (восстановление после ошибки)
show(Async.Resolved(3).bichain(e => Async.of('fixed'), v => Async.of(v + 1)))
// resolve: 4
show(Async.Rejected('bad').bichain(e => Async.of('fixed:' + e), v => Async.of(v)))
// resolve: fixed:bad

// alt — «запасной» Async, если текущий в Rejected
show(Async.Rejected('e1').alt(Async.Resolved('fallback'))) // resolve: fallback
show(Async.Resolved('ok').alt(Async.Resolved('other')))    // resolve: ok
show(Async.Rejected('e1').alt(Async.Rejected('e2')))       // reject: e2

// coalesce(l, r) — свернуть ОБЕ ветки в одну успешную (нужны две функции!)
show(Async.Rejected('err').coalesce(e => 'recovered:' + e, v => 'ok:' + v))
// resolve: recovered:err
show(Async.Resolved('v').coalesce(e => 'err:' + e, v => 'ok:' + v))
// resolve: ok:v

// swap(l, r) — поменять ветки местами, попутно преобразовав их
show(Async.Resolved(1).swap(e => 'E:' + e, v => 'V:' + v))  // reject: V:1
show(Async.Rejected('x').swap(e => 'E:' + e, v => 'V:' + v)) // resolve: E:x

await new Promise(r => setTimeout(r, 10))
```

Что важно запомнить:

| Метод | Ветка, которую обрабатывает | Возвращает |
|---|---|---|
| `map(f)` | только `Resolved` | `Async` |
| `chain(f)` | только `Resolved`, `f` → `Async` | `Async` |
| `bimap(l, r)` | **обе** сразу | `Async` |
| `bichain(l, r)` | **обе**, каждая функция → `Async` | `Async` |
| `alt(m)` | `Rejected` → подставить другой `Async` | `Async` |
| `coalesce(l, r)` | **обе** → свернуть в `Resolved` | `Async` |
| `swap(l, r)` | **обе**, поменяв местами | `Async` |

> ⚠️ **`coalesce` и `swap` у `Async` требуют ДВЕ функции**, а не одну
> (проверено). У `Either`/`Maybe` `coalesce` принимает один аргумент — здесь
> этого мало: иначе получаете
> `TypeError: Async.coalesce: Functions required for both arguments`.
> Это отличие легко забыть после урока 1.2.

> 🧠 **`alt` читается как «или».** `a.alt(b)` — «если `a` провалился, возьми
> `b`». Если и `b` в `Rejected`, ошибкой становится `b`. Именно на `alt` строят
> цепочки фолбэков (кеш → сеть → значение по умолчанию).

## 7. Мосты: `fromPromise`, `fromNode`, трансформации

Асинхронный мир `crocks` не требует переписывать всё сразу — есть конвертеры на
границах (та же идея «конвертируй на границе», что в уроках 1.1 и 6.4).

```js
import crocks from 'crocks'
const { Async, Maybe, Either,
        maybeToAsync, eitherToAsync, asyncToPromise } = crocks

const show = a => a.fork(
  e => console.log('reject:', e),
  v => console.log('resolve:', v)
)

// Promise-возвращающая функция -> Async (ленивый!)
const doubleP = Async.fromPromise(x => Promise.resolve(x * 2))
console.log('fromPromise:', await doubleP(21).toPromise())   // fromPromise: 42

// Node-callback (CPS) -> Async
const readConfig = cb => setTimeout(() => cb(null, { port: 8080 }), 1)
console.log('fromNode:', (await Async.fromNode(readConfig)().toPromise()).port)
// fromNode: 8080

// Maybe / Either -> Async
show(maybeToAsync('нет значения')(Maybe.Just(7)))    // resolve: 7
show(maybeToAsync('нет значения')(Maybe.Nothing()))  // reject: нет значения
show(eitherToAsync(Either.Right(8)))                 // resolve: 8
show(eitherToAsync(Either.Left('Left err')))         // reject: Left err

// Async -> Promise
console.log('asyncToPromise:', await asyncToPromise(Async.Resolved('done')))
// asyncToPromise: done

await new Promise(r => setTimeout(r, 10))
```

> ⚠️ **`fromPromise`/`fromNode` возвращают ФУНКЦИЮ, а не `Async`.** Они
> каррированы: `Async.fromPromise(fn)` — это «фабрика», которую надо вызвать с
> аргументами самой `fn`: `Async.fromPromise(fn)(x)`. Именно поэтому повторный
> вызов даёт **новое** вычисление — ленивость сохраняется.

Про время тоже есть готовые конструкторы:

```js
import crocks from 'crocks'
const { Async } = crocks

const later = Async.resolveAfter(10, 'через 10мс')
const fail = Async.rejectAfter(10, 'таймаут')

console.log(await later.toPromise())  // через 10мс
try {
  await fail.toPromise()
} catch (e) {
  console.log('rejectAfter:', e)      // rejectAfter: таймаут
}
```

Доступные трансформации в 0.12 (проверено): `asyncToPromise`, `maybeToAsync`,
`eitherToAsync`, `resultToAsync`, `firstToAsync`, `lastToAsync`.

## 8. Комбинирование: `race` и `all`

`race` — «кто первый, того и результат»; `all` — «собрать все или упасть на
первой ошибке».

```js
import crocks from 'crocks'
const { Async, race } = crocks

const slow = Async.resolveAfter(50, 'slow')
const fast = Async.resolveAfter(5, 'fast')

// race — и метод, и pointfree-функция
console.log('race (метод):', await slow.race(fast).toPromise())      // fast
console.log('race (pointfree):', await race(slow, fast).toPromise()) // fast

// all — Foldable структур из Async -> Async от массива
console.log('all:',
  await Async.all([Async.Resolved(1), Async.Resolved(2), Async.Resolved(3)]).toPromise())
// all: [ 1, 2, 3 ]

try {
  await Async.all([
    Async.Resolved(1),
    Async.Rejected('first bad'),
    Async.Rejected('second bad')
  ]).toPromise()
} catch (e) {
  console.log('all rejects with:', e)   // all rejects with: first bad
}
```

- `race` есть **и** как метод (`a.race(b)`), **и** как хелпер
  `crocks.race(a, b)` — но **не** как статик `Async.race` (его нет);
- `all` «падает быстро»: первая ошибка становится результатом, остальные
  результаты не собираются;
- `all` требует `Foldable` из `Async` — массив чисел или `Async.Rejected` даст
  `TypeError: Async.all: Foldable structure of Asyncs required`.

## 9. Полный пример: асинхронный пайплайн «пользователь → заказы»

Соберём типичный сценарий: загрузить пользователя, затем его заказы, посчитать
сумму, а ошибку превратить в понятное сообщение.

```js
import crocks from 'crocks'
const { Async } = crocks

// эмуляция HTTP (обычно здесь был бы fetch -> Promise)
const fetchUser = Async.fromPromise(id =>
  Promise.resolve({ id, name: 'Ivan' })
)
const fetchOrders = Async.fromPromise(uid =>
  Promise.resolve([{ total: 100 }, { total: 250 }])
)

const summary = fetchUser(1)
  .chain(user =>
    fetchOrders(user.id).map(orders => ({
      name: user.name,
      total: orders.reduce((acc, o) => acc + o.total, 0),
    }))
  )

console.log(await summary.toPromise())  // { name: 'Ivan', total: 350 }
```

Теперь ошибка как значение. Никакого `try/catch` — обе ветки живут в `Async`:

```js
import crocks from 'crocks'
const { Async } = crocks

// фабрика Async: аргумент — URL; здесь всегда падает
const fetchUserFrom = Async.fromPromise(url => Promise.reject(new Error('timeout')))

const message = fetchUserFrom('/api/user')
  .bimap(err => `не удалось: ${err.message}`, v => `ок: ${v}`)
  .coalesce(e => e, v => v)           // свернуть обе ветки в Resolved

console.log(await message.toPromise())  // не удалось: timeout
```

Фолбэк через `alt` (кеш → сеть) — то, что плохо выражается на `Promise`:

```js
import crocks from 'crocks'
const { Async } = crocks

const fromCache = Async.Resolved({ name: 'cached' })
const fromNetwork = Async.fromPromise(path =>
  Promise.reject(new Error('network down'))
)

// сначала сеть, при ошибке — кеш
const user = fromNetwork('/api/user').alt(fromCache)

console.log(await user.map(u => u.name).toPromise())  // cached
```

Почему это удобно:

- каждый шаг — самостоятельное `Async`, которое можно переиспользовать и
  компоновать;
- ошибка — это **значение** (`Rejected`), а не потеря управления: её видно в
  типах операций (`bimap`, `alt`, `coalesce`);
- построение пайплайна **не запускает** ни одного запроса — запуск один,
  в самом конце (`toPromise` / `fork`).

## 10. Чего нет в crocks 0.12 (проверено)

В плане урока встречались имена `resolved`, `rejected`, `run`. В 0.12 их **нет**
в таком виде:

```js
import crocks from 'crocks'
const { Async } = crocks

console.log(typeof Async.resolved)          // undefined
console.log(typeof Async.rejected)          // undefined
console.log(typeof Async.race)              // undefined (есть метод .race и crocks.race)
console.log(typeof Async.Resolved(1).run)   // undefined
console.log(typeof Async.Resolved(1).fork)  // 'function'
console.log(typeof Async.Resolved(1).toPromise) // 'function'
console.log(typeof Async.fromPromise)       // 'function'
console.log(typeof Async.fromNode)          // 'function'
console.log(typeof crocks.race)             // 'function'

// crocks.run существует, но это хелпер для IO, а не для Async
try {
  crocks.run(e => {}, v => {}, Async.Resolved(1))
} catch (e) {
  console.log(e.name + ': ' + e.message)
  // TypeError: run: IO required
}
```

Итог:

- `Async.resolved` / `Async.rejected` → **`Async.Resolved` / `Async.Rejected`**
  (с большой буквы) или `Async.of`;
- метода `.run` у `Async` нет → запуск это **`.fork(err, ok)`** или
  **`.toPromise()`**;
- `Async.race` как статик нет → есть **метод** `.race(m)` и **хелпер**
  `crocks.race(a, b)`;
- standalone `crocks.fork` нет (`undefined`); `crocks.run` — про `IO`;
- `coalesce` / `swap` у `Async` принимают **две** функции (в отличие от `Either`);
- `Async` **не** `Foldable`/`Traversable` (проверено), поэтому свёртки делайте
  через `toPromise` или трансформации в `Either`/`Maybe`.

## 11. Резюме урока

| Инструмент | Сигнатура / роль |
|---|---|
| `Async(fn)` | обернуть `(reject, resolve) => canceler?` |
| `Async.of(x)` / `Async.Resolved(x)` | успешное значение (лениво) |
| `Async.Rejected(x)` | ошибка как значение |
| `.fork(err, ok)` | запустить; вернёт canceler |
| `.toPromise()` | запустить и получить `Promise` |
| `.map(f)` | преобразовать `Resolved` |
| `.chain(f)` | шаг, зависящий от значения (`f` → `Async`) |
| `.ap(m)` | применить обёрнутую функцию к обёрнутому значению |
| `.bimap(l, r)` | преобразовать обе ветки |
| `.bichain(l, r)` | как `chain` для обеих веток |
| `.alt(m)` | фолбэк, если `Rejected` |
| `.coalesce(l, r)` | свернуть обе ветки в `Resolved` (2 функции!) |
| `.swap(l, r)` | поменять ветки местами (2 функции!) |
| `.race(m)` / `race(a, b)` | первый завершившийся |
| `Async.all([...])` | собрать все (падает на первой ошибке) |
| `Async.fromPromise(fn)` | `Promise`-функция → фабрика `Async` |
| `Async.fromNode(fn, ctx)` | CPS-функция → фабрика `Async` |
| `Async.resolveAfter(ms, v)` / `rejectAfter(ms, e)` | таймер |
| `maybeToAsync` / `eitherToAsync` / `asyncToPromise` | конвертация на границе |

Сравнение с соседями по курсу:

| | Что выражает | Запуск | Главная идея |
|---|---|---|---|
| `Maybe` (1.1) | отсутствие значения | — (значение уже внутри) | `Just` / `Nothing` |
| `Either` (1.2) | ошибка или успех | — | `Left` / `Right` |
| `Reader` (3.2) | зависимость от окружения | `runWith(env)` | самое окружение — снаружи |
| `ReaderT` (3.3) | окружение + эффект | `runWith(env)` | трансформер |
| `Async` (4.1) | **ленивое асинхронное** вычисление | `fork` / `toPromise` | время + отмена + ошибка как значение |
