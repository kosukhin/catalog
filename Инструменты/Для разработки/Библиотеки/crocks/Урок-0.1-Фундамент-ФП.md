## 0. Установка и импорт

```bash
npm install crocks
```

> **⚠️ Нюанс для Node (ESM-режим):** crocks — CommonJS-библиотека без поля `exports`.
> Если ваш проект использует `"type": "module"` (или файлы `.mjs`), импорты вида
> `import Async from 'crocks/Async'` упадут — ESM не разрешает импорт директорий
> без расширения, а именованные экспорты у CommonJS-модуля недоступны.
> Рабочие варианты:
>
> ```js
> // 1) импорт по полному пути с расширением
> import Async from 'crocks/Async/index.js'
>
> // 2) вся библиотека через default-экспорт (рекомендуется для Node)
> import crocks from 'crocks'
> const { Async, Maybe, compose, curry } = crocks
>
> // 3) CommonJS — файл с расширением .cjs
> const { Async } = require('crocks/Async')
> ```
>
> В браузере и при сборке бандлерами (Webpack, Vite) исходные импорты работают как есть.

## 1. Чистые функции

**Чистая функция** — функция, которая:

1. Возвращает одинаковый результат при одинаковых аргументах (детерминированность).
2. Не имеет побочных эффектов: не меняет внешнее состояние, не пишет в консоль, не делает запросов.

```js
// ❌ нечистая: зависит от внешней переменной и мутирует её
let tax = 0.2
function calcDirty(price) {
  tax = tax + 0.01          // побочный эффект
  return price * (1 + tax)  // зависит от внешнего состояния
}

// ✅ чистая: всё нужное приходит в аргументах
const calc = (price, taxRate) => price * (1 + taxRate)

calc(100, 0.2) // 120 — всегда
calc(100, 0.2) // 120 — всегда тот же результат
```

**Почему это важно для crocks:** все ADT (Maybe, Either, Async...) — это *чистые описания вычислений*. Они ничего не делают, пока их не «запустишь» (`run()`, `fork()`, `option()`, `either()`). Именно поэтому их можно свободно компоновать, тестировать и передавать.

```js
import Async from 'crocks/Async'

const fetchUser = Async.fromPromise(id =>
  fetch(`/api/users/${id}`).then(r => r.json())
)

// Ничего ещё НЕ произошло — это лишь «описание» вычисления:
const program = fetchUser(42)

// Запуск происходит ТОЛЬКО здесь:
program.fork(
  err  => console.error('ошибка:', err),
  user => console.log('пользователь:', user)
)
```

## 2. Иммутабельность

**Иммутабельность** — данные не изменяются после создания; вместо изменения создаётся новая копия.

```js
// ❌ мутация
const user = { name: 'Ivan', age: 30 }
user.age = 31

// ✅ новая версия через spread
const older = { ...user, age: 31 }
// user всё ещё { name: 'Ivan', age: 30 }
```

Полезные point-free хелперы crocks для работы со структурами:

```js
import prop from 'crocks/pointfree/prop'
import path from 'crocks/pointfree/path'

const user = { name: 'Ivan', age: 30, address: { city: 'Москва' } }

prop('name')(user)              // 'Ivan'
path(['address', 'city'])(user) // 'Москва'
```

Обрати внимание: `prop` — каррированная функция типа `(ключ) -> (объект) -> значение`.
«Данные идут последним аргументом» — ключевой стиль crocks (**data-last**), он и делает возможным point-free программирование (урок 6).

**Почему это важно для crocks:** все ADT crocks иммутабельны. `map` не меняет контейнер — он возвращает новый:

```js
import Maybe from 'crocks/Maybe'

const m = Maybe.Just(2)
const doubled = m.map(x => x * 2)

m        // Just 2  — не изменился
doubled  // Just 4  — новый контейнер
```

## 3. Каррирование (currying)

**Каррирование** — превращение функции от n аргументов в цепочку функций по одному аргументу.

```js
// обычная функция
const add3 = (a, b, c) => a + b + c

// каррированная вручную
const add3c = a => b => c => a + b + c

add3c(1)(2)(3) // 6
```

В crocks есть комбинатор `curry`, который каррирует любую функцию:

```js
import curry from 'crocks/combinators/curry'

const add3 = curry((a, b, c) => a + b + c)

add3(1, 2, 3)   // 6  — можно звать «все сразу»
add3(1)(2, 3)   // 6  — смешанно
add3(1)(2)(3)   // 6  — по одному

// Главная ценность — частичное применение:
const add10 = add3(10)
add10(2, 3)     // 15
```

Практический пример с `prop`:

```js
import prop from 'crocks/pointfree/prop'

const getName = prop('name')
getName({ name: 'Ivan' }) // 'Ivan'

// getName — это «заготовка», ожидающая данные
['Ivan', 'Olga'].map(getName) // ['Ivan', 'Olga']
```

**Почему это важно для crocks:** почти все функции библиотеки каррированы и принимают данные последними. Это позволяет «собирать» вычисления из маленьких кусочков (полный пример — в разделе 5).

## 4. Композиция функций

**Композиция** — построение сложной функции из простых: `f ∘ g = x => f(g(x))`.
Результат `g` передаётся в `f`, данные текут **справа налево**.

```js
// вручную
const compose = (f, g) => x => f(g(x))

const toUpper = s => s.toUpperCase()
const exclaim = s => s + '!'

const shout = compose(exclaim, toUpper)
shout('привет') // 'ПРИВЕТ!'
```

В crocks — `compose` и `pipe` (pipe читается слева направо):

```js
import compose from 'crocks/combinators/compose'
import pipe from 'crocks/combinators/pipe'

const shout = pipe(
  s => s.toUpperCase(),
  s => s + '!'
)
shout('привет') // 'ПРИВЕТ!'

// compose — эквивалент «снизу вверх»:
const shout2 = compose(s => s + '!', s => s.toUpperCase())
```

### Композиция с контейнерами

Суть crocks: `map` позволяет применять обычные чистые функции *внутри* контейнера, не разворачивая его:

```js
import Maybe from 'crocks/Maybe'

const toUpper = s => s.toUpperCase()
const exclaim = s => s + '!'

Maybe.Just('привет')
  .map(toUpper)   // Just 'ПРИВЕТ'
  .map(exclaim)   // Just 'ПРИВЕТ!'

// map «спускается» на один уровень вложенности за вызов:
Maybe.Just(Maybe.Just(2))
  .map(x => x * 2)
//map получил x = Just 2 (внутренний контейнер), а не число → Just NaN.
//Один вызов map сдвигает применение функции ровно на один уровень вглубь.
//Для двух уровней — два вложенных map, а для «схлопывания» слоёв — chain (урок 1.4).
```

И тот же принцип — в цепочке с данными пользователя:

```js
import safe from 'crocks/Maybe/safe'
import prop from 'crocks/pointfree/prop'
import isString from 'crocks/predicates/isString'
import pipe from 'crocks/combinators/pipe'
import chain from 'crocks/pointfree/chain'

const getCityName = pipe(
  Maybe.of,
  chain(safe(prop('address'))),
  chain(safe(prop('city'))),
  chain(safe(isString))
)

getCityName({ address: { city: 'Москва' } }) // Just 'Москва'
getCityName({ address: {} })                 // Nothing
```

## 5. Алгебраические типы данных (ADT)

**ADT** — способ описывать «формы данных» через сумму и произведение типов:

- **Произведение** (product): «и A, и B» — данные, требующие оба значения сразу. Название — из математики: если `A` имеет m вариантов, а `B` — n, то пара (A, B) имеет **m × n** вариантов, как декартово произведение. Примеры: объект `{ name, age }` (3 имени × 2 возраста = 6 возможных объектов) или кортеж.
- **Сумма** (sum): «или A, или B» — выбор одной из веток, поэтому варианты **складываются**: у `Maybe` это `Just a` (сколько угодно) + `Nothing` (ровно 1).

ADT из crocks — это, в первую очередь, **суммовые типы — контейнеры, кодирующие контекст вычисления**:

| ADT | Варианты | Кодируемый контекст |
|---|---|---|
| `Maybe` | `Just a` / `Nothing` | значение может отсутствовать |
| `Either` | `Right a` / `Left b` | успех или ошибка с описанием |
| `Result` | `Ok a` / `Err b` | то же, «Result-стиль» |
| `Async` | `Resolved a` / `Rejected b` | асинхронный успех/ошибка |
| `State` | функция `s -> (a, s)` | вычисление с состоянием |
| `Reader` | функция `r -> a` | зависимость от окружения |

Ключевая идея: **ошибка/отсутствие значения — не исключение и не `null`, а обычное значение внутри контейнера**. Контроль потока становится явным и компонуемым:

```js
// императивный стиль: неявные способы «выйти» из функции
function findUser(id, users) {
  const user = users.find(u => u.id === id)
  if (!user) return null            // неявный «сбой»
  if (!user.active) return null     // ещё один способ «сбоя»
  return user.name
}
// Вызывающий код обязан помнить: здесь может быть null. И линтер не поможет.

// ADT-стиль: все ветки — значения одного типа
import Maybe from 'crocks/Maybe'
import safe from 'crocks/Maybe/safe'
import prop from 'crocks/pointfree/prop'
import pipe from 'crocks/combinators/pipe'
import chain from 'crocks/pointfree/chain'
import alt from 'crocks/pointfree/alt'
import option from 'crocks/pointfree/option'

const activeUser = u => u.active ? Maybe.Just(u) : Maybe.Nothing()

const userName = id => pipe(
  chain(safe(u => u.id === id)),   // совпадает ли id (иначе Nothing)
  chain(activeUser),               // активен ли пользователь
  chain(safe(prop('name'))),       // есть ли поле name (строка)
  alt(Maybe.Just('гость')),        // запасное значение для любого Nothing
  option()                         // разворачиваем контейнер в строку
)

userName(2)(Maybe.Just({ id: 2, name: 'Olga', active: true })) // 'Olga'
userName(1)(Maybe.Just({ id: 1, name: 'Ivan', active: false })) // 'гость' (не активен)
userName(5)(Maybe.Nothing()) // 'гость' (пользователь не найден)
```

Появляется «алгебра»: контейнеры подчиняются законам (например, `map` идемпотентен:
`m.map(f).map(f) === m.map(compose(f, f))`), и благодаря этим законам сложные
цепочки остаются предсказуемыми. Законы Functor/Monad/Applicative разберём в уроке 1.4.

## 6. Резюме урока

1. **Чистые функции + иммутабельность** → предсказуемый код, который можно компоновать.
2. **Каррирование + data-last** → из маленьких функций собираются большие (point-free, урок 6).
3. **Композиция + `map`** → применяем функции внутри контейнеров, не разворачивая их.
4. **ADT** → контекст вычисления (может отсутствовать, может упасть, асинхронен) кодируется *самим типом*, а не `null` и не `throw`.
