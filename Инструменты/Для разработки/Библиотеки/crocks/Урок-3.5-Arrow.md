# Урок 3.5 — `Arrow`: функция как композируемое значение 🔴

> Цель: научиться упаковывать функцию `a -> b` в значение с интерфейсом
> композиции и адаптации: `map`, `contramap`, `promap`, `compose`, `first`,
> `second`, `both`, `fanout`.

> `promap`, `compose`, `first`, `second`, `both`, `fanout`.

## 1. Зачем нужен `Arrow`

Обычная функция — это «глагол»: её можно вызвать, но нельзя хранить как
значение с набором операций. `Arrow` превращает функцию `a -> b` в **значение**,
которое:

- **лениво** — ничего не выполняет, пока не вызван `runWith`;
- умеет **адаптировать вход** (`contramap`), **выход** (`map`) и **оба конца**
   (`promap`);
- **композируется** с другими Arrow через `.compose`;
- умеет работать с `Pair`: `first`, `second`, `both`;
- может быть **разветвлено** через `fanout`.

```js
import crocks from 'crocks'
const { Arrow } = crocks

const toUpper = Arrow(s => s.toUpperCase())

// пока не вызван runWith — ничего не выполнено
console.log(toUpper.runWith('hello')) // 'HELLO'
```

Чем это отличается от `Reader` (урок 3.2)?

| | `Reader` | `Arrow` |
|---|---|---|
| Что описывает | вычисление, зависящее от **окружения** | преобразование **входа** в выход |
| Форма | `env -> a` | `a -> b` |
| Запуск | `runWith(env)` | `runWith(a)` |
| Главная сила | dependency injection | композиция и адаптация функции |

`Arrow` — не контейнер значения и не монада: это **профунктор**, обёртка над
функцией, у которой вход контравариантен, а выход ковариантен.

---

## 2. Форма: `Arrow(fn)`, `runWith`, `id`

```js
import crocks from 'crocks'
const { Arrow } = crocks

const inc = Arrow(x => x + 1)

console.log(inc.runWith(3))   // 4
console.log(inc.toString())   // Arrow Function
console.log(inc.type())       // Arrow
console.log(inc['@@type'])    // crocks/Arrow@2

console.log(Arrow.id().runWith(5)) // 5 — тождественная Arrow
console.log(typeof Arrow.id)       // 'function'

try {
  Arrow(42)
} catch (e) {
  console.log(e.name + ': ' + e.message)
  // TypeError: Arrow: Function required
}
```

- `Arrow(fn)` принимает **унарную функцию** `a -> b`;
- `runWith(a)` — единственный способ выполнить вычисление;
- `Arrow.id()` — тождественная Arrow (`x => x`), нейтральный элемент композиции.

---

## 3. Три способа адаптировать функцию

`Arrow` — профунктор, поэтому у него две стороны, которые можно менять
независимо:

- `map(fn)` — преобразовать **выход**;
- `contramap(fn)` — преобразовать **вход**;
- `promap(l, r)` — то и другое сразу.

```js
import crocks from 'crocks'
const { Arrow } = crocks

const inc = Arrow(x => x + 1)

console.log(inc.map(x => x * 10).runWith(3))                // 40 — выход
console.log(inc.contramap(x => x * 10).runWith(3))          // 31 — вход
console.log(inc.promap(x => x * 2, x => x * 10).runWith(3)) // 70 — вход и выход
```

Формулы:

| Метод | Что получается |
|---|---|
| `arrow.map(r)` | `r ∘ arrow` |
| `arrow.contramap(l)` | `arrow ∘ l` |
| `arrow.promap(l, r)` | `r ∘ arrow ∘ l` |

Это и есть **Profunctor**: контравариантность по входу, ковариантность по
выходу. Практический смысл: одну и ту же Arrow можно приспособить к новому
API, не переписывая её тело.

## 4. Композиция: `.compose` — это «затем»

```js
import crocks from 'crocks'
const { Arrow } = crocks

const inc = Arrow(x => x + 1)
const dbl = Arrow(x => x * 2)

console.log(inc.compose(dbl).runWith(3))          // 8 — inc, затем dbl
console.log(dbl.compose(inc).runWith(3))          // 7 — dbl, затем inc
console.log(Arrow.id().compose(inc).runWith(3))   // 4 — id слева
console.log(inc.compose(Arrow.id()).runWith(3))   // 4 — id справа

try {
  inc.compose(42)
} catch (e) {
  console.log(e.name + ': ' + e.message)
  // TypeError: Arrow.compose: Arrow required
}
```

> ⚠️ **Порядок `Arrow.compose` — прямой, как у `pipe`, а не как у `compose`.**
> `a.compose(b)` означает «сначала `a`, затем `b`». В плане курса эта операция
> называлась `then`; в crocks 0.12 метода `then` нет — его роль играет
> `.compose`.

## 5. `Pair` и две дорожки: `first`, `second`, `both`

`Arrow` можно применить не ко всему `Pair`, а к одной из его «дорожек»:

```js
import crocks from 'crocks'
const { Arrow, Pair } = crocks

const inc = Arrow(x => x + 1)

console.log(inc.first().runWith(Pair(1, 100)).toString())  // Pair( 2, 100 )
console.log(inc.second().runWith(Pair(1, 100)).toString()) // Pair( 1, 101 )
console.log(Arrow(x => x * 2).both().runWith(Pair(2, 3)).toString()) // Pair( 4, 6 )

try {
  inc.first().runWith(42)
} catch (e) {
  console.log(e.name + ': ' + e.message)
  // TypeError: Arrow.first: Pair required for inner argument
}
```

- `first()` — применяет Arrow только к **первому** компоненту;
- `second()` — только ко **второму**;
- `both()` — к **обоим** (одна и та же функция);
- не-`Pair` на входе — ошибка.

Те же операции есть как pointfree-функции и принимают либо обычную функцию,
либо `Arrow`:

```js
import crocks from 'crocks'
const { Arrow, Pair, first, second, both } = crocks

const inc = Arrow(x => x + 1)

console.log(first(x => x + 1)(Pair(1, 100)).toString())  // Pair( 2, 100 ) — функция
console.log(first(inc).runWith(Pair(1, 100)).toString()) // Pair( 2, 100 ) — Arrow
console.log(second(x => x * 2)(Pair(1, 10)).toString())  // Pair( 1, 20 )
console.log(both(x => x * 2)(Pair(2, 3)).toString())     // Pair( 4, 6 )
```

## 6. `fanout`: один вход — два результата

`fanout(f, g)` разветвляет вход: применяет `f` и `g` к одному и тому же
значению и складывает результаты в `Pair`.

```js
import crocks from 'crocks'
const { Arrow, fanout } = crocks

const name = Arrow(u => u.name)
const age = Arrow(u => u.age)

const person = fanout(name, age)

console.log(person.type()) // Arrow
console.log(person.runWith({ name: 'Ivan', age: 20 }).toString()) // Pair( "Ivan", 20 )

// с обычными функциями fanout тоже работает
console.log(fanout(x => x + 1, x => x * 2)(3).toString()) // Pair( 4, 6 )
```

- если `f` и `g` — обычные функции, `fanout(f, g)(x)` вернёт `Pair`;
- если это `Arrow`, `fanout` вернёт новую `Arrow`, которая при запуске даст
   `Pair`;
- `fanout` — **отдельная функция**, а не метод `Arrow` (в плане он значился
   среди конструкторов, но в 0.12 это хелпер `crocks.fanout`).

## 7. Полный пример: пайплайн обработки

Соберём конвейер `parse -> double -> format`:

```js
import crocks from 'crocks'
const { Arrow } = crocks

const parse = Arrow(s => Number(s))
const double = Arrow(n => n * 2)
const format = Arrow(n => `result: ${n}`)

const program = parse.compose(double).compose(format)

console.log(program.runWith('21')) // 'result: 42'

// адаптируем вход и выход под объект
const fromInput = program.promap(o => o.value, s => ({ message: s }))
console.log(fromInput.runWith({ value: '21' })) // { message: 'result: 42' }
```

Почему это удобно:

- каждый шаг — самостоятельная Arrow, которую можно переиспользовать;
- `.compose` читается слева направо: `parse`, затем `double`, затем `format`;
- `promap` адаптирует готовый пайплайн под другой контракт входа/выхода, не
   трогая его тело.

## 8. Практика: статистика через `fanout`

Один вход — два независимых результата:

```js
import crocks from 'crocks'
const { Arrow, fanout } = crocks

const stats = fanout(
  Arrow(xs => xs.length),
  Arrow(xs => xs.reduce((a, b) => a + b, 0))
)

console.log(stats.runWith([1, 2, 3]).toString()) // Pair( 3, 6 )
```

Здесь `fanout` — «вилка»: вход `[1, 2, 3]` уходит в две Arrow, а результаты
складываются в `Pair(длина, сумма)`.

## 9. `Arrow` vs функция и `Reader`

| | обычная функция | `Reader` (3.2) | `Arrow` |
|---|---|---|---|
| Форма | `a -> b` | `env -> a` | `a -> b` (обёрнута) |
| Запуск | `f(x)` | `runWith(env)` | `runWith(a)` |
| Контекст | нет | окружение | нет |
| Адаптация входа | обёртка | — (окружение задаёт `runWith`) | `contramap` |
| Адаптация выхода | обёртка | `map` | `map` |
| Цепочка | `compose` / `pipe` | `chain` / `pipeK` | `.compose` |
| `Pair` | — | — | `first` / `second` / `both` |
| Интерфейсы | — | Functor, Monad | Functor, Contravariant, Profunctor |

`Arrow` реализует `Semigroupoid`, `Category`, `Functor`, `Contravariant`,
`Profunctor`, но **не Monad**: `chain`/`ap`/`of` у него нет.

```js
import crocks from 'crocks'
const { Arrow, isFunctor, isContravariant, isProfunctor, isMonad } = crocks

const inc = Arrow(x => x + 1)

console.log(isFunctor(inc))       // true
console.log(isContravariant(inc)) // true
console.log(isProfunctor(inc))    // true
console.log(isMonad(inc))         // false
console.log(typeof inc.chain)     // 'undefined'
console.log(typeof inc.ap)        // 'undefined'
```

## 10. Чего нет в crocks 0.12 (проверено)

В плане урока были имена `arrow`, `arr`, `then`. В 0.12 их **нет**:

- `crocks.arrow`, `crocks.arr`, `crocks.then` → `undefined`;
- `arr` заменяет конструктор `Arrow(fn)`;
- `then` заменяет метод `.compose` (порядок — слева направо);
- `fanout` — отдельная функция `crocks.fanout`, а не метод `Arrow`;
- `first`/`second`/`both` есть и как методы Arrow, и как pointfree-функции для
   `Pair`;
- у `Arrow` нет `of`, `ap`, `chain` — это не монада;
- `Arrow.id()` есть и как статический, и как instance-метод.

Полезно помнить:

- `Arrow` ленив: построение цепочки ничего не выполняет;
- `runWith` — единственная точка запуска;
- `.compose` требует именно `Arrow`, а не функцию:
   `TypeError: Arrow.compose: Arrow required`;
- `first`/`second`/`both` требуют на входе `Pair`, иначе
   `TypeError: Arrow.first: Pair required for inner argument`.

## 11. Резюме урока

| Инструмент | Роль |
|---|---|
| `Arrow(fn)` | обернуть функцию `a -> b` |
| `.runWith(a)` | запустить вычисление |
| `Arrow.id()` / `.id()` | тождественная Arrow |
| `.map(fn)` | преобразовать __выход__ |
| `.contramap(fn)` | преобразовать __вход__ |
| `.promap(l, r)` | вход и выход сразу |
| `.compose(m)` | «затем»: сначала this, потом `m` |
| `.first()` / `.second()` / `.both()` | Arrow над частью `Pair` |
| `fanout(f, g)` | разветвить вход в `Pair` |
| `first(fn_or_arrow)(pair)` и т. д. | pointfree-версии для `Pair` |
