# Todo App — TDD на Vue 3

Демонстрация TDD (Test-Driven Development) в Vue 3 приложении: Todo-список,
написанный по циклу **Красный → Зелёный → Рефакторинг**.

## Стек

- Vue 3 (`<script setup>` / Composition API)
- Vite
- Vitest + Vue Test Utils + jsdom

## Запуск

```bash
npm install
npm run test        # запустить тесты один раз
npm run test:watch  # режим TDD: тесты перезапускаются при каждом сохранении
npm run dev         # открыть приложение в браузере
```

## Как здесь применялся TDD

Каждый компонент создавался строго по циклу TDD:

### Цикл 1: TodoItem

1. **🔴 Красный** — сначала написан `tests/TodoItem.test.js` (5 тестов:
   рендер текста, класс `done`, события `toggle` и `remove`). Компонента ещё
   не существует — тест падает: `Failed to resolve import "TodoItem.vue"`.
2. **🟢 Зелёный** — написана минимальная реализация `src/components/TodoItem.vue`,
   ровно настолько, чтобы все 5 тестов прошли.
3. **🔵 Рефакторинг** — стили и читаемость, тесты остаются зелёными.

### Цикл 2: TodoList

1. **🔴 Красный** — `tests/TodoList.test.js`: 8 тестов (пустой список,
   добавление, запрет пустой задачи, очистка инпута, уникальные id,
   переключение, удаление, счётчик оставшихся).
2. **🟢 Зелёный** — `src/components/TodoList.vue` с минимальным состоянием
   (`todos`, `newTodo`, `nextId`).

## Ключевые приёмы TDD во Vue

- **`data-test` атрибуты** — тесты не зависят от CSS-классов и структуры DOM,
  только от контракта компонента (что он рендерит и какие события эмитит).
- **Тестируем поведение, а не внутренности** — не приватные поля, а то, что
  видит пользователь: ввод текста, клики, отображение списка.
- **Тест-первый дисциплинирует API** — сначала решаешь, как компонент будет
  использоваться (пропсы, события), потом как он устроен внутри.
- **`npm run test:watch`** — цикл Красный→Зелёный становится секундным:
  изменил код — тут же видишь результат.
